# Steps·LOE·WBS Summary·Actual Dates 확장

2026-11-05 / GAP-10 native 증분. Project 최대 schema19, Workspace schema1. 기존 파일은 새 정보가 없으면 기존 최소 schema를 유지한다.

## Steps와 진척 원천

자원 메뉴의 **Steps·LOE·WBS Summary…**에서 실제 작업을 선택해 Step 이름·가중치·진척을 편집한다. 정의를 먼저 저장하고 상태일·보고자·사유를 갖춘 진척 보고를 제출한다. 가중치는 양의 정수1~1,000,000, 진척은0~100%의 소수 둘째 자리이며 가중 평균을 basis point로 반올림한다. 예를 들어 가중치1/3에 진척100%/0%이면 물리 진척25%다.

정의는 `PlanInput.activities`에 저장하며 실행 취소·다시 실행·기준선/시나리오 동결에 포함한다. 작업 복제는 Steps 정의를 복사하고 보고 이력은 원본 작업에 유지한다. 보고 없는 작업 삭제 시 해당 Steps 정의도 함께 삭제·복구한다. LOE 기준 작업을 삭제하려면 참조하는 지원 활동부터 정리한다.

제출한 `Project.stepReports`는 보고 당시의 Step ID·이름·가중치·진척, 상태일·기록 시각·보고자·사유·원본 문서/revision을 동결한다. 제출은 기존 실적/원가와 같은 불변 이력이며 undo 이력을 비운다. 정정은 새 보고를 추가한다. 조회는 현재 상태일 이하의 가장 늦은 보고를 사용하고 같은 상태일은 뒤에 추가한 정정이 이긴다. 미래 보고는 과거 상태일 조회에 포함하지 않는다. 정의의 이름·가중치를 바꾸거나 정의를 삭제해도 과거 보고는 보존한다. Steps 보고가 있는 실제 작업은 정의 삭제 후에도 삭제를 차단한다.

작업별 **물리 진척/EVM에 Steps 보고 사용**을 선택하면 물리 진척과 physical 방식 EV는 해당 작업의 Steps 보고를 원천으로 삼는다. 보고가 없으면 미정이다. 선택을 해제하면 기존 수동 물리 진척 보고를 사용한다. 두 원천을 더하지 않는다. 기준선에 동결된 `zero-hundred` EV 방식은 기존 실제 완료 규칙을 유지한다. 실제원가나 실제 시작·완료·기간·잔여량을 Steps에서 자동 생성하지 않는다.

화면은 물리·기간·보고분 공수 비율을 별도로 표시한다. 기간은 보고된 실제 기간/(실제+잔여 기간), 보고분 공수는 기간 원장의 알려진 실제공수/(보고된 실제공수+보고 잔여공수)다. 완료 기간은 실제 완료 보고를 따르고, 필요한 보고·분모가 없으면 미정이다. 공수 비율은 미보고 기간/자원의 공수를 추정하지 않는 **보고분 기준**이다. Steps100%가 실제 완료를 뜻하지 않는다.

## LOE와 WBS Summary 지원 활동

같은 대화상자의 지원 활동 탭에서 추가·선택 정의 조회/편집·삭제한다. 정의는 실행 작업과 구분해 저장하고 전용 화면과 보고서에서 계산 구간을 제공한다.

- **LOE**는 지정한 실제 작업의 시작부터 다른 실제 작업의 완료까지다. 한 작업을 양 끝으로 선택할 수도 있다. 실행 작업 재계산에 따라 구간이 바뀐다.
- **WBS Summary**는 선택 WBS와 모든 하위 WBS의 실제 작업들에서 가장 이른 시작과 가장 늦은 완료를 집계한다. 프로젝트 전체 범위도 선택할 수 있다.
- 기간은 선택한 지원 활동 달력의 근무분이다. 새 정의는 프로젝트 기본 달력을 사용한다. 계획/활성 예측/채택 정책의 계산 결과를 사용하고, 다른 문서·revision 또는 미산정 결과는 날짜를 표시하지 않는다. 빈 범위·거꾸로 된 LOE 끝점·달력 산정 실패는 미정 사유로 표시한다.
- 지원 활동끼리 참조하거나 CPM 선후행 관계를 연결하지 않는다. 지원 활동에는 실행 공수·자원·고정 예산·실적 원장을 배정하지 않아 실제 작업 수·자원 부하·예산/EVM에 이중으로 집계하지 않는다. 실제 작업의 이름·종류·CPM/여유는 바꾸지 않는다.

현재는 **지원 구간 모델**이다. 자원/원가를 직접 갖는 P6 LOE/WBS Summary 실행 활동, 자동 LOE 관계 생성과 관계 기반 확장·축소, 지원 활동 전용 간트 카드는 후속이다. 기존 XER 가져오기의 TT_LOE/TT_WBS 차단 정책을 해제하지 않는다. XML/XER 내보내기에는 지원 정의·Steps 보고의 손실을 진단하고 `source.ppm`에 전체 native 데이터를 보존한다.

## Actual Dates native 정책

기존 **진척 정책 비교·채택**에 C **Actual Dates**를 추가한다. A/B의 변경 건수·편차는 기존 B−A 의미를 유지하고 C의 잔여 재개·완료·총여유·상태를 추가 표시한다. 비교 JSON에는 C의 작업별 결과·진단과 `actualDatesHistoricalRelationships`가 포함된다.

정책 ID는 `native-actual-dates-v1`이다. 원본 전체 계획의 누락·미정·순환을 먼저 검증한 뒤 계산 전용 그래프에서 다음을 적용한다.

1. 상태일 기준 실제 시작이 있는 진행 작업에서 이미 발생한 시작 끝점을 대상으로 하는 수신 FS/SS 관계를 이력으로 분류한다.
2. 아직 발생하지 않은 완료 끝점의 FF/SF 관계와 지연은 잔여 계산에 유지한다.
3. 실제 완료 작업은 두 끝점이 이미 발생했으므로 모든 수신 관계를 이력으로 분류한다. 실제 시작·완료는 고정한다.
4. 원본 관계와 보고 사실은 변경하지 않는다. 이력 관계 목록과 순서 위반 관측을 보존하고 native의 작업/자원 달력·잔여량·고정 실적/잔여 여유 산정 규칙을 사용한다.

담당자·사유를 갖춰 C를 채택·해제하고 저장·복구·undo/redo할 수 있다. 기존 평준화 조합은 동일한 실행 그래프를 사용한다. 상태일이 없으면 채택 설정은 비활성이다. 미래의 실제 시작/완료를 현재 상태일 이전 실적으로 허용하지 않는 기존 검증과 실제 기간의 명시 보고 규칙을 유지한다.

독립 기대 사례: 실제 시작한 B에 A→B FS와 D→B FF가 있을 때 A는2026-11-04 14:00, B는2026-11-03 14:00, C는2026-11-03 18:00에 완료한다. C는 B의 실제 시작2026-11-02 14:00을 보존하고 FF 완료 관계를 지킨다. 단순히 모든 수신 관계를 없애는 B와 구분한다.

Oracle의 [진척 활동 스케줄 옵션](https://docs.oracle.com/cd/G48902_01/client_help/en_US/general_tab_-_schedule_options_dialog_box.htm), [물리 진척과 가중 Steps 필드](https://docs.oracle.com/en/industries/construction-engineering/intelligence/subject-area-reference-guide/p6-activity-primaveraactivity.html), [WBS Summary 개념](https://docs.oracle.com/cd/G48897_01/English/User_Guides/p6_eppm_user/6617.htm)을 대조했다. 이 native 정책은 끝점 처리와 지원 범위를 명시한 구현이며 **P6 Actual Dates의 모든 전진/후진·SS 지연 옵션과 동일하다고 검증하지 않았다**. 실제 P6 재계산·재저장 왕복은 미실행이다.

## 저장·한도·출력

활동 정의가 현재 입력·기준선·시나리오에 있거나 Steps 보고/C 정책이 있으면 schema19를 사용한다. schema1..18은 새 필드를 거절하고 이전 파일은 계속 읽는다. 새 스키마가 필요 없는 기존 작성 결과의 버전은 유지한다. 복구 검사에도 schema19와 새 정의/보고 차이를 포함한다. 미리보기 이후 문서·세션 변경과 읽기 전용 편집은 차단한다.

활동 정의10,000개, 작업당 Steps200개·전체 정의10,000개, 보고10,000개·관측값100,000개와 기존 파일 크기·보고서 셀 한도를 적용한다. ID·이름·가중치·진척 범위, 중복 정의/보고 ID, 없는 작업·WBS·달력 참조를 검증한다. 지원 활동은 실제 작업만 참조해 지원 활동 간 순환을 만들 수 없다.

보고서의 Steps 표는 선택 작업 범위에서 최신 보고의 동결 가중치·각 진척·합계·물리 원천을 보여준다. 프로젝트 전체 보고서에는 LOE/WBS Summary 날짜·근무 기간·원본 작업 수·미산정 사유 표를 추가한다. WBS 필터 보고서는 별도 지원 범위 표를 생략한다. XLSX/PDF에도 같은 표를 출력하며 KPI/예산/실제원가 합계의 작업 코호트를 늘리지 않는다.
