# 주간 갱신과 연속 실적 입력

2026-11-17 · UX-W03. 주 창 툴바 또는 **추적 → 주간 갱신**에서 연다.

상단의 **상태일 설정/변경**으로 보고 기준을 정한다. 이번 주는 선택한 상태일의 월요일00:00부터
상태일까지이며 PC의 오늘 날짜를 기준으로 보고를 섞지 않는다. 상태일이 없으면 실적 입력을 막고
설정 버튼을 제공한다.

목록은 전체 프로젝트를 조회한다. 주 창의 WBS·검색·정렬과 독립적이며 작업 ID로 입력 대상을
연결한다. 기본 **이번 주 확인 대상**은 완료가 보고되지 않은 작업과 이번 주 보고 작업이다.
향후 계획의 미보고 작업도 포함될 수 있다. 일정만으로 착수 여부를 추정하거나 보고할 일을
확정하지 않으며 PM이 목록을 검토한다. 이전 주 완료 작업은 **전체 작업**에서 조회·정정할 수 있다.

보고 현황은 다음을 구분한다.

- **현재 상태일 보고**: 선택한 상태일·시각에 제출한 보고. 같은 시점 정정은 마지막 원장 항목을 사용한다.
- **이번 주 앞선 보고**: 이번 주 보고는 있지만 현재 상태일에는 아직 갱신하지 않은 작업.
- **이전 주 보고만**: 선택 상태일까지의 최근 보고가 이전 주에 있다.
- **미보고**: 선택 상태일까지 보고가 없다. 미래 보고가 있어도 현재 사실로 사용하지 않는다.
  미착수나0%로 간주하지 않는다.

현황별 필터와 이름·ID 검색으로 좁히고, 작업을 선택해 **입력/정정**한다. 기존 실적 입력창에서
실제 날짜·실제/잔여 기간 또는 잔여 공수·보고자·작업별 사유를 확인하고 제출한다.
보고 이력은 그 창에서 확인하며 정정도 새 항목으로 보존한다. 기간은 [d/h/m 규칙](duration-input.md)을 따른다.

**저장 후 다음 미보고 대상 입력으로 계속**을 켜면 선택 작업부터 시작해 현재 목록 순서로
현재 상태일 보고가 없는 다음 대상을 연다. 목록 끝에서는 앞쪽 미보고 대상으로 이어지며,
현재 상태일에 보고한 다른 작업은 자동으로 다시 열지 않는다. 처음 선택한 기존 보고는 정정할 수 있다.
오류가 있으면 같은 작업에 머물고, **목록으로 (초안 취소)**는 연속 입력을 중단한다.
이미 제출한 다른 작업의 보고를 되돌리지 않으며 취소·미입력 작업을 자동 제출하지 않는다.
체크를 끄면 한 작업을 제출한 뒤 목록으로 돌아온다. **다음 미보고 대상 선택**은 입력 없이 탐색만 한다.

보고 제출은 문서의 변경이다. 주간 갱신 창을 닫는 것은 전체 되돌리기가 아니다.
**입력 마치고 재예측**은 창을 닫고 현재 입력으로 계산한다. 목록 닫기나 초안 취소만으로는 계산하지 않는다.
파일 저장은 별도이며 주 창의 [파일·일정 상태와 다음 행동](save-reforecast-flow.md)에서 각각 확인한다.
엔진·파일 schema·기준선·보고 원장 계약은 유지한다.
읽기 전용에서는 조회만 가능하고, 문서를 교체/재열기하면 오래된 목록을 닫는다.

[자동 검사·실제 화면 검증](validation/weekly-update-flow-2026-11-17/README.md).
