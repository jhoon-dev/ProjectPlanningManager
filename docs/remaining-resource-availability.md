# 현재 부하를 반영한 잔여 가용량

2026-11-16 후속: [공유 풀 잔여 가용량](shared-remaining-availability.md)으로 여러 파일의 명시 연결 수요를 별도 조회할 수 있다. 아래 RRA 계약과 두 계산식은 계속 단일 프로젝트의 로컬 자원을 계산한다. 공유 조회는 schema를 추가하지 않는다.

2026-11-16 · RRA-01~06. **자원 → 현재 부하·잔여 가용량…**에서 명시 시각의 자원 공급·동시 배정 수요·잔여/추가 배정 가능량·부족분을 조회한다. 이 화면은 입력을 변경하지 않는다.

| 값 | 정의 |
| --- | --- |
| 유효 가용률 | 자원 근무 달력·휴일과 기존 전체 가용 경계·날짜/기간 예외를 반영한 공급. 근무 시간 외는0 |
| 배정 수요 | 해당 분에 실행 중인 **현재 프로젝트 전체** 배정의 합. 다른 WBS와 해당 배정 자신도 포함 |
| 잔여 가용량 | 유효 가용률−배정 수요. 음수는 부족분 |
| 추가 배정 가능 | max(잔여,0) |
| 부족 | max(−잔여,0) |

예: 공급50%에 동시 배정75%+50%가 있으면 수요125%, 잔여−75%, 추가 배정 가능0%, 부족75%다. 배정 종료 시각은 수요에서 제외하며 같은 분의 시작/종료는 함께 반영한다. 공급의 종료 분 포함 규칙은 [가용기간 계약](resource-availability.md)을 유지한다.

- **RRA-01 수요:** 현재 입력과 일치하는 완전한 일정의 실제 실행 배정 구간을 인덱싱한다. 기간 곡선·고정 공수/단위의 실행 배정·수동 중단·작업/자원 달력의 실행 구간을 재사용한다. 일별 평균이나 기본 배정률만으로 현재 수요를 추정하지 않는다. 유효한 일정에서 미배정 자원의 수요는0이다. 알 수 없는 공급에서도 알려진 수요는 표시한다.
- **RRA-02 일정 문맥:** 기본 조회는 `calculate`가 선택한 현재 일정이다. 상태일이 있으면 미완료 작업의 잔여 예측 수요, 없으면 계획 수요이며 채택 평준화를 반영한다. 계획 일정만 선택할 수도 있다. 예측 상태일 이전은 실제 수요를 추정하지 않고 수요/잔여를 미설정으로 표시한다. 취소·불완전·충돌·오래된 일정이나 부분 작업 목록을0수요로 처리하지 않는다. 삭제된/다른 자원 ID도 거절한다.
- **RRA-03 공급:** 기존 Resource.maxUnits·availableFrom/To·날짜/기간 예외에 자원 자체의 근무 달력을 적용한다. 지정 자원 달력이 없으면 기본 월~금09~12/13~18과 프로젝트 휴일이다. 공급 미설정은 잔여도 미설정이며0과 구별한다. 기존 `PPMUnitAvailability`는 계속 달력 근무시간을 곱하지 않은 설정 가용률 조회다. 이 증분은 현재 프로젝트의 공급/수요를 계산하며 작업공간의 다른 파일 부하를 자동 합산하지 않는다.
- **RRA-04 계산식:** Resource/Assignment 외부 계산식에서 `PPMResourceLoad(시각)`와 `PPMRemainingAvailability(시각)`를 지원한다. 예: `PPMRemainingAvailability(#2026-11-16T09:30:00#)`. 1=100%인 Number이며 잔여는 음수를 보존한다. ISO Date/Text 인자 하나를 받고 날짜만 있으면00:00이다. 없는 날짜는 Null, 잘못된 날짜/숫자·시간대 오프셋은 오류다. 단일 자원이 없는 작업/프로젝트/요약 범위는 Null이다. 일정 평가 문맥이 없으면 미설정이며 자동으로0을 넣지 않는다. 서로 다른 일정/평준화 문맥의 캐시를 구별하고 native/XML 혼합 의존성을 지원한다.
- **RRA-05 UI/보고/교환:** 시각과 계획/현재 일정 선택, 비동기 계산·취소·세션/revision 검사와 입력 변경 후 표시 무효화를 지원한다. 자원 필드 보기·계산식 편집기에도 연결한다. 보고서의 새 명세는 상태일, 없으면 프로젝트 시작일09:00을 기준 시각으로 명시한다. WBS로 표시 자원을 줄여도 차감할 수요는 전체 프로젝트다. XML/XER의 **계획 내보내기**는 기존 Plan 평가 문맥을 따라 계획 부하/잔여 결과를 정적으로 투영한다. XML에는 PPM 확장 식도 보존하고 재가져오기 후 지원 계획으로 재계산한다. 공급 정보를 정확히 가져오지 못한 XML에서는 기존 가용률 식과 함께 새 식을 비활성 보존한다. 실제 외부 제품의 확장 함수 실행을 의미하지 않는다.
- **RRA-06 저장/한도:** 결과는 파생 값이며 원장·기준선·일정을 수정하지 않는다. 활성 새 함수가 있으면 현재/승인/시나리오·일정 채택·통화/ID 사본에서 조건부 schema80이다. 비활성 원문은 기존 최소 writer를 유지한다. 기존1~79 읽기와 기준선 의미를 보존하며 현재 상한80·미지원 미래81이다. 실행 구간500,000개와 기존 일정/입력 한도·취소를 적용한다. 자원별 누적 수요 이벤트와 공유 달력 사본으로 조회하고 조회일자를 일별 자료로 팽창시키지 않는다.

조회 시각은 시간대 없는 civil 분이며 OS 현재 시각을 읽지 않는다. 이 값은 현재 일정의 배정 수요와 공급을 비교한 수치다. 실제 출퇴근/타임시트와 다중 프로젝트 공유 풀의 후속 확장은 별도 모델을 따른다.
