# 외부 XER EV/PV의 native 채택

2026-11-08 · XEA-01~06. 보존한 XER의 TASKFIN 재무기간 EV/PV를 사용자가 기준선·작업·개시 누계와 함께 명시 채택한다. 선택한 값은 native EVM 측정값을 대체하며 AC·물리 진척·Steps·기준선 예산이나 기존 원장을 바꾸지 않는다.

Oracle의 [TASKFIN 매핑](https://docs.oracle.com/cd/F25600_01/English/Mapping_and_Schema/xer_import_export_data_map_project/97911.htm)은 `bcwp`를 Earned Value Cost, `bcws`를 Planned Value Cost로 정의한다. [기간 실적 저장 설명](https://docs.oracle.com/cd/F51303_01/English/User_Guides/p6_pro_user/post_actual_amounts_for_a_period.htm)에 따라 이 구현은 재무기간에 저장된 금액을 기간 값으로 해석한다. P6의 균등 표시 배분이나 외부 EVM 계산 옵션까지 재현하는 계약은 아니다.

## XEA-01 원본·기준선·범위

원가 → 외부 XER EV/PV native 채택…에서 현재의 최초/최신 보존 집계, 선택 기준선과 작업 ID를 검토한다. 새 XER ID는 기존 재연결 기능으로 현재 ID에 먼저 연결한다. 현재 문서와 선택 기준선에 모두 존재하는 작업만 채택하며 통화 변환은 하지 않는다. native 상태일은 채택할 원본 상태일 이상이어야 한다. 파일 SHA256·집계 투영 지문과 재무 revision, 기준선 ID·기록 시점을 참조한다.

## XEA-02 기간과 개시 누계

TASKFIN의 EV/PV 관측이 있는 기간만 선택한다. 자원 TRSRCFIN·비용/공수 값으로 EV/PV를 추정하지 않는다. EV/PV 각각의 채택 여부를 지정하고 관측값의 개시 누계를 명시 입력한다. 기본값은 공란이며0을 자동 입력하지 않는다. 빈 원본 필드는 미정, 명시0은 알려진 값이다. 마감 누계는 명시 개시 누계+해당 기간 금액이다. 다른 기간의 누계를 자동 합산해 개시값을 만들지 않는다.

동일 작업에서 기간이 겹치면 차단한다. 연속 기간이 공유하는 경계에서 알려진 마감·개시 누계가 다르면 차단한다. 서로 떨어진 기간은 각 개시값을 사용자가 확인해야 한다. 명시 개시값이 공백의 마감 경계도 확인해 주는 경우 그 경계는 알려진 값이다. 두 경계가 알려져 있으면 그 사이 기간 증감도 계산할 수 있지만 내부 값을 보간하지 않는다. 개시·합계의 금액 한도와 중복/깨진 기간 참조를 검사한다.

## XEA-03 경계와 계산

원본 기간의 civil 시작일00:00 직전과 종료일23:59가 누계 경계다. 종료일이 원본 상태일 당일이면 원본 상태 시각으로 마감을 자른다. 다음 날00:00 미만과 전날23:59 이하는 같은 경계로 처리한다. 확인한 개시/마감만 알려진 값이며 구간 내부·공백·채택 범위 전후를 보간/연장하지 않는다. 일/주/월 조회가 원본 기간을 쪼개면 해당 경계의 EV/PV는 미정일 수 있다.

선택 기준선·작업의 채택 EV/PV는 기존 물리 진척/Steps/0-100·계획 PV를 대체한다. 선택하지 않은 지표와 다른 작업·다른 기준선은 기존 native 계산을 따른다. 두 값을 더하지 않는다. 현재 채택본으로 과거 경계를 다시 표시하는 정책이며 당시 지식 revision을 동결한 마감 자료는 아니다. 현재 상태일 이후 EV/AC는 예측하지 않는다.

CV/SV·CPI/SPI, 프로젝트/WBS·기간 EVM·기존 원가 보고/추이는 채택값을 사용한다. AC는 기존 native 누계이고 날짜 배분은 별도 대사다. BAC는 동결 기준선 그대로다. 외부 EV 또는 PV가 그 작업 BAC를 넘으면 원시 금액과 편차/비율은 보존하고 해당 작업을 포함한 EAC/ETC는 미정으로 표시한다. 금액을 BAC로 잘라내거나 차이를 AC에 더하지 않는다.

## XEA-04 명시 검토·불변 이력

작성자·사유와 대체/미정 경계를 확인한 뒤 비동기 검증·현재/채택 EVM 미리보기를 열고 검증된 결과를 제출한다. 읽기/미리보기·취소·닫기에는 문서를 바꾸지 않는다. 입력 변경 시 확인/검증을 해제하고, 문서/revision/session/저장 상태·권한 변경이나 worker 취소에는 제출하지 않는다.

재채택은 선택 작업의 이전 채택 범위를 새 범위로 대체하는 새 이력이다. 화면의 철회는 선택 기준선의 활성 채택 작업 전체를 대상으로 하며 native 측정법으로 돌아온다. API는 작업 일부의 철회도 지원한다. 일반 undo로 채택/철회 이력을 없애지 않는다. 기존 원본·채택·작성자/사유/시각과 당시 참조는 남으며 이후 계획 undo도 이력을 유지한다. 이력이 참조한 작업의 삭제·통화 변경은 보호한다.

## XEA-05 저장·복구·출력

채택 또는 철회 이력이 있는 파일은 조건부 schema29다. 없는 문서는 기존1~28 writer를 유지하며 구 envelope의 새 필드와 미래31을 거절한다. native 저장/재열기·복구·독립 사본은 이력과 원본 참조를 보존하고 당시 최신 재무 집계·기준선/시각·금액/공유 경계를 재검증한다. 전체128건, 작업/기간 참조 합계100,000개, 기존 native64MiB 한도를 적용한다. 원가 일별 추이는 최대20,000개 civil 날짜, 보고서는 기존100만 cell 한도다. 초과하면 채택 기간·WBS/보고 날짜 범위를 줄여 조회한다.

native 기간 EVM과 일반 보고서의 XLSX/PDF에 채택 근거·원본 기간/개시·마감/현재 정책 이력을 포함한다. 채택 자체는 XER 실적·원가 재사용 판정의 투영 지문을 바꾸지 않는다. XER/XML은 native 채택/철회 정책을 표현하지 않으므로 source.ppm을 함께 보존한다. 원본 XER 전체 바이트의 보관은 기존 교환 계약을 따른다.

## XEA-06 검증과 후속

사용자 정의 기간 예산/EV 입력·임의 일별 배분, 당시 지식 revision 마감 잠금, 외부 계산 옵션/통화·단위 변환, 새 일정 병합·MPP reader와 실제 P6/MS Project 재계산·재저장은 후속 범위다.
