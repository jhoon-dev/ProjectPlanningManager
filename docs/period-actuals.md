# 기간별 실제공수·실제원가 입력과 정정

[사용자 기간 마감](custom-financial-periods.md)이 활성인 작업의 원장은 마감일 이전 제출 상태일과 실제 날짜를 모두 잠근다. 뒤 상태일에 과거 날짜 배분을 추가하는 경우도 거절하며, 정정하려면 관련 마감을 최신 기간부터 재개방한다.

2026-11-07 [XER 집계 편집·날짜별 배분](xer-aggregate-editing.md)은 명시한 날짜/비중으로 XER 집계를 이 원장에 정정 제출한다. 생성한 원장 키를 소유 이력에 연결하고 날짜 이동/철회는 미보고 정정으로 남긴다. 동일 누계 안에서 배분하며 작업 AC를 중복 합산하지 않는다. 기존 독립 기간 실적 입력은 유지하고 다른 입력과 같은 키가 충돌하면 자동으로 덮어쓰지 않는다.

2026-11-06 XER의 일 단위 재무기간 명세와 누계 AC는 [상세 교환 계약](xer-actual-cost-exchange.md)으로 연결한다. 주/월 집계를 임의 날짜에 배분하지 않으며 원본/보고에 보존한다. 가져온 관측 스냅샷은 아래 원장·원가 대사·저장/복구 규칙을 그대로 따른다.

2026-11-03 사용자 요청으로 GAP-04의 기간별 실제 입력을 추가한다. 날짜·작업·자원별 관측 실제공수와 원가를 제출하고 기존 누적 실제원가와 대사한다. 실제공수에서 작업의 실제 소요 기간·잔여량을 자동 추정하거나 단가로 실제원가를 재평가하지 않는다.

## 사용 방법

1. 프로젝트의 상태일을 먼저 설정한다. 자원 → **기간별 실제공수·원가 입력/정정…**, 또는 Usage의 **기간 실적 입력/정정…**을 연다.
2. 작업을 선택하고 실제 날짜·자원(또는 작업 직접비)·공수·원가를 입력한다. 행 추가로 여러 날짜/자원을 한 번에 제출한다. 공수는 `1.25`처럼 시간으로 입력하거나 `6001u`처럼 정수 `%·분`을 직접 입력한다. 자원 없는 직접비 행은 공수를 비워 둔다.
3. 원가를 제출할 때는 **누적 실제원가 총계(배분액 포함)**도 확인한다. 현재 누계를 그대로 두면 그 안에서 배분한다. 신규 지출을 추가했다면 누계도 새 총액으로 입력한다. 공수만 제출하면 누계 원가는 바꾸지 않는다.
4. 작성자와 사유를 입력하고 **기간 실적 제출**을 누른다. 검증 실패/준비 취소 때는 어떤 행도 반영하지 않는다. 모든 행은 동일한 상태일로 제출한다.
5. 정정은 제출 원장에서 기록을 선택해 **정정 초안으로 불러오기**를 누른다. 정확한 원본 공수는 `u` 단위로 불러오며, 행의 공수/원가 전체를 새 값으로 제출한다. 초안 행 제거는 이미 제출한 기록을 지우지 않는다.
6. Usage에서 **보고 실제공수 / 보고 실제원가**를 선택한다. 툴팁의 보고 건수와 미배분 원가를 확인한다. XLSX/PDF의 **누적 원가 배분 대사**는 날짜 범위에 관계없는 전기간 대사를 제공한다.

읽기 전용에서는 원장 조회만 가능하다. 제출 원장은 가상 표로 표시하고, 입력 행의 자원 목록은 공유해 많은 기록/행이 있어도 같은 데이터를 반복 생성하지 않는다.

## 원장과 입력 계약

- 키는 작업 ID + 자원 ID + civil 날짜다. 자원 없는 행은 작업 직접비/미배정 원가이며 공수는 입력하지 않는다. 자원 배정은 계획과 별개로 실제를 기록하되 처음 제출하는 작업/자원 조합은 현재 배정이어야 한다. 이전 제출 조합은 배정을 해제해도 정정할 수 있다.
- 날짜는 상태일의 날짜 이하다. 휴일·비근무일에도 관측한 실제를 명시 기록할 수 있다. 자원 가용량이나 계획 배정률로 실제공수를 제한·생성하지 않는다. 인력/장비 종류를 제출 때 동결하고 정정은 원래 단위를 유지한다.
- 공수는 정수 `%·분`이며 6,000이 1인시/1장비시다. 시간 입력은 소수 6자리까지 허용하되 정수 `%·분`으로 정확히 표현돼야 한다. 시간 소수로 정확히 표현할 수 없는 값은 `6001u`처럼 정수 단위 접미사를 사용한다. 원가는 프로젝트 통화의 정수 최소 단위다. 각각 미보고(null)·명시 0·양수를 구분한다. 한 행의 공수/원가 모두 미보고로 정정하면 기존 값의 배분을 철회하는 새 기록이다.
- 각 제출은 작성자·사유·보고 UTC·상태일·원본 문서/revision·이전 기록 ID를 보존하는 불변 원장이다. 행은 전체 값의 대체 스냅샷이며 정정 때 차액을 더하지 않는다. 같은 키/상태일은 나중에 제출한 정정, 서로 다른 상태일은 조회 상태일 이하의 가장 최근 보고를 사용한다.
- 한 번 최대 1,000행을 원자적으로 제출하고 총 50,000기록까지 보존한다. 기존 native 파일 16MiB 한도도 함께 적용한다. 중복 키·잘못된 날짜/정밀도/참조·불일치가 있으면 어떤 행도 반영하지 않는다. 제출은 일반 undo로 삭제하지 않으며 정정 보고로 변경한다. 이후 계획 편집의 undo/redo는 제출 이력을 보존한다.

## 누적 실제원가와 대사

- 기존 `CostEntry` 누계가 AC/EVM의 유일한 총액이다. 기간별 원가는 그 누계에 **포함된 금액의 배분 명세**이며 두 값을 더하지 않는다. 원가를 입력/철회하는 제출에는 해당 작업의 기존 금액을 포함한 **누적 실제원가 총계**도 함께 명시한다. 변경하지 않은 기존 누계로 제출하면 그 안에서 배분하는 뜻이다. 신규 지출을 추가하려면 누계도 사용자가 늘려 제출한다.
- 예: 기존 누계 80에 11-02 인력 원가 30을 배분하면 AC=80, 전기간 배분=30, 미배분=50이다. 신규 원가 10을 기록하면서 누계 90을 제출하면 AC=90이다. 두 경우 모두 AC에 배분액을 다시 더하지 않는다.
- 누계와 기간 행은 같은 원자적 제출에 저장하고 기간 기록의 `costEntryId`로 누계 보고를 연결한다. 원가 보고의 기존 물리 진척은 유지한다. 과거 누계·EV·기준선을 덮어쓰지 않는다.
- 모든 과거 보고 상태일에서 알려진 전기간 배분 합계 ≤ 알려진 누계를 검증한다. 과거 정정 때문에 미래 누계와 모순이 생겨도 거절한다. 누계 미정은 AC와 미배분을 미정으로 유지하며 알려진 배분만 조회한다.
- 미배분=누계−조회 상태일의 **전기간** 최신 배분 합계다. 화면 날짜 범위를 좁혀도 미배분을 다시 만들지 않는다. 기간별 입력이 없는 기존 누계를 날짜/자원에 추정 배분하지 않는다.

## Usage·보고·파일

Usage에 보고 실제공수/보고 실제원가를 추가한다. 부분 제출의 알려진 보고 합계와 보고 건수를 표시하며 미보고를 0실적으로 확정하지 않는다. 실제 행은 계획/기준선/잔여 결과와 별도로 표시하고, 누계·전기간 배분·미배분을 대사한다. 실제공수 제출로 미래 일정·잔여량·원가 예측·자원 과부하를 조용히 바꾸지 않는다.

원장 이력·기간별 명세·대사와 출처를 XLSX/PDF에 보존한다. 원장이 있으면 native schema 11을 사용하고 없으면 기존 schema 9/10 writer를 유지한다. schema 1~10을 읽으며 기존 복구·사본·읽기 전용·checksum 정책을 유지한다. XML/XER에는 새 실적을 매핑하지 않고 손실을 명시하며 native 사본에 원장을 보존한다.

## 수용조건

1. 두 자원 종류·분수 공수·실제 원가·명시 0/미보고·휴일·월/주 경계·배정 해제 후 정정의 독립 기대값을 확인한다.
2. 원자적 실패, 중복 키·정밀도·미래 날짜·미배분 음수·과거/미래 누계 충돌을 거절한다. 작성자/사유·누계 링크·정정 원본을 보존한다.
3. 상태일 이동과 같은 날짜 정정, 계획/기준선·물리 EV 불변, 누계 AC 단일 합산과 보고 합계/미배분 일치를 검증한다.
4. schema 11·구 writer·파일/복구/사본, 읽기 전용·worker 취소·session/revision 교체·삭제/통화 보호와 입력 UI·보고서를 검증한다.

로컬 Windows의 전체 CTest 71개·독립 XLSX/PDF·입력/Usage 화면·schema 1~11 seed 재생 결과와 미실행 범위는 [검증 기록](validation/period-actuals-2026-11-03/README.md)에 보존한다. 실제 제품 동등성·기간별 계획 배정 편집의 완료 기록은 아니다.
