# 실제 자재 원장과 잔여 일정 자동 대기

2026-11-17 후속: [자재 제약 여유·임계](material-float.md)를 계획/잔여·공유 통합에 연결했다. 아래 당시 미지원 여유/임계는 이 후속으로 대체한다. 새 승인 자재 기준선만 조건부84이며 일반 원장 문서는83을 유지한다. 현재 상한84, 미지원 미래85다.

2026-11-17 후속: [SMAT-01~07 공유 통합 예측](shared-material-actuals.md)에도 실제 원장과 확인 잔여 재고를 연결했다. 아래 MAT-08의 통합 미지원은 이 후속으로 대체한다. 자재 재고는 프로젝트별이며 통합 여유/임계·구매/원가 최적화·여러 파일 날짜 일괄 채택은 남는다.

2026-11-17 · MAT-01~08. [계획 입고 자동 대기](material-arrival-leveling.md)에 실제 입고·소모 원장과 상태일 잔여 재고를 추가한다.

사용 순서:

1. 자재 계획에서 단위·개시 재고·기준 시각과 계획 소모/입고를 입력하고 프로젝트 상태일을 설정한다.
2. **자원 → 실제 자재 입고·소모 원장…**에서 작성자·사유와 실제 입고/소모 시각·수량을 제출한다. 실제 입고가 기존 계획의 일부라면 **연결할 계획 입고**를 선택한다.
3. **상태일 재고·잔여 소모 확인** 탭에서 계산 재고와 앞으로 필요한 각 소모량을 확인해 입력하고 함께 제출한다. 빈칸은 미확인이고 0은 명시적인 잔여 없음이다.
4. **자재·비용계정·역할 계획 → 잔여 평준화에 확인된 실제 자재 재고·잔여 소모 적용**을 켠다. **기간별 부하·평준화 비교**에서 결과를 검토하고 현재 일정으로 채택한다.

예: 개시2개 + 실제 입고1개 − 실제 소모3개 = 상태일 재고0개. 계획 입고3개 중1개가 이미 도착했다면 미래 공급은 남은2개다. 상태일09:30에 잔여 시작 소모1개가 필요한 진행 작업은11:00의 남은 입고를 기다린다. 실제 시작09:00은 보존하고 잔여 시작만11:00으로 늦춘다. 후속 작업·자원 점유도 새 잔여 날짜를 따른다.

- **MAT-01 원장:** `Project.materialActuals`는 실제 입고(`receipt`)·소모(`consume`), 상태일 재고 확인(`confirm`)·소모행별 잔여 수량(`remaining`)의 추가 전용 기록이다. 수량은 자재 단위의1/1000 정수, 시각은 기존 ISO civil 분이다. ID/거래 ID·상태일·기록 UTC·작성자·사유·원본 문서/리비전·정정 연결을 보존한다. 실제 원가/AC나 진척은 자동 생성하지 않는다.
- **MAT-02 정정/보호:** 거래를 선택해 정정하면 동일 거래의 이전 값을 대체하는 새 기록을 붙인다. 실제 입고/소모의0은 취소이며 삭제하지 않는다. 거래 종류·자재·연결 대상은 정정으로 바꾸지 않는다. 최신 기록을 기준으로 정정해야 하며 오래된 초안은 거절한다. 제출은 원자적으로 반영하고 일반 undo 이력을 비운다. 원장이 참조하는 작업·소모·계획 입고, 자재 단위·개시 재고·기준 시각을 보호한다. 이름/단가·미래 입고 계획의 수량/시각 변경은 별도 계획 편집이다.
- **MAT-03 실제 재고:** 개시 재고 + 실제 입고 − 실제 소모다. 계획 소모와 계획 입고를 실제로 간주하지 않는다. 조회 상태일까지 보고된 각 거래의 최신 정정을 선택하므로 후일 정정은 이전 상태일의 보고를 바꾸지 않는다. 실제 거래는 보고 상태일 이후나 개시 기준 이전일 수 없다. 실제 음수 잔고도 사실로 보존·표시하지만 자동 배치 공급으로 쓰지 않는다. 미래 재고를 실제 재고로 표시하지 않는다.
- **MAT-04 명시 확인:** 현재 상태일에 계획 소모가 있는 모든 자재의 재고 확인과 모든 소모행의 잔여 수량이 필요하다. 재고 확인 수량은 원장 계산값과 같아야 한다. 진척률·경과 시간·실제 소모에서 잔여 소모를 자동 추정하지 않는다. 완료 작업은 잔여0이어야 한다. 실제 원장을 나중에 정정/추가하면 같은 상태일의 이전 재고 확인도 무효화한다. 상태일 변경 후에는 새 상태일 확인이 필요하다.
- **MAT-05 미래 공급:** 상태일보다 늦은 계획 입고만 후보 공급이다. 연결된 실제 입고 누계를 계획 수량에서 차감하고 음수 잔량은0으로 한다. 부분/조기 입고와 정정을 반영하며 이미 받은 입고를 이중 합산하지 않는다. 연결하지 않은 실제 입고는 독립 거래이므로 계획 입고 잔량을 줄이지 않는다. 상태일 이전의 미입고 계획은 미래 공급으로 추정하지 않으므로 계획 입고 시각을 명시적으로 수정해야 한다.
- **MAT-06 잔여 배치:** 별도 옵션과 정책 `serial-material-remaining-v1`을 사용한다. 네 계산 프로필에서 실제 시작·완료를 보존하고 잔여 구간에 명시 수량을 배치한다. 시작/완료/균등 소모·실제 실행 구간 합집합·정수 누적 half-up, 달력·가용량·선후관계·고정 날짜와 이전 배치의 미래 소모 예약을 함께 검사한다. 공수 기반/곡선·날짜별 잔여 공수도 기존 실행 모델을 재사용한다. 논리 예측은 옵션만으로 바뀌지 않고 비교/채택 후 재현된다. 원장·상태일·입력 변경은 채택을 무효화한다. 미확인/부족/한도/실패/취소는 날짜를 채택하지 않는다.
- **MAT-07 저장/출력:** 조건부 native **schema83**, 미지원 미래84다. 옵션만 사용하거나 실제 원장/과거 새 정책 이력이 남은 경우도83이다. 시나리오는 당시 원장 전체를 동결하며 통화/원장 ID 이관의 전체 전후 사본·사본/복구에 보존한다. 이전 파일은 명시 옵션 없이는 새 잔여 의미를 사용하지 않는다. 보고서 XLSX/PDF에 전체 정정 원장·상태일 실제 재고·잔여 자동 대기 정책을 출력한다. native 파일은 전체 원장의 JSON 보존본이다.
- **MAT-08 한도/범위:** 원장100,000행, 제출20,000행, UI 잔여 확인10,000소모행과 기존 자재/평준화 탐색 한도를 따른다. 이력을 가상 표로 조회하고 협력 취소를 전달한다. 단일 문서의 잔여 일정에 적용한다. 공유 통합 잔여 원장 투영은 명시적으로 거절하며 기존 계획 공유 평준화는 유지한다. 자재 제약을 포함한 여유/임계, 재고 원가 평가·구매 최적화·승인/타임시트·여러 파일 일괄 채택은 별도 범위다.
