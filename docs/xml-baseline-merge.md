# 기존 문서에 외부 XML 기준선 병합

2026-11-15 후속: [native 상세 시간분포 출력](native-baseline-timephased.md)의 부모 위치 기준선 자료도 같은 번호별 연결/교체 검토로 병합한다. 새 위치 정보는 조건부 schema77이며 기존 내부 시간분포/병합만 있는 최소 schema75/76은 유지한다.

2026-11-15 · XBM-01~06. [새 XML 사본 채택](xml-baseline-exchange.md)에 이어 현재 문서의 번호별 기준선 출처를 명시적으로 교체한다.

## 사용 흐름

파일 → **외부 XML 기준선을 현재 문서에 병합…** → XML 선택 → 기준선 번호 선택 → 작업·WBS·자원·프로젝트 연결 또는 명시 제외 → 현재/수신 값 비교 → 필요 시 기존 번호 교체 확인 → 검토자·사유 입력 → 병합 → 일반 저장.

번호와 대상은 기본 미선택이다. 이름·XML UID가 같다는 이유로 자동 연결하지 않는다. 작업/자원 연결에 따라 배정도 대응하며 해당 배정이 현재 문서에 있어야 한다. 배정만 기준선을 가진 원본도 작업/자원 연결이 필요하다. 프로젝트 UID0은 현재 프로젝트에 연결하거나 명시 제외할 수 있다. 작업은 작업끼리, WBS는 WBS끼리 연결한다. 자원 종류가 다르면 공수 단위 보호를 위해 거절한다.

## 수용 계약

- XBM-01: XML 원본 바이트·변환 프로젝트·보고·후보를 다시 읽어 대조한 뒤 선택 번호의 전체 유효 후보를 준비한다. 같은 번호에 잘못된/중복 값이 있으면 그 번호 전체를 거절한다. 선택하지 않은 다른 번호의 오류는 기존 후보 계약대로 격리한다. 준비·취소는 문서를 변경하지 않는다.
- XBM-02: 선택 번호의 모든 원본 객체에 일대일 대상 또는 명시 제외를 요구한다. 다대일·누락 연결·없는 현재 객체/배정을 거절한다. 제외 작업/자원의 배정은 함께 제외한다. 각 선택 번호에 최소 한 개의 연결된 기준선 행이 필요하다. 현재 작업/자원/WBS/배정은 생성하지 않는다.
- XBM-03: 번호 전체를 교체한다. 그 번호에 현재 외부 값이나 native vN+1 승인이 있으면 교체 확인이 필요하다. 선택 번호의 누락·제외 객체/필드는 미설정이며 이전 외부 값이나 native 값으로 보충하지 않는다. native 승인본 자체는 보존한다. 선택하지 않은 번호의 행·출처·검토자·사유·동결 달력은 그대로 유지한다. 서로 다른 XML의 번호를 함께 보존하며 요약 기간 계산도 해당 번호의 달력을 사용한다.
- XBM-04: 현재 계획·달력·실적/원가/기간 원장·마감·승인본·시나리오를 변경하지 않는다. 상태일 없이도 병합할 수 있다. 기준선 변경만으로 기존 평준화 선택을 해제하지 않는다. 통화가 다르면 병합을 거절하며 기존 명시 통화 전환 흐름으로 먼저 맞춘다. 시간분포를 실제 원장이나 native EVM으로 만들지 않는다.
- XBM-05: 작업자 스레드에서 결과를 준비하고 원래 문서 session/revision과 편집 권한을 재확인해 한 번에 반영한다. 읽기 전용·취소·stale는 부분 반영하지 않는다. 병합은 일반 저장으로 보존하고, 이력에는 원본 이름/SHA256·검토 정보·선택 자료·연결/제외표·기존 번호 교체 확인·통화·전후 기준선 집합을 남긴다. 전후 결과를 재실행하여 검증한다. 승인/실적 이력과 같은 보존 정책으로 일반 undo 대상에 넣지 않으며 정정은 명시 재병합으로 기록한다. 화면의 **보존된 병합 이력…**에서 기록을 조회한다.
- XBM-06: 병합 이력 또는 번호별 출처가 있으면 조건부 schema76이다. schema75 이하에서는 새 필드를 거절한다. 기존 단일 사본 채택만 있는 파일은 schema75를 유지한다. 저장·재열기·복구·기준선/시나리오 동결과 전체 통화/ID 이관 사본을 연결한다. 현재/동결 기준선 값은 전환·이관하되 병합 감사 기록은 당시 통화/ID의 전후 자료로 보존한다. XML 재내보내기는 현재 연결 ID와 선택 번호 값을 사용하고 native 전체 이력은 `source.ppm`에 보존한다.

병합 이력은 최대128건, 이력의 수신/전후 기준선 합계는300,000행이다. 기존 native 파일 크기·시간분포 개수 한도도 적용한다. 원본 XML 전체 바이트는 문서 안에 추가 복제하지 않으므로 **원본 XML 파일을 함께 보관**한다. 이 기능은 지원되는 기준선 값의 병합이며 일반 XML 계획 병합·자동 환율·native 승인 생성은 포함하지 않는다.

실제 MS Project/P6 실행 환경이 없어 제품 왕복은 미실행 상태를 유지한다. [구현 검증 기록](validation/xml-baseline-merge-2026-11-15/README.md).
