# 시간축 계획 입고·잔여 자재 재고

2026-11-17 후속: [자재 제약 여유·임계](material-float.md)는 시각별 재고를 후보/최대 여유 배치에 검산한다. 아래 MINV-04의 여유 미산정은 이 후속으로 대체한다. 자동 지연과 실제 원장도 각 후속 계약을 따른다.

2026-11-17 후속: [실제 자재 원장·잔여 자동 대기](actual-materials.md)를 지원한다. 아래 계획 재고와 별도로 실제 거래·정정·상태일 확인을 보존하고 잔여 일정의 재고 공급을 구성한다. 실제 원가를 자동 생성하지 않는다.

2026-11-17 후속: [MAD-01~07 자재 입고 자동 대기](material-arrival-leveling.md)를 추가했다. 명시 옵션을 켜면 계획 평준화가 재고를 예약하며 날짜를 자동 지연한다. 아래 MINV의 기본 검산 방식은 옵션을 끈 기존 계획에 유지한다. 자동 옵션/정책 이력은 조건부 schema82다.

2026-11-17 · MINV-01~07. **자원 → 자재·비용계정·역할 계획 → 계획 입고**에서 시각별 입고를 편집하고, **자원 → 계획 입고·잔여 자재 재고…**에서 지정 시각의 계획 재고와 최초 부족을 조회한다.

| 값 | 정의 |
| --- | --- |
| 개시 재고/시각 | 해당 분의 입고·소모 **직전** 재고. 빈 시각은 프로젝트 시작일09:00 |
| 누적 입고 | 개시 시각 이후 해당 분까지의 명시 계획 입고 합계 |
| 누적 소모 | 개시 시각 이후 해당 분까지의 계획 작업 소모 |
| 잔여 | 개시 재고+입고−소모. 음수 보존 |
| 사용 가능 / 부족 | max(잔여,0) / max(−잔여,0) |

수량은 자재 단위의1/1000 정수이며 UI는 소수3자리다. 개시 재고 미정은 입고가 생겨도 잔여 미정이다. 같은 분의 입고·소모는 합산 후 재고를 판정하므로 그 분에 받은 자재를 그 분에 소모할 수 있다. 조회 시각은 시간대 없는 civil 분이며 OS 현재 시각을 읽지 않는다.

- **MINV-01 입력:** Material의 선택 `stockAt`와 ResourcePlan의 `receipts:{id,materialId,at,quantityMilli}`를 추가했다. 입고 ID는 기존 자원 계획 전체 ID와 중복할 수 없다. 자재 참조·유효 시각·개시 기준 이후·양수1~10^12 milli를 검증하며 입고는 최대100,000개다. 개시 기준 이전 입고를 중복 반영하지 않도록 거절한다. 개시 시각 이전 조회는 미정이다.
- **MINV-02 소모:** 기존 자재 소모의 시작/완료/균등 발생 방식을 사용한다. 시작·완료는 해당 분에 전량 소모한다. 균등은 실제 작업 실행 구간의 근무분에 누적 half-up 정수 반올림으로 배분한다. 분의 작업을 마친 경계에서 소모하며 마지막 분까지 총량이 정확히 보존된다. 점심·휴일·수동 중단·자원 달력 공백을 제외하고 여러 자원의 겹치는 실행 구간은 한 번만 센다. 자원 없는 작업은 작업 달력을 사용한다.0기간 균등 소모는 완료 시각에 발생한다.
- **MINV-03 문맥/부족:** 완전하고 현재 문서/revision/profile에 맞는 계획 일정과 채택 계획 평준화만 사용한다. 미정 일정·부분 작업 목록·예측 결과를0소모로 처리하지 않는다. 개시 시각이 계획 중간이면 이전 소모를 다시 차감하지 않으며 해당 분 이후 소모만 계산한다. 입고 직전·소모 경계에서 잔여를 확인하고 단조 감소 구간을 이진 탐색해 최초 부족 분을 찾는다. 이후 입고로 회복되어도 과거 부족을 숨기지 않는다.
- **MINV-04 평준화:** 날짜 있는 재고/입고를 쓰면 단일 프로젝트 및 공유 통합 평준화의 후보 결과를 시각별 재고로 검사한다. 총 입고가 충분해도 제때 도착하지 않으면 결과를 거절한다. 작업 날짜 또는 입고를 직접 조정한 뒤 다시 계산할 수 있다. 자동 자재 지연/구매 최적화 탐색은 후속이다. 실제 소모 원장이 없는 잔여 예측 평준화는 날짜 있는 자재 입력에서 명확히 거절한다. 해당 제약을 포함한 자원 여유는 미산정으로 표시한다. 날짜 없는 기존 자재는 기존 전체 재고 검사를 유지한다.
- **MINV-05 화면/출력:** 자재 표의 개시 시각·새 입고 탭을 기존 단일 저장/undo/redo에 포함한다. 잘못된 입력/읽기 전용/취소/stale는 원본을 보존한다. 조회는 불변 입력의 비동기 계산·취소·문서/시각 변경 무효화를 사용한다. JSON/XLSX/PDF에 음수·미정·개시 기준/조회 시각·최초 부족을 보존하며, 일반 보고서도 개시 재고와 입고 목록을 별도 표로 제공한다. JSON 단위는 `quantityScale:1000`,계약은 `ppm-material-inventory-v1`이다. XLSX 수량은 소수3자리의 정확한 텍스트다.
- **MINV-06 저장/교환:** 입고 또는 개시 시각을 사용하면 조건부 native **schema81**,미지원 미래82다. 현재/승인본/시나리오·일정 채택·통화/ID 전후 사본 전체를 검사한다.80 이하에서는 새 필드를 거절하고 미사용 파일은 기존 최소 writer를 유지한다. undo/복구/저장과 사본에 보존하며 입고는 작업 복제/삭제에 따라 복제·삭제하지 않는 자재 전체 입력이다. 통화 전환은 기존 단가만 환산하고 입고 수량·시각을 바꾸지 않는다. XML/XER에는 기존 자원 계획 손실 안내를 유지하고 native 보존 범위를 명시한다.
- **MINV-07 한계/한도:** 계획 입고는 실제 입고·타임시트·실제 원가가 아니다. 구매 원가를 새로 만들지 않으며 기존 소모 원가를 한 번만 합산한다. 자원 공유 풀도 자재 재고를 자동 공유하지 않는다. 실행/입고/소모 항목500,000개,최초 부족 검색의 예상 평가 작업량5,000,000개와 기존 일정/입력 한도·취소를 적용한다. 근무분 전체를 일별/분별 저장 자료로 팽창시키지 않는다.
