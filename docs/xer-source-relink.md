# 새 XER 버전·삭제 ID 재연결

2026-11-08 · XRL-01~06. 기존 XER 문서에 새 원본의 작업/자원 식별자를 연결하고, 삭제 후 다시 만든 현재 ID와 이전 집계의 관계를 보존한다. 현재 계획·의존관계·달력·실제 원장과 누계 AC는 유지하며 새 원본의 재무 스냅샷·파일 지문·연결표를 새 이력으로 등록한다.

## XRL-01 파일·프로젝트 선택

**파일 → 새 XER 버전·삭제 ID 재연결…**에서 인코딩(UTF-8 또는 Windows-1252)을 지정하고 새 파일을 읽는다. 여러 프로젝트가 있으면 대상 프로젝트를 선택한다. 파일 이름/SHA256, 선택한 프로젝트 이름/ID, 원본 상태일과 통화를 확인한다. 읽기는 worker에서 수행하며 취소·실패·문서 변경에는 새 원본을 등록하지 않는다.

관측 재무 스냅샷이 없는 계획 XER도 작업/자원 사전으로 사용할 수 있다. 외부 상태일이 없으면 이를 명시하고 현재 문서 상태일을 연결 기준으로 기록한다. 재무 관측값을 만들어 내지 않는다. 현재 상태일은 이전 집계와 새 원본의 상태일 이상이어야 하며 통화가 같아야 한다.

## XRL-02 명시 ID 연결

연결표는 **새 원본**과 **이전 집계**의 작업/자원을 모두 보여준다. 같은 ID를 우선 후보로 제시하고, 없으면 같은 종류의 유일한 동일 이름을 후보로 제시한다. 중복 이름은 임의 선택하지 않는다. 현재 연결 대상 열에서 실제 작업/자원을 선택한다. 원본 이름과 현재 이름이 달라도 사용자가 같은 대상을 명시할 수 있다. 작업/자원은 별도 ID 공간이며 각 기준·종류 안에서 한 대상에 중복 연결할 수 없다.

이전 ID가 삭제됐고 현재 문서에 같은 이름의 새 작업/자원을 만들었다면 이전 집계 ID와 새 원본 ID를 각각 새 현재 ID에 연결한다. 실제 원장의 작업/자원 ID나 기존 작성자·기록 ID를 바꾸지 않는다. 원장/원가가 있는 현재 항목의 기존 삭제 보호도 유지한다.

**미연결 / 관측 없는 항목 제외**는 관측값이 없는 사전 항목에만 허용한다. 실제 공수/원가·외부 요약과 명시0도 관측값이므로 연결 없이 제외할 수 없다. 존재하지 않는 대상, 중복 연결, 인력/장비 종류 불일치, 관측값이 있는 작업/자원 조합의 배정 누락은 차단한다. 날짜·통화·단위를 연결 과정에서 변환하지 않는다.

연결표를 확인하고 **선택한 프로젝트를 후속 원본으로 사용…**을 체크한 뒤 다음 검토를 연다. 연결 대상이 바뀌면 확인을 다시 해야 한다. 서로 다른 프로젝트 ID도 사용자가 후속 관계를 명시 확인한 경우에만 등록된다. 이름의 유사도나 외부 ID 숫자 변화량을 근거로 자동 승인하지 않는다.

## XRL-03 재무 스냅샷 후보와 누락 정책

새 원본의 알려진 배정 누계는 동일하게 연결한 현재 작업/자원 조합에 투영한다. 빈 누계 필드는 기본적으로 이전 보존값을 유지한다. 새 원본이 기간 명세를 제공하는 작업/자원 소유자는 그 새 명세를 사용하며, 명세가 없는 소유자는 이전 기간을 유지한다. 현재 문서의 작업/자원 사전·이름과 배정은 그대로 사용한다.

**새 원본의 빈 누계·빠진 기간을 미보고로 채택**을 선택하면 새 원본에 있는 배정의 빈 필드와 해당 작업에서 빠진 기간을 미보고로 취급한다. 이전 원본과 제출 이력은 남는다. 현재 계획의 배정을 지우거나 기존 날짜 원장을 철회하는 옵션은 아니다. 부분 원본과 유지값의 합성이 자체 대사를 만족하지 못하면 원본 범위와 이 정책을 확인해야 한다.

기존에 배분한 기간의 소유/구간/관측 금액이 같으면 날짜 연결을 유지한다. 새 원본의 단일 날짜와 현재 원장의 공수·원가가 정확히 같을 때도 연결할 수 있다. 그 밖의 새 원본 관측값은 스냅샷으로 보존하고 native 원장에 조용히 제출하지 않는다. 필요한 실제 정정/배분은 기존 편집기로 명시 제출한다.

## XRL-04 기존 병합 검토와 원자적 등록

**연결 검증·재무 병합 검토…**는 [XFM 병합 화면](xer-ledger-merge.md)을 연다. 새 원본과 현재 날짜 기록이 모호하게 겹치면 기간 교체를 검토하고, 정규/초과근무 누계가 부족하면 명시 입력한다. 현재 AC를 자동으로 늘리지 않는다. 작성자·사유를 입력하고 검증된 미리보기를 제출해야 등록된다.

단순 읽기·확인 취소·닫기·검증 실패에는 문서가 바뀌지 않는다. 읽기 전용·권한 회수·문서 ID/revision/session 변경·worker 취소에도 반영하지 않는다. 제출은 새 불변 이력이며 일반 undo로 삭제하지 않는다. 이후 일반 병합과 집계 편집·날짜 배분을 계속 사용할 수 있다. 이전 상태일/revision의 원장 ID·당시 AC 대사는 유지한다.

## XRL-05 저장·복구·교환

재연결 이력이 있는 문서는 조건부 **schema28**이다. 일반 XER 보존25·정정26·병합27 writer를 유지하고, 구 envelope의 새 필드/의미와 미래33을 거절한다. 원본 최초 스냅샷, 각 새 원본의 재무/ID 사전 스냅샷, 프로젝트/외부 상태일, 새/이전 ID 연결표, 빈값 정책·확인, 병합 선택·작성자/사유/UTC/문서/revision을 저장·복구·독립 사본에 보존한다. 당시 연결표와 원장을 사용해 결과를 재구성해 검사한다.

최신 재무 집계가 현재 문서와 일치하면 재내보낼 수 있다. `conversion.json.actualCosts.sourceRelinkCount`는 재연결 등록 건수다. 현재 계획과 원장의 값·이름은 유지하며 원본의 외부 이름으로 덮어쓰지 않는다. 원본 XER 전체 바이트가 필요하면 선택한 파일을 별도로 보관한다. SHA256는 파일 식별/손상 대조용이며 제작자 인증 서명이 아니다.

기존 XER16MiB·native64MiB, 작업/자원 각10,000·배정/기간100,000, 이력128건과 스냅샷 총300,000행 한도를 유지한다. 총 행 수에는 새 원본 스냅샷도 포함한다. 연결표는 기준별20,000행, 병합의 알려진 날짜 원장은1,000행까지 지원한다. 가상 표·공유 선택 목록·검색을 사용한다.

## XRL-06 검증·후속

`xer_source_relink_contract`는 외부 ID 변경·현재 ID 삭제/재생성·안전한 제외, 이름 중복/종류/통화/0·서로 다른 프로젝트, 빈 재무 사전과 정책, 원본/원장/AC 불변, 후속 병합, schema28/구버전·복구/사본/stale/취소/읽기 전용·파일 읽기와 메뉴/UI를 검사한다. `scripts/verify-xer-relink.py`는 전체 native 입력/원장 동일성·원본/본문/투영 SHA256·명시 ID 연결 oracle, TSV와 MPXJ16.10.0 strict reader를 사용한다. [전체 회귀 실행 증거](validation/xer-relink-2026-11-08/README.md)를 따른다.

2026-11-08 [native 기간 EVM](native-period-evm.md)은 동결 기준선과 native 보고 원장으로 기간 증감을 계산한다. [외부 XER EV/PV native 채택](external-xer-evm-adoption.md)은 별도 명시 이력으로 지원한다. 새 버전의 일정/WBS/달력·의존관계 자동 채택, 관측 원장 ID의 일괄 이관, 이름 유사도 자동 승인·통화/단위 전환, MPP reader와 실제 Oracle P6 재계산/재저장은 후속 범위다.

## 후속 통화·자원 단위 전환
