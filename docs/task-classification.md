# 작업 사용자 정의 필드·코드·그룹·저장된 보기

2026-11-11 후속: [XML 계산식](xml-external-formulas.md)의 Text/Flag/숫자/금액/기간/날짜 결과를 표·그룹·필터·정렬에 연결한다. 활성 결과는 직접 입력/지우기를 차단한다.

2026-11-11 후속: [요약 roll-up](xml-roll-up.md)은 현재 WBS·검색·필터의 고유 작업과 분류 계층으로 그룹 값을 계산해 툴팁에 표시한다. 계층 평균과 전체/직접/말단 개수를 구분한다.

2026-11-02 사용자 후속 개발 요청으로 구현한 GAP-03의 첫 증분이며 작업 객체를 대상으로 한다. 프로젝트/자원 사용자 정의 필드는 2026-11-05 [객체 필드 증분](object-custom-fields.md)으로 확장했다. 계산식 필드와 MSP/P6 UDF/Activity Code 교환은 후속 범위다. [로컬 검증 기록](validation/task-classification-2026-11-02/README.md)에 전체 CTest 67개와 독립 출력 검사·화면·측정을 보존한다.

## 사용 방법

1. **프로젝트 → 사용자 정의 필드…**에서 텍스트·숫자·날짜·목록 필드를 만든다. 목록 옵션은 같은 창에서 추가하거나 이름을 바꾼다. **작업 코드 사전…**에서는 코드 종류와 부모/자식 코드를 관리한다.
2. 작업 표의 새 열에서 값을 편집하거나 작업 여러 개를 선택해 **프로젝트 → 선택 작업 분류 값…**으로 일괄 배정한다. `값 제거`는 미설정으로 되돌린다. 텍스트의 빈 문자열은 미설정과 별개다. 기존 TSV 붙여넣기는 작업명·기간·선행의 세 열을 대상으로 한다.
3. **보기 → 분류·필터·정렬·열 배치…**에서 WBS·검색·필터와 최대 3단계 그룹·분류 정렬을 정한다. 열은 드래그로 순서를 바꾸고 체크로 표시하며 폭은 40~2,000픽셀이다. 숫자 값에는 단위를 붙여 입력하지 않는다.
4. WBS 탐색기의 **분류별 보기 · 전체** 아래 그룹을 선택하면 작업 표와 간트가 함께 좁혀진다. 작업 수·알려진 기간 합계·기간 미정 수는 그룹의 툴팁에서 확인한다. `전체`로 돌아가면 해당 WBS의 모든 그룹을 표시한다.
5. **보기 → 현재 보기 저장…**으로 조건과 열 배치를 이름으로 저장한다. 같은 이름은 확인 후 대체한다. **저장된 보기 적용…**에서 복원하고 필요 없는 보기는 삭제한다. 보기 저장/삭제는 실행 취소할 수 있으며 유효한 일정 계산을 무효화하지 않는다.

분류 필터의 `포함`은 단위 접미사를 제외한 표시 값을 찾는다. 임시 그룹/검색/필터는 보고서 범위를 바꾸지 않는다. XLSX/PDF의 분류 명세는 선택한 WBS 범위 전체를 사용하며 그룹별 원가·공수 소계는 제공하지 않는다.

## 데이터와 편집 계약

- 프로젝트별 작업 필드 정의(안정 ID·이름·형식·선택 단위·목록 옵션)와 작업별 값을 보존한다. 형식은 텍스트, 숫자, 날짜, 목록이다. 목록 옵션도 안정 ID를 사용하며 이름 변경으로 배정이 끊기지 않는다.
- 숫자는 소수 6자리의 정확한 고정소수로 처리하고 ±999,999,999.999999 범위를 사용한다. 날짜는 ISO civil `YYYY-MM-DD`다. 텍스트 빈 문자열과 미설정, 숫자 0과 미설정을 구분한다. 필드는 일정 기간·공수·원가에 자동 합산하지 않는다.
- 작업 코드 종류별로 ID·이름·부모 ID를 가진 계층형 코드 사전을 두고 작업에는 종류별 최대 하나의 코드를 배정한다. 코드 이름/부모 변경은 ID 배정을 유지한다. 현재 배정된 옵션/코드를 없애거나 값이 있는 필드의 형식을 변경하면 원자적으로 거절한다.
- 필드/코드 종류 삭제는 현재 작업 값과 저장된 보기 참조를 먼저 확인한다. 무음으로 값을 삭제하거나 잘못된 참조를 남기지 않는다. 기존 기준선/시나리오의 사전·값은 별도 동결 입력으로 보존한다.
- 정의는 필드 64개·코드 종류 64개, 전체 코드 노드 10,000개, 계층 깊이 16단계로 제한한다. 필드당 목록 옵션은 1,000개, 텍스트 값은 UTF-8 16KiB다. 잘못된 형식·중복 ID·계층 순환·누락 참조·제한 초과는 명시 진단으로 거절한다.
- 일반 편집·다중 작업 배정·삭제는 하나의 편집으로 검증 후 반영하며 실행 취소/다시 실행을 제공한다. 읽기 전용은 조회·임시 보기 변경만 가능하다. 복제 작업은 분류 값도 복제하고 실적·원가 원장은 복제하지 않는다.

## 보기와 집계 계약

- 기본 작업 열에 사용자 필드/코드 열을 추가하고 WBS와 별도의 분류 탐색을 제공한다. 최대 3개 분류 키를 순서대로 그룹화하고 선택한 그룹은 표·간트의 동일 작업 ID를 표시한다. 코드 그룹은 실제 배정된 코드 값으로 묶으며 전체 계층 경로를 레이블로 보여 준다.
- 그룹과 필터는 전체 계산 그래프와 원본 작업/선행 번호를 바꾸지 않는다. WBS 범위에 검색·기본 필터·분류 필터를 적용한 후 그룹/정렬을 구성한다. 미설정 그룹은 별도 표시하고 같은 작업은 각 그룹 단계에 한 번만 포함한다.
- 그룹 합계는 고유 작업 수·알려진 작업 기간 합계·기간 미정 수를 표시한다. 기간 합계는 경과기간이 아니며 공수·금액을 혼합 합산하지 않는다. 기존 WBS·원가/EVM 보고의 범위와 집계는 유지한다.
- 필터는 분류 키에 대한 같음·포함·미설정·설정됨을 지원한다. 같음은 목록/코드의 안정 ID를, 포함은 표시 텍스트를 사용한다. 숫자 정렬은 수치 순서이고 날짜는 날짜 순서이며 미설정은 뒤에 둔다.
- 저장된 보기는 이름·WBS·검색·기본 필터/정렬·분류 필터·그룹 키/선택 경로·분류 정렬과 열 ID별 순서/폭/숨김을 보존한다. 최대 64개다. 적용은 임시 화면 변경이며 저장/삭제만 프로젝트 입력 이력으로 남긴다. 파일을 열 때 임의 적용하지 않고 사용자가 저장된 보기를 선택한다.
- 새로 추가된 열은 기존 보기에 없는 경우 기본 표시로 뒤에 붙인다. 존재하지 않는 필드/코드/WBS를 가리키는 저장된 보기는 거절하며 이름 변경은 참조에 영향을 주지 않는다.

## 파일·기준선·교환

기간 실적 원장이 있으면 schema 11이 우선한다. 원장이 없고 분류/저장된 보기 또는 이를 포함한 기준선/시나리오가 있는 파일은 native schema 10으로 저장한다. 새 데이터가 없는 파일은 기존 schema 9 writer를 유지한다. schema 1~9를 계속 읽고 schema 1~8은 기존 원본 보존 사본 저장 정책을 유지한다. schema 9에서 새 분류 데이터를 추가해 저장하면 schema 10이 되며 이전 앱은 미지원 버전으로 거절한다.

필드 사전/값은 PlanInput에 포함해 기준선/시나리오가 동결하고 저장된 보기는 현재 Project에만 둔다. 실행 취소 dirty 계산·복구·파일 사본에서 새 데이터를 보존한다. XML/XER의 실제 매핑은 추가하지 않으며 내보내기 손실 진단과 native 원본 보존으로 미교환 범위를 알린다.

보고서에는 작업 ID·필드/코드 종류·값·단위를 가진 분류 명세를 추가한다. 숫자는 XLSX 숫자 셀로, 미설정은 미정으로 출력한다. 명세 행이 늘어도 기존 일정/공수/원가/EVM 합계에 중복 합산하지 않는다. 그룹 선택은 임시 작업 보기이며 기존 보고서의 WBS 범위와 구분해 안내한다.

5. 저장된 보기의 열 순서/폭/숨김과 조건 복원, 분류 보고서·XLSX/PDF, 기존 계산/원가 합계 불변과 1천/1만 작업의 반응성을 검증한다.
