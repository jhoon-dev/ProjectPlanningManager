# XER 재무기간·누계 보존 스냅샷

2026-11-08 [XER EV/PV native 채택](external-xer-evm-adoption.md)은 보존 집계의 TASKFIN 관측을 별도 기준선/작업·개시 누계와 명시 연결한다. 읽기/집계 편집만으로 활성화하지 않으며 선택한 지표를 native EVM에서 대체한다. 최초/각 재무 스냅샷은 그대로 남고 채택/철회 이력은 조건부 schema29로 보존한다. 외부 EV/PV를 원가/물리 진척에 합산하지 않는 기본 경계는 유지한다.

2026-11-07 후속: [집계 편집·날짜별 배분](xer-aggregate-editing.md)은 원본을 유지하고 조건부 schema26 정정 이력과 명시 날짜 원장을 추가한다. 조회 창에서 최신 정정·원본을 각각 확인하며 문서와 일치하는 최신 집계를 재내보낸다. 아래 XFS 계약의 원본 불변·외부 EV/PV 분리 규칙을 유지한다.

2026-11-07 · XFS-01~06 · GAP-09. [실적·원가 교환](xer-actual-cost-exchange.md)에 이어, 날짜가 없는 배정 누계와 주/월 등 여러 날짜의 재무기간을 `.ppm` 자체에 보존하고 조회·재내보내기한다. 원본 데이터와 현재 날짜별 실적 원장은 다른 표현이므로 합산하지 않는다.

## XFS-01 보존 모델과 계산 경계

`Project.xerFinancials`는 가져올 때 생성하는 읽기 전용 스냅샷이다. 원본 파일 이름/SHA256·원본 프로젝트 ID·상태일·통화·UTC 가져오기 시각, 당시 작업/자원 이름·종류, 정규/초과근무의 누계 공수·원가와 원본 재무기간 시작/종료를 보존한다. TASKFIN의 인건비·장비비·자재비·경비와 BCWP/BCWS도 외부 요약으로 보존한다.

이 필드는 현재 계획 입력이나 승인 기준선이 아니다. native 일정·Usage·원가/EVM 계산은 기존 ProgressEntry/CostEntry/PeriodActualEntry만 사용한다. 원본 누계나 재무기간을 실제 날짜에 나누어 적지 않고, BCWP/BCWS로 native EV/PV를 대체하지 않는다. 기존 일 단위 재무기간의 날짜별 원장 매핑은 유지한다.

예제 입력은 누계3.75h(정규3.25+초과근무0.50), 재무기간 명세3.25h, 기간 미지정0.50h를 가진다. 여러 날짜의 첫 기간2h를 날짜별 원장에 나누지 않아 native 날짜별 공수는1.25h다. 누계 AC는122.80 USD이며 native 날짜 배분은33.34 USD다. 보존된 주간 금액을 다시 더해 누계를 늘리지 않는다.

## XFS-02 조회

**파일 → XER 보존 재무기간·누계 조회…**에서 조회한다. XER 집계가 없는 문서에서는 이 메뉴가 비활성화된다. 읽기 전용 문서에서도 사용할 수 있다.

- 배정 누계·기간 미지정: 정규/초과근무, 재무기간 명세 합계, 기간이 없는 차액, 누계/기간/미배분 원가.
- 자원 재무기간: 원본 시작·종료와 자원별 공수·원가. 여러 날짜의 구간을 그대로 표시한다.
- 작업 요약·외부 EV/PV: TASKFIN의 자원 종류별 비용·경비와 외부 EVM 값. native EVM에 합산하지 않는다는 설명을 함께 표시한다.

검색은 세 표에 같은 작업·자원·날짜 문자열을 적용한다. 표는 가상 모델을 사용하고 원본을 수정하지 않는다. 작업/자원을 현재 문서에서 지웠어도 당시의 이름과 단위를 조회할 수 있다. 통화는 스냅샷의 원래 통화를 표시한다.

## XFS-03 현재 문서와 일치하는 집계만 재내보내기

가져오기 당시 native 투영의 SHA256을 기록한다. 문서 내용이 달라지면 보존 스냅샷은 그대로 남지만 **현재 원장과 별도인 원본**으로 표시한다. 변경된 문서의 XER에는 현재 원장만 쓰고 과거 집계를 자동으로 합치지 않는다. 내보내기 미리보기와 conversion.json.actualCosts.preservedFinancials에 `reexported` / `stale-source-only` / `absent` 판정을 표시한다.

내용 지문은 보수적으로 문서 입력/원장·설정 전체를 대조하며 현재 revision/documentId/derivedFrom만 제외한다. 실행 취소로 내용이 되돌아오면 다시 일치한다. 내용이 같은 독립 사본도 보존 집계를 재내보낼 수 있다. 지문/원본 해시는 손상·상태 대조용이며 원본 제작자 인증이나 보안 서명이 아니다.

일치할 때는 TASKRSRC의 정규/초과근무 누계와 FINDATES/TRSRCFIN/TASKFIN의 원본 구간·값을 다시 쓴다. 자원 원가는 보존된 누계110.46 USD, 직접비12.34 USD로 되돌려 작업 AC122.80을 유지한다. TASKFIN 자원 요약은 별도 AC로 더하지 않는다. 원본 항목 ID 대신 새 ID를 생성하며, 일괄 내보내기에서는 모든 재무기간·배정 참조를 다시 배정한다. 원본 비용 항목별 이름/발생 규칙을 완전히 복원하는 기능과 P6 DB 갱신 동일성은 범위 밖이다.

## XFS-04 저장·복구와 한도

일반 원본 스냅샷만 있으면 **schema25**, 일반 정정만 있으면 **schema26**, [병합 이력](xer-ledger-merge.md)이나 독립 외부 요약/경비의 분리 중첩이 있으면 **schema27**, [새 원본 ID 재연결](xer-source-relink.md) 이력이 있으면 **schema28**, 외부 EV/PV 채택/철회 이력이 있으면 **schema29**다. 없는 문서는 기존 schema9~24를 유지한다. 구 버전 envelope의 새 의미/필드와 미래 schema30를 거절한다. native 저장/재열기·독립 사본·dirty 복구·문서 변경/undo/redo에 보존한다. XML 내보내기에는 전용 스냅샷을 투영하지 않고 source.ppm 보존 진단을 표시한다.

원본16 MiB·전체 셀/행 한도와 native64 MiB 제한을 유지한다. 스냅샷은 작업/자원 각각10,000개, 배정100,000개, 자원·작업 재무기간 합계100,000행, 서로 다른 구간10,000개를 제한한다. 날짜·소유·중복·단위·정수 최소단위·통화·음수·초과 배분을 검사한다. 같은 작업/자원 또는 작업 요약의 겹치는 civil 기간은 중복 집계 위험으로 거절한다. 휴일에도 관측값을 보존하며 이를 계획 달력으로 재평가하지 않는다.

## XFS-05~06 검증과 남은 범위

수작업 `tests/fixtures/primavera-financial-periods.xer`, `xer_financial_snapshot_contract`와 기존 XER/파서·전체 회귀로 확인한다. 원본 주간 구간, 정규/초과근무·누계/기간 미지정 값, AC/EVM 중복 방지, schema25·사본/복구·undo/stale, 고아 이력의 조회, 두 프로젝트 결합/선택, 잘못된 JSON/참조/기간/금액을 검증한다. `scripts/verify-xer-financials.py`는 별도 TSV/Decimal·native/projection SHA256·MPXJ16.10.0으로 판독한다. [실행 증거](validation/xer-financials-2026-11-07/README.md).

집계 편집·명시 날짜 배분은 후속 [XAE](xer-aggregate-editing.md), 원본/현재 원장 병합은 [XFM](xer-ledger-merge.md)에서 지원한다. native 기간 EVM, 외부 계산식·배정 override, 삭제 ID/단위 전환, MPP reader와 실제 Oracle P6 재계산/재저장은 후속 범위다. 실제 제품 실행을 독립 reader 성공으로 대체하지 않는다.
