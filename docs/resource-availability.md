# 부분일·무기한 자원 가용기간

2026-11-16 후속: [현재 부하를 반영한 잔여 가용량](remaining-resource-availability.md)을 지원한다. 기존 가용기간과 자원 근무 달력에 동시간대 실행 수요를 연결하고 잔여/부족·추가 배정 가능량, 조회 UI·계산식·교환/보고를 제공한다.

2026-11-16 · RAV-01~06. 자원 등록 화면에서 부분일·무기한 가용기간과 자원의 전체 가용 시작/종료를 편집한다. native 가용량·과부하·평준화·외부 계산식과 XML 교환에 같은 규칙을 적용한다.

| 입력 | 의미 |
| --- | --- |
| 가용 시작 / 종료 | `YYYY-MM-DD HH:mm`. 시작·종료 분을 모두 포함하며 빈칸은 해당 방향 제한 없음 |
| 기간별 가용량 | `2026-11-16 09:00 ~ 2026-11-16 11:59=50`. 해당 구간50% |
| 무기한 기간 | `2026-11-17 00:00 ~ =200`, ` ~ 2026-11-15 23:59=?` |
| `?` / `0` | 가용량 미설정 / 알려진 가용량0%. 서로 구별 |

- **RAV-01 모델:** Resource.availableFrom/availableTo와 AvailabilityPeriod.from/to/units를 저장한다. 전체 경계 밖은0%, 경계 안은 날짜 예외→기간 예외→기본 Max Units 순서다. 기간끼리 같은 종료/시작 분을 공유하면 겹침이다. 경계 역전·잘못된 민간 시각·가용률 범위 위반·겹침은 거절한다. 기간은 자원당10,000개, 프로젝트 PlanInput당100,000개까지다. 초과근무·부하 차감·자재 입고는 이번 범위에 포함하지 않는다.
- **RAV-02 계산:** 시간대 없는 civil 분으로 적용한다. 근무 달력은 작업 실행 구간을 정하고 가용량은 그 구간의 수요를 제한한다. 기본 계획의 날짜를 가용률 때문에 자동 이동하지 않으며 과부하로 표시한다. 명시 평준화에서는 FixedDuration/고정 공수·단위의 실행 수요와 기간 경계를 검사한다. 기존 세 엔진과 재분배 여유 탐색에 가용량 변화 좌표를 연결한다. 기존 가용량 정의의 의미와 동결 입력은 유지한다.
- **RAV-03 계산식:** `PPMUnitAvailability(#2026-11-16T10:30:00#)`는 명시한 분의 값을1=100%로 반환한다. 날짜만 주면00:00이다. 기존 일별 예외만 있는 문서는 시각에 따른 값 차이가 없다. 기간/전체 경계 변경은 혼합 XML/native 식 캐시를 무효화한다. `[Max Units]`는 계속 설정된 기본 가용률이다.
- **RAV-04 XML:** AvailableFrom/AvailableTo·AvailabilityPeriods의 분 단위·무기한 범위를 읽는다. 시작은초00, 종료는초00/59만 지원하며 종료 분을 포함한다. 더 세밀한 경계·중복/잘못된 기간은 부분 적용하지 않고 날짜 조회식을 비활성 보존한다. 단순한 전체 날짜 범위는 기존 CapacityDay 저장을 유지한다. 장기간/부분일/무기한 자료는 일별로 팽창시키지 않는다. 새 native 모델의 출력은 기본값·날짜 예외·전체 경계를 겹치지 않는 완전한 기간표로 투영하고 종료초59를 쓴다. 기간 밖0과 기본 가용률도 명시한다. 편집 정의/우선순위는 source.ppm, XML은 유효 가용량을 보존한다. XML 정규화 후 자원당10,000기간을 넘으면 출력하지 않는다.
- **RAV-05 편집·보고:** 등록 창의 새 입력은 기존 자원 편집 명령·undo/redo·읽기 전용 검사를 따른다. 등록 명세에 경계·기간을 표시하며 수요가 있는 실행 구간에서 가용량이 바뀌면 가용률과 최대 사용률을 `기간 내 변동`으로 표시한다. 과부하 시간/초과 공수는 실제 구간별 합이다. 알 수 없는 가용량은0으로 대체하지 않는다. XER는 새 가용기간을 완전히 표현하지 못해 손실 진단과 source.ppm을 따른다. XER 일괄 공유 자원 자동 연결은 새 가용기간이 있는 자원을 생략한다. 작업공간에서 명시 공유 자원에 연결하면 기존 계약대로 공유 풀의 가용량을 사용한다.
- **RAV-06 저장:** 새 가용 경계/기간이 있을 때만 조건부 schema79, 상한79·미지원 미래80이다. 현재/승인/시나리오·XER 일정 채택·통화/ID 이관 사본을 검사한다. 과거78 이하의 파일과 최소 writer를 유지하며 새 필드를 과거 버전으로 읽지 않는다. 긴 기간도 콤팩트하게 저장하고 편집 메모리 예산에 포함한다.

외부 XML 기간표에 빈 구간이 있으면 기존 PPM 계약처럼 기본 MaxUnits를 사용한다. 전체 가용 경계 밖은0이다. 외부 제품의 빈 구간 해석은 다를 수 있다. 이 정책은 실제 MS Project/P6 재계산 동등성을 의미하지 않는다. 외부 XML의 원본과 정적 스냅샷은 기존 교환 정책에 따른다.
