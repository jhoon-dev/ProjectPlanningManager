# 추가 전파의 비용 추정·적용 기준

2026-11-04 사용자 요청의 엔진1.8 증분이다. [비단조 전파](nonmonotone-propagation.md)의 작은 입력 추가 비용을 줄이고, 기존1.0~1.7 승인 기준선·현재 날짜·실적·원장·schema9~14를 유지한다.

## 수용조건

- COST-01: 후보 수·후보 실행 구간 수·관계 끝점 방문 수로 추가 순회 비용을 추정한다. 작은 입력의 전역 필수 부하 순회와 분기 연쇄 전파를 비용 대비 기대 절감이 부족하면 생략한다. 시간 측정값으로 계산 정책을 바꾸지 않는다.
- COST-02: 최초 추정에서 생략한 단위도 실제 정확한 탐색의 후보 실패가 누적되면 추가 전파를 켠다. 실제 제외 효과가 낮으면 재시도를 늦춘다. 제외 상태의 가역 복구, 필수 부하의 안전성, 남은 후보의 정확한 탐색/native 인증과 전체 예산을 유지한다.
- COST-03: 추정·적용·생략·관측 활성화·낮은 효과로 인한 중단을 진단한다. 기존1.7 전파/기준선은 당시 경로로 보존하며 새1.8과 같은 입력의 수치·날짜·반복 관측을 대조한다. 작은 공수/다일 용량과 큰 필수 부하 사례, 추정 경계·관측 전환·복구·미정/취소·native/출력을 검증한다.

추정은 실행 시간의 보장이나 실행 가능성 판정이 아니다. 생략하거나 중단한 전파는 후보를 임의로 제거하지 않으며, 정확한 탐색과 전체 자원 인증으로 결과를 확인한다. 모든 입력의 속도 향상이나 완료를 보장하지 않는다.

## 비용 산식과 적용

현재 선택 엔진은 `jobs-adopted-leveling-1.8`이다.1.7까지의 승인 결과는 당시 경로로 재현한다. 추가 비용 정책은 비단조 effort 묶음에 적용하며, 기존1.6의 안전한 상한·선택 이웃 전파·독립 단위·native 인증 공유는 유지한다.

`PropagationCost`는 움직일 수 있는 작업 수 M, 해당 후보 수 C, 고정 작업을 포함한 해당 범위의 후보 실행 구간 수 S, 관계 끝점의 후보 방문 수 E를 사용한다. 한 번의 추가 순회 추정량은 W=min(2,000,000, C+3S+E), 반복 탐색에서 피할 수 있을 것으로 추정한 방문 수는 R=min(2,000,000, M×max(0,C−M))다. M>1이고 R≥4×max(1,W)일 때 추가 전역 순회를 적용한다. 탐색 단위도 같은 산식으로 최초 분기 전파 적용 여부를 정한다. C는 이동 가능한 작업의 후보만 세고 S는 고정 작업의 구간 비용도 포함한다. E는 중복 관계를 제거한 양 끝 후보 수의 합이며 원본 연결 묶음 밖 대상은1로 센다. 단위 추정에서 다른 단위의 끝점도 원본 묶음에 남은 후보 수로 보수적으로 센다.

이동 작업이4개 이하이면 M(C−M)<4C≤4W여서 최초 적용 조건을 만족할 수 없다. 따라서 전역 정밀 추정을 생략하고 단위에서는 C만 하한으로 기록한다. 실패 F≥max(64,C)이고 남은 예상 실패가2C 이상이 될 때만 S/E를 읽어 W를 정밀 추정한다. 하한만으로 전파를 켜지 않으며 이후에는 정밀 W의 활성화 조건을 모두 만족해야 한다.

계수3과4는 보수적인 작업량 휴리스틱이며 시간 단위나 실측 속도 배율이 아니다. 추정은 후보 배열의 크기와 구간 수 메타데이터를 읽으며 실행 구간을 새로 생성하거나 시각을 기준으로 판단하지 않는다. 생략한 추가 전파 대신 기존 정확한 탐색이 모든 필요한 날짜·관계·합산 용량을 검사한다.

## 관측 활성화와 낮은 효과의 재시도 지연

처음 생략한 단위도 실제 탐색에서 날짜 관계나 합산 용량으로 거절된 후보 수 F가 max(64,W)개에 닿고, 남은 선택 작업의 예상 실패 수가2×max(1,W) 이상일 때 분기 전파를 켠다. 완료한 선택 작업 수를 A라 하면 남은 예상 실패 수는 (M−A)×ceil(F/(A+1))이다. 이미 쓴 실패는 회수할 수 없는 비용이므로 계산 후반에는 실패 누적만으로 전파를 켜지 않는다. 이 실패 계수는 같은 계산의 선택 작업들 사이에서 공유하며 자유여유의 다른 날짜 고정 경로에는 적용하지 않는다. 이미 검사한 후보 실패를 사용할 뿐 결과의 실행 가능성을 추정치로 확정하지 않는다.

한 번의 전파가 쓴 추가 판정 수를 Q, 끝점 지지/부하로 제외한 사건 수를 X라 할 때 Q>0이고8X<Q이면 단위의 추가 전파를 끈다. 이후 max(256,4W)개의 새로운 실패가 누적되기 전에는 재시도하지 않는다. 현재 분기의 안전한 제외는 가역 기록에 유지하고 기존 탐색을 계속한다. 필요하면 가역 마스크를 분기 중에 만들며, 생성 이전 조상의 복원 지점0도 처리한다. 임시 부하를 배경에 남기지 않는다.

1.7의 연산당 추가 전파50,000판정·전체1,900,000판정에서 기존 탐색으로 전환하는 상한과 전체2,000,000판정 예산은 유지한다. 비용 정책과 재시도 상태는 계산마다 새로 만들며 세션 간 학습이나 파일 입력을 추가하지 않는다. 미정 가용량·취소·전체 한도·native 인증 실패의 처리는 기존 계약을 따른다.

## 진단·호환·검증

`LEVELING_PROPAGATION_COST_POLICY`는 전역 순회 생략 수, 탐색 단위의 최초 생략 수, 최초 추정에서 적용 가능하다고 본 단위 수, 실제 실패 관측 후 활성화 횟수, 낮은 효과의 재시도 지연 횟수, 판단에 사용한 추정 순회량의 합, 지연 정밀 추정 횟수를 순서대로 기록한다. 최초 판단 계수는 실제 완료한 전파 횟수와 구분한다. 순회량 합에는 여러 범위/순회의 W와 정밀 추정 전 하한 C가 포함되며 실제 판정 수나 실행 시간이 아니다. 실제 추가 판정·제외·상한 전환 수는 기존 `LEVELING_NONMONOTONE_PROPAGATION_POLICY`에서 함께 확인한다.

`propagation_cost_contract`는 산식 경계·구간/관계 비용·포화·지연 정밀 추정·후반 활성화 방지·관측/재시도 경계와 실제 작은 후보 분기의 지연 마스크 생성/복원을 검사한다. 작은 공수/다일 용량/달력 공백·큰96작업·기존 분할 사례에서1.7/1.8의 TaskSchedule 전체 값·현재 날짜를 비교한다. 늦은 활성화를 막는 사례를 포함한 작은5사례는 각5회, 나머지3사례는 각3회 순서를 교차해 새 평가 캐시로 파생 계산만 측정한다. 캐시 해제까지 포함하고 전진 평준화·UI/파일 I/O는 제외한다. 반복 표본과 checkpoint는 원시 자료로 보존한다.

독립 reader는 기존 원시 시간축 oracle을 재사용해 작은 허용 배치4/55/673/17,366/64/32,768개와 분할155,761쌍을 전수 대조하고, 증인138개/날짜400개를 재구성한다. 기존1.7/신규1.8 기준선의 동일 수치·native12 재열기/체크섬·XLSX 출처와 새 진단을 확인한다.1.7 계약은 명시적으로 당시 엔진에 고정하고 공통 fixture만 추출해 유지한다. 입력 schema9~14와 과거 검증 폴더를 변경하지 않는다.

관측 활성화가 계산 후반에 발생하거나 추정이 맞지 않으면 작은 입력도 느려질 수 있다. 최종 표본의 개선과 회귀를 함께 [측정·전체 검증 기록](validation/propagation-cost-2026-11-04/README.md)에 보존한다.
