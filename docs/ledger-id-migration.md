# 관측 원장 ID 이관

2026-11-08 · LIM-01~06 · GAP-09. **파일 → 관측 원장 ID 이관…**에서 현재 작업·자원의 관측 원장을 명시한 새 ID로 이관한다. [새 XER 일정 채택](xer-schedule-adoption.md)으로 추가한 작업처럼 같은 객체를 새 ID로 관리해야 하는 경우에 사용한다.

## LIM-01 명시 연결과 충돌

관측 기록이 있는 현재 작업·자원을 원래 이름·ID·기록 수로 나열한다. 각 행에서 이관하지 않음, 새 ID 부여, 관측 기록이 없는 기존 대상 중 하나를 선택한다. 이름으로 동일성을 추정하지 않는다. 새 ID는 직접 입력하고 작성자·같은 객체로 확인한 근거를 기록한다.

새 ID는 원래 정의를 유지하며 식별자만 바꾼다. 기존 대상으로 이관하면 대상의 현재 작업/자원 정의를 유지하고 원래 중복 정의를 제거한다. 배정·예산·활동과 다른 작업의 선행 참조는 대상 ID를 사용한다. 기존 대상의 계획 기간·달력·단가가 원래 정의와 다르면 이후 계획 계산은 달라질 수 있다. 전후 원본 조회에서 전체 정의를 확인한다.

일대일 연결만 허용하며 같은 배치의 연쇄·순환, 중복 원래/대상, 다른 종류의 객체 ID 충돌을 거절한다. 대상에 관측 기록이 있으면 값이 0이거나 미정이어도 합칠 수 없다. 인력/장비 종류 또는 과거 공수 단위의 변경, 동결 기준선/시나리오가 이미 사용하는 대상 ID, 중복 배정·예산과 선행 순환을 거절한다. 배정 구간이 대상의 고정 기간을 넘는 경우 먼저 현재 계획을 정리해야 한다.

## LIM-02 관측값과 감사 정보

진행·누계 원가·날짜별 원장·Steps의 작업/자원 소유 참조를 이관한다. 기록 ID·이전 보고 ID·원가 보고 ID, 금액·통화·공수·실제/잔여 기간·물리 진척·Steps 값, 관측일·상태일·기록 UTC·기록 revision·작성자·사유·출처 문서는 유지한다. 기록을 새 실적으로 다시 생성하거나 두 이력을 합산하지 않는다.

기준선의 입력/계산 행과 선행 근거, 저장 시나리오의 입력/진행/날짜별 잔여 목표, 현재 잔여 목표·자재/비용/역할 배정·네트워크 위치도 연결한다. 기준선의 승인 정보와 동결 날짜·원가 수치는 유지하며 변환된 입력으로 기준선 계산을 재검증한다. 사용자 재무기간의 작업별 값과 마감 스냅샷, 외부 EV/PV 채택 작업도 연결하며 금액과 당시 지식 revision은 보존한다.

기존 선택한 평준화는 해제하고 결정 원장에 invalidate 근거를 남긴다. 기존 평준화 결정의 당시 메타데이터는 보존한다.

## LIM-03 XER 이력과 원본 공간

최초/정정/병합 XER 재무 스냅샷의 native 작업·자원 참조, 배정별 병합 선택, 재연결의 현재 대상과 이전 native 사전 연결을 이관한다. 재연결의 raw incoming 원본 ID 공간은 변경하지 않는다. 과거 일정 채택의 원본·연결표·전후 계획 전체도 당시 기록으로 유지한다.

원본 파일·과거 투영 SHA256은 당시 출처이므로 다시 쓰지 않는다. 현재 입력이 바뀌어 stale이 되면 기존 XER 규칙을 따른다. 필요할 때 별도 재무 병합 검토로 현재 투영을 다시 등록한다. 이관 이후 재연결·병합·외부 EV/PV·XER 내보내기는 새 native ID를 사용한다.

## LIM-04 검토·원자 제출

검증과 준비는 worker에서 실행한다. 원장 표는 기록 ID, 이전/이관 작업·자원 ID, 상태일/관측일/기록 UTC·작성자/사유·수치와 정정 연결을 전후로 표시한다. 원본 조회는 읽기 전용 전체 JSON 두 개를 제공한다. 연결표·작성자·근거를 바꾸면 준비 결과와 확인을 무효화한다.

동일 객체와 전후 결과를 확인한 뒤 단일 revision으로 제출한다. 취소·닫기·문서/session/revision 변경·읽기 전용/권한 회수 시 제출하지 않는다. 일반 undo로 이관 기록을 지우지 않는다. 추가 수정은 새로운 명시 이관으로 기록할 수 있으며 이관 후 일반 편집/undo는 계속 사용할 수 있다. 읽기 전용에서는 저장된 이관 이력과 전후 원본을 조회한다.

## LIM-05 저장·재실행·한도

이관 이력이 있는 파일은 조건부 schema33이다. `ledgerIdMigrations`에 `explicit-ledger-identity-v1`, 연결표·확인·작성자/근거·UTC·문서/revision과 전체 이관 전/후 스냅샷을 저장한다. 각 스냅샷에는 중첩 이관 이력이 없다. 앞선 이력은 루트 배열에서 별도 보존해 재귀 중첩을 막는다.

재열기 때 각 전 스냅샷에서 이관을 다시 수행해 후 스냅샷의 모든 필드와 대조한다. 연속 revision의 두 이관 및 이관 직후 현재 문서도 대조한다. 자동 평준화 해제 1건과 사본/복구의 새 문서 계보만 허용한다. 이후 일반 편집 revision에서는 과거 이관 결과를 현재 입력으로 강제하지 않는다.

기존 schema1~32 writer를 유지하며 구 envelope의 새 필드·알 수 없는 필드/형식·중첩 이력·손상된 전후 결과를 거절한다. 이력16건, 한 번의 연결20,000개, 모든 전후 스냅샷의 주요 행 합계300,000개 및 기존 native64MiB/각 컬렉션 한도를 적용한다. 파일 SHA256은 무결성 검사이며 디지털 서명은 아니다.

후속 [프로젝트 전체 통화 전환](project-currency-conversion.md)과 교차 실행할 수 있다. 두 전환의 이전 이벤트는 루트에 보존하고, 각각의 전후 원본에는 통화/ID 이관 배열을 모두 제외해 재귀 중첩을 막는다. 통화 전환 이력이 있는 문서는 schema34이며 후속 날짜 고정 잔여 역산을 포함한 현재 reader 상한35·미지원 미래36이다. 해당 새 의미가 전후 원본에 있으면 schema35로 보존한다.

XER에는 현재 native ID의 작업/자원 투영을 내보내고 교환 보고 `actualCosts.ledgerIdMigrationCount`에 건수를 기록한다. 이관 전후의 감사 원본은 `source.ppm`에 보존한다.

## LIM-06 검증

[회귀 실행 기록](validation/ledger-id-migration-2026-11-08/README.md)에 전체 회귀, 손상 파서 사례, 독립 JSON/원장 보존 대조, XER strict reader와 Windows 기본/800×600 화면을 남긴다. 서로 관측된 객체의 통합, 값/통화/자원 종류 환산, MPP 판독과 실제 P6/MS Project 재계산은 이 기능의 범위에 포함하지 않는다.
