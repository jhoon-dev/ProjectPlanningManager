# 다중 프로젝트 공유 풀의 잔여 가용량

2026-11-16 후속: [공유 풀의 부분·열린 가용기간](shared-resource-availability.md)을 추가했다. 아래 SRA의 시점 공급은 새 전체 경계/기간별 가용률도 반영한다. 새 설정이 있으면 작업공간은 조건부 schema4다.

2026-11-16 · SRA-01~06. **파일 → 다중 프로젝트·공유 자원… → 시각별 공유 잔여 가용량…**에서 명시 시각의 공유 공급과 연결된 프로젝트들의 동시 수요를 비교한다. 조회 결과는 프로젝트와 작업공간 입력을 변경하지 않는다.

| 값 | 계산 기준 |
| --- | --- |
| 유효 가용률 | 공유 풀 자체의 기본/날짜별 가용률과 근무 요일·시간대·휴일. 비근무 시각은0 |
| 전체 수요 | 명시 연결된 모든 프로젝트/로컬 자원의 실행 배정 수요 합계 |
| 확인된 수요 | 조회 가능한 기여만 합한 하한. 누락이 있으면 전체 수요를 대신하지 않음 |
| 잔여 | 유효 가용률−전체 수요. 음수 보존 |
| 배정 가능 / 부족 | max(잔여,0) / max(−잔여,0) |

공유 공급100%에 프로젝트 P가75%+25%, Q가50%를 동시에 사용하면 수요150%, 잔여−50%, 배정 가능0%, 부족50%다. 로컬 공급이 각각 다른 값이어도 공유 공급은 한 번만 적용한다.

- **SRA-01 연결:** `(documentId, resourceId)→sharedId`의 명시 연결만 사용한다. 이름과 로컬 ID가 같은 다른 파일을 구분하며, 한 프로젝트의 여러 로컬 자원이 같은 공유 풀에 연결되면 함께 합산한다. 열린 파일의 미연결 자원 수를 따로 표시한다. 다른 풀의 누락은 연결이 없는 풀의 수요0을 막지 않는다.
- **SRA-02 수요:** [단일 프로젝트 조회](remaining-resource-availability.md)의 실행 구간·반개구간 종료·곡선/중단/작업 및 자원 달력·공수 기반 배정을 재사용한다. 일별 peak나 기본 배정률을 합하지 않는다. 각 파일의 civil 분을 같은 날짜/시각으로 정렬한다. 독립 프로젝트 일정과 각 파일의 채택 평준화를 사용하며, 통합 일정의 교차 링크/공유 평준화 결과를 자동 채택하지 않는다.
- **SRA-03 공급:** 공유 카탈로그의 기본/날짜별 용량과 공유 달력을 한 번 적용한다. 로컬 capacity·가용기간은 공유 공급으로 합산하거나 덮어쓰지 않는다. 공유 상한10,000,000%, 로컬 상한100,000%를 구분한다. 공유 공급 미설정은 근무 중 잔여도 미정이다. 공유 풀의 부분/열린 가용기간은 후속 [SPA 계약](shared-resource-availability.md)으로 추가했다.
- **SRA-04 미정/예측:** 연결한 파일이 닫혔거나 일정이 불완전/충돌이거나 자원 연결이 유효하지 않으면 해당 풀의 전체 수요·잔여·배정 가능·부족은 미정이다. 확인된 수요와 프로젝트별 이유를 남긴다. 기본 현재 일정은 파일마다 상태일이 있으면 잔여 예측, 없으면 계획이다. 파일별 상태일보다 이른 조회는 그 파일의 실제 부하를 추정하지 않는다. 계획 일정 선택은 상태일 전 조회도 계획 수요로 계산한다. 출퇴근·타임시트 실적 조회를 뜻하지 않는다.
- **SRA-05 화면/출력:** 공유 잔여량·프로젝트별 기여·입력/상태일 탭, 비동기 계산·취소, JSON/XLSX/PDF 저장을 지원한다. 시각/모드/문서 revision/열기·닫기/공유 카탈로그·연결이 바뀌면 표와 출력 권한을 무효화한다. 미정이 있는 결과도 이유와 하한을 포함한 진단 자료로 저장할 수 있다. JSON은 `ppm-shared-remaining-availability-v1`, 백분율 정수100=1명/대, 알 수 없는 수치는null이다. XLSX/PDF는 미정으로 표기한다. 닫힌 파일의 revision/계산 방식도 미정이다.
- **SRA-06 저장/한도:** 파생 조회이며 새 영속 필드나 schema 변경이 없다. native 상한80과 기존 작업공간 schema1/2/3 계약을 유지한다. 프로젝트100·공유 자원1,000·연결10,000 및 연결 자원의 전체 실행 구간500,000개 한도를 적용하고 취소를 전달한다. 제공된 일정의 문서 ID/revision/profile/모드/상태일과 전체 작업 목록을 검사한다. 계산 시 입력과 공유 카탈로그를 복사하고 출력 시 같은 설정/작업공간 세대인지 검사한다.

조회 시각은 시간대 없는 명시 civil 분이다. 초기값은 참조한 열린 파일의 가장 늦은 상태일, 없으면 가장 이른 프로젝트 시작일09:00이다. OS 현재 시각으로 조회 기준을 바꾸지 않는다. `PPMResourceLoad`/`PPMRemainingAvailability`는 계속 해당 문서의 로컬 자원을 조회한다.
