# 자재 입고 대기에 따른 자동 작업 지연

2026-11-17 후속: [자재 제약 여유·임계](material-float.md)를 구현했다. 아래 당시 여유 미산정/미지원은 이 후속으로 대체한다. 자동 대기·수동 계획·확인 원장의 잔여 일정과 공유 통합에서 현재 완료일을 유지하는 총/자유여유를 계산한다.

2026-11-17 후속: [공유 통합 실제 자재 원장](shared-material-actuals.md)을 지원한다. 원본의 확인 재고·미입고 잔량·잔여 소모와 공유 자원/교차 링크를 함께 반영한다. 원장/단위/기준·정정 연결을 보존하고 자재 제약 여유는 계속 미산정이다.

2026-11-17 후속: [MAT-01~08 실제 자재 원장·잔여 자동 대기](actual-materials.md)를 별도 옵션·정책/schema83으로 구현했다. 아래 MAD-04의 잔여 예측 미지원은 기존 계획 옵션만 사용하는 경우다. 새 원장 확인 흐름은 단일 문서 잔여 예측을 지원하며 자재 제약 여유·구매/비용 최적화·공유 통합 잔여 원장 투영은 남는다.

2026-11-17 · MAD-01~07. **자원 → 자재·비용계정·역할 계획 → 평준화 시 자재 입고 대기에 맞춰 작업 날짜 자동 지연**을 켜고 저장한다. **기간별 부하·평준화 비교**에서 날짜를 검토한 뒤 기존 **A 결과를 현재 일정으로 채택**을 사용한다. 설정만 켜면 논리 ASAP 일정은 유지되며 평준화 비교/채택에서 자동 대기를 계산한다.

예:09:00 시작 작업에 철근1개가 필요하고10:00에1개가 입고되면 작업을10:00으로 늦춘다. 그 작업의 후속 작업도 선후관계에 맞춰 지연된다. 두 작업이 같은 입고1개를 각각 쓰지 않도록 이미 배치한 작업의 **미래 소모**까지 예약한다.

- **MAD-01 선택/호환:** ResourcePlan.autoDelayForReceipts를 명시적으로 켠다. 꺼진 기존 schema81 계획은 날짜별 재고의 후보 검산만 수행한다. 새 정책은 `serial-material-arrivals-v1`이며 기존 정책과 구분해 승인본/시나리오를 재현한다. 입력의 기간·공수·배정·제약·입고를 수정하지 않고 파생 배치를 만든다. 기존 채택/해제·undo/redo·저장/복구 흐름을 따른다.
- **MAD-02 탐색:** 기존 직렬 평준화의 준비 작업/우선순위·동률 행 순서를 유지한다. 각 후보는 선후관계·작업/자원 달력·자원 용량과 함께 자재 재고를 검사한다. 수락한 작업의 소모는 이후 후보에서도 유지한다. 시작 전량 소모는 다음 공급 변경으로 안전하게 건너뛰고,완료/균등 소모와 비단조 공수 곡선은 각 합법 근무분 후보를 검사한다. 완료 시 입고를 쓰는 작업은 입고 전 착수할 수 있고,균등 소모의 누적 반올림도 동일하게 적용한다.
- **MAD-03 재고 의미:** [계획 재고 계약](material-inventory.md)의 같은 분 입고/소모 합산과 정확한 milli 수량·소모 방식·중단/달력 구간을 사용한다. 자동 모드는 개시 시각 이전의 자재 소비를 가정하지 않는다. 다른 프로젝트의 이름/ID가 같은 자재도 자동 공유하지 않는다. 개시 재고 미정 또는 전체 입고를 합해도 부족한 자재는 즉시 거절하며,새 입고를 만들어내지 않는다.
- **MAD-04 제약/실패:** 고정 시작/완료·상한 날짜를 임의로 완화하지 않는다. 자재/자원에 맞는 날짜를 지정 탐색 기간 안에서 찾지 못하면 후보 날짜를 적용하지 않는다. 실제 입고/소모 원장이 없는 잔여 예측의 자동 대기는 지원하지 않으며 계획 평준화를 안내한다. 자재 제약을 포함한 자원 여유는 미산정이다. 우선순위 직렬 정책이며 전역 최소 완료일·구매/원가 최적해를 보장하지 않는다.
- **MAD-05 통합:** 공유 평준화에서도 옵션을 켠 프로젝트의 자재/소모/입고를 명시적으로 qualified ID로 투영한다. 각 프로젝트의 개시 시각을 유지하고,교차 링크·공유 자원 용량과 함께 배치한다. 옵션을 켜지 않은 프로젝트의 기존 재고 검산은 유지한다. 통합 결과는 읽기 전용이며 여러 원본 파일의 날짜를 일괄 덮어쓰지 않는다.
- **MAD-06 출처/저장:** `MATERIAL_DELAY` 진단은 자재 대기로 늦춘 작업과 시작 시각을 표시한다. 일반 XLSX/PDF 보고에 자동 대기 설정/정책을 표시한다. 옵션 또는 새 정책의 결정 이력이 있으면 조건부 native **schema82**,미지원 미래83이다. 현재/승인/시나리오·일정 채택·통화/ID 전후 사본과 채택 결정 이력을 검사한다. 옵션/자재를 지운 뒤 과거 결정만 남아도82를 유지한다.81 이하의 새 필드/정책은 거절하고 미사용 파일의 최소 writer와 workspace4는 유지한다.
- **MAD-07 한도/취소:** 기존 입력/탐색 기간·실행 구간 한도와 [재고 조회의 한도](material-inventory.md)를 유지한다. 자동 대기는 자재 후보20,000회·예상 검사 작업량100,000,000개를 상한으로 하고 협력 취소를 전달한다. 한도 도달은 실행 불가능의 증명이 아니라 별도 한도 진단이다. 실패·취소·stale는 채택하지 않는다.
