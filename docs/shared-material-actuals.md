# 공유 통합 예측의 실제 자재 원장·잔여 재고

2026-11-17 후속: [MF-01~07 자재 제약 여유·임계](material-float.md)를 구현했다. 아래 SMAT-07의 통합 여유 미지원은 이 후속으로 대체하며, 현재 완료일/자원 반환 순서·프로젝트별 확인 재고/미입고/잔여 소모를 함께 검산한다. 통합 표·JSON/XLSX/PDF에 총/자유여유·임계를 표시한다.

2026-11-17 · SMAT-01~07. [실제 자재 원장](actual-materials.md)의 확인/정정 규칙을 공유 통합 예측에도 적용한다. 새 프로젝트/작업공간 필드를 추가하지 않으며 native83과 기존 조건부 작업공간1~4를 유지한다.

사용 순서:

1. 각 자재 사용 문서에서 **실제 자재 입고·소모 원장**의 현재 상태일 재고와 잔여 소모량을 확인하고 **잔여 평준화에 확인된 실제 자재 재고·잔여 소모 적용**을 켠다.
2. 프로젝트마다 같은 상태일을 사용하고 작업공간에서 자원을 공유 풀에 명시 연결한다. 필요한 프로젝트 간 선후관계도 설정한다.
3. **프로젝트 간 링크·통합 일정 → 현재 예측 + 공유 자원 평준화 → 통합 일정 계산**을 실행한다. 작업의 실제 시작/통합 완료/통합 잔여 시작과 프로젝트별 자재 근거 표를 함께 검토한다.
4. 같은 계산 결과의 JSON/XLSX/PDF를 저장할 수 있다. 원본 문서의 날짜·원장·채택 설정은 보존되는 읽기 전용 통합 결과다.

예: P와 Q가 각각 재고0개, 미래 미입고2개를 갖고11:00에 자재가 도착한다. 공유 시공조가1개이고 각 프로젝트가1개 시공조를 쓰면 P의 잔여 작업을11:00~12:00, 후속을13:00~14:00에 먼저 예약한 뒤 Q의 잔여 작업은14:00부터 배치한다. 두 문서의 실제 시작09:00은 유지한다. 공유 시공조가2개면 두 잔여 작업을11:00에 함께 실행할 수 있다. P의 입고로 Q의 자재 부족을 대신 채우지 않는다.

- **SMAT-01 격리/원장:** 옵션이 켜진 프로젝트의 자재·계획 소모/입고·실제 거래 ID/안정 거래 ID/정정 연결·작업 참조를 구분된 통합 ID로 투영한다. 이름/원래 ID가 같아도 자재 재고는 프로젝트별이다. 단위·원래 개시 기준·작성/기록/보고 정보·원래 기록 리비전을 보존한다. 통합 그래프에서는 기록 리비전으로 안정 정렬해 서로 다른 프로젝트의 정정 사슬이 끊기지 않게 한다. 원본 원장은 수정하거나 합산 저장하지 않는다.
- **SMAT-02 공급/수요:** [MAT-03~05](actual-materials.md)의 상태일별 정정 선택·확인 재고·명시 잔여 소모와 실제 도착분을 차감한 미래 입고 잔량을 그대로 사용한다. 미래 상태일의 정정은 현재 공통 상태일에 적용하지 않는다. 미확인/부족/이미 지난 미입고 계획은 가상 공급으로 만들지 않는다. 확인 오류는 원래 프로젝트 ID와 함께 반환한다. 자재가 없는 문서도 같은 통합 자원/관계 그래프에 참여할 수 있다.
- **SMAT-03 배치:** 공유 가용량·부분/열린 가용기간·달력·프로젝트 간 관계와 자재 재고를 함께 검사한다. 이전에 수락한 작업의 미래 자원 점유/소모도 예약한다. 실제 시작/완료는 보존하고 잔여 구간만 이동한다. 소모 방식·정수 누적·곡선·완료 작업 처리와 원본의 진척 정책을 유지한다. 논리 통합 미리보기는 자재 대기를 자동 채택하지 않으며 별도의 공유 평준화 옵션으로 계산한다.
- **SMAT-04 날짜별 잔여 공수:** 작업/자원 참조와 날짜 목표를 통합 그래프에 연결한다. 같은 작업의 여러 로컬 자원을 하나의 공유 자원으로 합치면서 날짜별 잔여 목표가 있으면 부분 대체의 의미가 모호하므로 거절한다. 이때 공유 연결을 분리해야 한다. 날짜 목표를 생략하거나 조용히 합산하지 않는다.
- **SMAT-05 화면/출력:** 통합 표에 **통합 잔여 시작**을 별도 표시한다. 프로젝트/자재별 상태일·확인 재고·잔여 소모·미입고 잔량·원장 원본 리비전을 표시하고 JSON/XLSX/PDF에도 전달한다. JSON의 선택적 `materialStocks`는 milli 수량을 정확한 십진 문자열로 내보내며, 큰 합계도 binary64 정밀도 손실을 피한다. 원본 revision/작업공간 generation과 정책 `/material-remaining-v1`을 보존한다. 새 자재 결과가 없으면 기존 JSON/보고 구조를 유지한다.
- **SMAT-06 실패/세대:** 원장 정정·재확인·원본 입력·상태일·옵션·연결 변경 후 날짜/자재 근거/내보내기를 무효화한다. 재확인하지 않은 원장으로 다시 계산해도 결과를 내보내지 않는다. 오류/한도는 후보 날짜·완료·자재 근거를 부분 확정하지 않고 협력 취소를 전달한다. 전역 관계 순환·참조 누락·공유 달력 불일치·과부하/미정 가용 검사도 유지한다.
- **SMAT-07 한도/범위:** 선택된 자재 입력을 합해 자재10,000개·소모/계획 입고/실제 원장 각100,000행, 날짜별 잔여 공수10,000배정/100,000날짜행과 기존 작업·달력·배정·예약 탐색 한도를 적용한다. 자재 제약을 포함한 통합 여유/임계·전역 최적 배치·구매/비용 최적화·프로젝트 간 자재 재고 풀·여러 원본 파일 날짜 일괄 채택은 별도 범위다.
