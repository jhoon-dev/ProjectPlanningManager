# XER 원본·현재 원장 자동 병합

2026-11-07 사용자 지정 후속 증분이다. 가져온 [원본 스냅샷](xer-financial-snapshots.md) 또는 최신 [집계 정정](xer-aggregate-editing.md)을 기준으로 현재 날짜 원장을 대조한다. 현재 실제·원가 기록과 누계 AC를 그대로 유지하고, 병합 집계와 연결 근거만 새 이력으로 저장한다.

## XFM-01 자동 병합 범위

**파일 → XER 원본·현재 원장 병합…**에서 분석한다. 이름·계획·상태일 변경 때문에 이전 집계의 내용 지문이 달라졌어도 같은 ID의 작업/자원/배정과 현재 원장을 대조한다. 현재 이름·상태일·작업별 최신 AC를 채택하고 신규 작업/자원/배정도 현재 문서의 ID로 연결한다. 이름이 비슷하다는 이유로 다른 ID를 연결하지 않는다.

원본/최신 정정에서 이미 날짜 배분한 기간은 현재 날짜 원장의 최신 공수·원가로 재구성한다. 동일 키의 정정은 기존 값에 더하지 않는다. 명시 미보고 철회는 0으로 확정하지 않으며 이전 기록은 남는다. 기존 날짜 기록이 완전히 사라졌다면 미보고로 추정하지 않고 충돌로 판정한다. 겹치지 않는 새 날짜 기록은 일 단위 기간으로 추가한다.

날짜 없는 원본 기간은 기본적으로 그대로 남는다. 새 날짜 명세가 그 기간 밖에 있으면 누계 안의 미배분 잔량을 명세화한 것으로 연결한다. 배정 정규/초과근무 누계를 날짜 합계만큼 다시 더하지 않는다. 누계가 충분하면 그대로 두며 부족한 누계는 자동으로 늘리거나 정규/초과근무로 분류하지 않는다.

## XFM-02 모호한 기간과 누계 구분

날짜 없는 원본 기간과 현재 날짜 명세가 겹치면 같은 금액의 포함 명세인지 별도 실적인지 추정할 수 없어 제출을 차단한다. 검토 표에서 원본 기간 공수/원가와 현재 날짜 합계를 비교하고 **현재 원장으로 교체**를 선택한 뒤 다시 분석한다. 선택한 기간의 집계 공수/경비를 현재 날짜 명세로 교체한다. 원래 총액과 기간은 원본·이전 이력에 보존한다. 선택하지 않은 모호한 기간은 미해결 상태로 남는다.

날짜 명세가 없는 원본 기간도 기본 유지/선택 교체를 검토할 수 있다. 선택하면 해당 기간의 공수/원가 명세를 비운다. 원본 누계는 별도 값이므로 자동으로 줄이지 않는다. 현재 AC 정정으로 원래 집계와 모순이 생겼다면 기간 선택과 배정 누계를 함께 확인한다.

날짜 공수/원가가 원본 누계를 초과하거나 새 배정에 누계가 없으면 **정규·초과 누계 구분** 탭에서 값을 명시한다. 공수는 h 또는 정확한 정수 u(6000u=1h), 금액은 표시 통화의 최소 단위다. 빈칸은 미보고, 0은 명시 0이다. 알려진 날짜 합계가 알려진 배정 누계 이하여야 한다. 현재 AC는 이 창에서 바꾸지 않는다. 자원 누계+경비 명세가 현재 AC를 초과하거나 필요한 AC가 미정이면 기간/누계 구분 또는 기존 원가 입력에서 현재 AC를 정정하고 다시 분석한다.

삭제된 원본 작업/자원·해제된 배정, 현재 날짜 기록의 배정 누락, 인력/장비 종류 변경·통화 변경, 원본 이전으로 이동한 상태일은 자동으로 해석하지 않는다. 기존 ID의 연결/단위/상태일을 복원하거나 별도 전환을 수행해야 한다. **선택 초기화**는 검토 초안만 초기화한다.

## XFM-03 현재 원장·AC 불변과 대사

병합은 `PeriodActualEntry`, `CostEntry`, ProgressEntry, 계획/진척·기준선을 새로 쓰거나 수정하지 않는다. 새 병합 이력이 현재 원장의 최신 기록 ID를 참조한다. 반복 병합해도 원가/공수 원장 행 수나 누계가 늘지 않는다. 내부 EVM은 기존 누계 AC·물리 진척만 사용한다.

예제 원본은 배정 누계22500u·11046센트, 작업 AC12280센트다. 현재 원장에 새 날짜 자원1800u·500센트와 직접비700센트를 기존 AC 안에서 입력했다면 native 날짜 원가는4534센트, 미배분7746센트로 유지한다. 병합 재무기간의 자원 공수21300u·원가10546센트, 경비1234센트는 원본 누계 안의 명세다. 정규19500u+초과3000u와 배정 누계11046센트를 그대로 두므로 공수1200u·자원 원가500센트는 여전히 기간 미지정이다.

외부 TASKFIN의 비용 요약·BCWP/BCWS는 그대로 별도 참조다. 원본 외부 EV 구간 안에 현재 날짜 경비를 연결할 때는 서로 다른 차원으로 보존한다. 같은 작업의 외부 요약끼리 또는 경비끼리 겹치는 기간은 여전히 거절한다. 외부 요약과 경비가 같은 정확한 구간이면 XER 내보내기에서 하나의 TASKFIN 행으로 합쳐 기본 키 중복을 방지한다.

## XFM-04 검토와 원자적 제출

작성자·병합 사유를 입력하고 **병합 분석·미리보기**를 실행한다. worker가 자동 연결·충돌·누계 구분과 원가 대사를 계산한다. 검토, 정규/초과 누계, 원가 대사, 연결할 날짜 원장을 확인하고 **검증된 병합 제출**로 반영한다. 입력 변경 후에는 다시 분석해야 한다. 미해결 충돌·검증 실패에는 제출할 수 없다.

취소/닫기·읽기 전용·권한 회수·문서 ID/revision/session 교체는 미리보기를 반영하지 않는다. 병합 시점의 모든 알려진 날짜 기록을 빠짐없이 연결하고, 각 ID가 그 상태일·제출 revision 이전의 최신 기록인지 검사한다. 저장된 병합 집계의 작업 AC도 그 시점의 native 누계 보고와 대조한다. 이후 정정이 생겨도 과거 병합의 기준과 참조를 바꾸지 않는다.

병합 제출은 불변 이력이며 일반 undo로 제거하지 않는다. 이후 계획 편집 undo는 원본·병합/정정 이력을 유지한다. 병합 뒤에는 최신 집계와 현재 문서가 일치하므로 기존 집계 편집·날짜별 배분을 이어서 사용할 수 있다. 이후 새로운 원장 변경이 생기면 다시 병합 분석한다.

## XFM-05 저장·외부 교환과 한도

병합 이력 또는 외부 요약/날짜 경비의 분리 구간이 있는 문서는 조건부 **schema27**이다. 원본만 있으면25, 일반 정정만 있으면26, 둘 다 없으면 기존9~24 writer를 유지한다. 해당 기능이 없는 구 envelope와 미래31을 거절한다. 저장·복구·독립 사본에 원본, 병합 당시 전체 집계·날짜 연결, 기준 투영 SHA256·기간 교체/누계 선택, 작성자/사유/UTC/원본 문서/revision을 보존한다. 지문은 상태/손상 대조용이며 제작자 인증 서명이 아니다.

기존 원본10,000작업/자원·100,000배정/기간, 이력128건·정정 스냅샷 총300,000행, native64MiB·원장50,000기록 한도를 유지한다. 병합은 현재 상태일의 알려진 날짜 원장1,000행까지 지원한다. 원가/공수의 합계·정밀도·중복·참조/유형과 미보고/0을 검사한다. 가상 표와 검색으로 누계·충돌 목록을 조회한다.

문서와 일치하는 병합 집계는 XER로 재내보낸다. conversion.json.actualCosts의 `financialMergeCount`, `financialAdjustmentCount`, `preservedFinancials`로 이력 수와 재사용 판정을 확인한다. 병합/정정 전체 이력과 원래 작성자는 source.ppm에 남으며, XER 재가져오기는 새 관측 스냅샷이다. XML은 전용 재무 집계/이력을 투영하지 않고 source.ppm 보존 진단을 따른다.

## XFM-06 검증·후속

`xer_financial_merge_contract`는 비겹침 잔량 연결, 기존 배분 정정/철회, 명시 기간/초과근무·AC 선택, 새 ID/0, 원본·현재 원장/일정 불변, 반복/후속 편집, 한도·누락·단위/통화/상태일, 권한/session/stale/취소/읽기 전용, schema27·복구/사본, TASKFIN 분리/동일 키 병합과 native UI를 검사한다. `scripts/verify-xer-merge.py`는 native 전체 입력/원장 동일성·SHA256·상태일/revision 참조 oracle, 별도 TSV/Decimal과 MPXJ16.10.0 strict reader로 판독한다. [전체 회귀 실행 증거](validation/xer-merge-2026-11-07/README.md)를 남긴다.

2026-11-08 [새 XER 버전·삭제 ID 재연결](xer-source-relink.md)은 별도 파일/프로젝트 선택·명시 연결표를 검증한 뒤 이 병합 검토를 사용한다. 같은 ID·유일한 동일 이름은 후보이며 사용자의 확인이 필요하다. 기존 병합만 있는 문서는27, 재연결 이력이 있으면28로 저장한다. [native 기간 EVM](native-period-evm.md)은 native 보고 누계로 기간 지표를 계산한다. [외부 EV/PV native 채택](external-xer-evm-adoption.md)은 별도 명시 이력으로 지원한다. 새 원본 일정의 자동 채택, 관측 원장 ID 이관, 통화/인력-장비 단위 전환, 관측하지 않은 날짜 생성, MPP reader와 실제 Oracle P6 재계산/재저장은 후속 범위다.
