# 평준화 결과 채택과 해제 (GAP-06)

2026-11-03 사용자의 다음 단계 개발 요청에 따른 native 증분이다. [자원 비교](resources-leveling.md)의 직렬 휴리스틱을 현재 일정으로 채택하고, 해제·실행 취소·저장·복구와 표/간트/Usage/원가/보고서에 연결한다. 후속 [자원 슬롯 순서 고정 여유](leveling-float.md)를 지원하며 실제 MSP/P6 재계산 왕복은 별도 검증 대상이다.

## 사용 흐름

자원 부하·평준화 비교에서 현재 입력 또는 저장된 A를 계산하고, 완료일·작업 날짜·과부하·진단을 검토한다. 사유를 입력한 뒤 **A 결과를 현재 일정으로 채택**한다. A의 일정 입력이 현재 입력과 다르면 직접 채택할 수 없다. B는 비교용이며 채택하려면 A로 선택해 다시 계산한다. **채택 해제**는 논리 일정으로 돌아간다. 채택/해제는 하나의 편집이며 undo/redo로 복원한다.

상태일이 없으면 계획을, 상태일이 있으면 잔여 예측을 채택한다. 잔여 채택은 실제 시작/완료와 불변 실적을 보존하고, 현재 계획·승인 기준선을 바꾸지 않는다. 읽기 전용에서는 비교만 가능하다. 계산/제출 취소와 문서 재열기·변경에 따른 오래된 결과는 적용하지 않는다.

## 계산·무효화 계약

- `PlanInput.planLeveling` 또는 `Project.remainingLeveling`에 우선순위·탐색 근무일·정책 버전·채택 UTC·사유·원본 문서 ID/revision을 보관한다. 둘을 동시에 설정하지 않는다. 저장된 날짜를 입력 제약으로 덧붙이지 않고, 같은 입력과 기록된 결정적 정책을 재생해 실행 구간을 계산한다.
- 지원 정책, 1~5200 기본 달력 근무일, 세 우선순위와 필수 사유를 검증한다. 문서/session/revision이 일치하는 요청만 worker에서 재계산하고 GUI에서 원자적으로 반영한다. 일정과 결과 자원 부하가 모두 Valid인 안만 채택한다. 미정 용량·충돌·기간 내 배치 불가·취소 결과를 적용하지 않는다.
- 채택 설정을 제외한 `PlanInput`, 상태일 또는 실적이 바뀌면 채택을 해제한다. 따라서 이름·분류·WBS·단가 등 PlanInput 편집도 보수적으로 해제한다. 누적 실제원가·기간별 관측 사실의 추가, 보기 저장, 기준선/시나리오 추가는 이 입력을 바꾸지 않아 채택을 유지한다. 해당 편집 undo는 입력과 채택 설정을 함께 복원한다.
- 비교는 채택을 제거한 논리 일정부터 시작한다. 채택된 일정에 다시 같은 지연을 중첩하지 않는다. 기준선은 계획 채택 설정을 동결한다. 새 기준선은 `jobs-adopted-leveling-1.8`, 기존 `1.0`/`1.1`/`1.2`/`1.3`/`1.4`/`1.5`/`1.6`/`1.7`은 당시의 미산정/전체 구간/실행 창 유지/64개 제한/이동 가능128개 제한/후보 결합·인증/안전한 상한·이웃 전파·인증 공유/비단조 필수 부하·연쇄 전파 결과로 별도 검산한다.
- 채택 일정의 총/자유여유·임계·driving은 [엔진별 자원 여유 계산 기준](leveling-float.md)으로 후진 계산한다. 교차 분할과 구간 소멸·재생성은 실제 자원 수요와 작업별 재배치 증인으로 계산한다. 순서 정책·탐색 한도는 상세 계약을 따르며, 인증하지 못하면 날짜를 유지하고 미산정 사유를 표시한다. 채택 중 간트 날짜 드래그는 비활성화하며 표의 입력 편집 시 채택을 해제한다.

채택 설정은 일반 계획 편집의 출처 정보다. 2026-11-05 후속 [불변 결정 원장](leveling-decisions.md)은 채택·해제·무효화와 undo/redo를 별도 기록한다. 설정은 되돌려도 원장은 보존하고 새 결정을 추가한다. 승인 기준선·실적·실제원가·기간 실적의 기존 불변 경계는 유지한다. 여유 내 한정·자동 분할·고급 우선순위·프로젝트 간 공유 평준화는 후속이다.

## 일관성·파일

계획/예측 계산의 동일 실행 구간을 작업 표·간트·Usage·유효일별 자원 원가·비교·보고서가 사용한다. 표준/Usage XLSX/PDF는 채택 모드·정책·우선순위·범위·사유·시각과 자원 순서 계산 기준을 기록한다. 표준 보고서는 여유·임계와 계산 불가 사유를 제공한다. 날짜가 달라지면 유효일별 단가에 따라 계획/잔여 원가도 달라질 수 있다. 누계 실제원가는 재평가하지 않는다. 잔여 채택은 Usage의 잔여 배정원가에 반영하며 EVM의 EAC/ETC는 기존 선택 공식으로 계산한다.

현재 채택 또는 기준선/시나리오의 계획 채택이 있으면 native writer는 **schema 12**를 쓴다. 없으면 종전 조건에 따라 periodActuals 11 / 분류 10 / 일반 9를 유지한다. schema 1~12를 읽고 복구 envelope 1의 내부 projectSchema 12도 지원한다. 잘못된 정책·숫자·알 수 없는 필드를 거절한다. 과거 검증 폴더의 source hash는 당시 코드 증거로 보존한다.

XML/XER 기간 기반 계획 내보내기는 채택 정책/실행 날짜를 보존하지 못한다는 손실 진단을 제공하며, 교환 패키지의 `source.ppm`에 native 설정을 보존한다. 실제 외부 제품 결과로 간주하지 않는다.

## 검증

`leveling_selection_contract`는 공유 자원 100%에 독립 8h 작업 A/B/C의 논리 11-02 완료→채택 11-04 완료, 유효 단가 1→2에 따른 계획 원가 40, 기준선 동결·Usage·채택 해제·undo·입력 무효화·잔여 실제 날짜 보존·schema12·복구·취소·읽기 전용·session 경계를 검사한다. `leveling_selection_ui`는 A 입력 불일치 차단, 제출/취소, 표/간트 표시, 해제·재열기와 출력 파일을 검사한다. Windows Release 전체 CTest 73개(303.03초)와 독립 출력 검사를 통과했다. [검증 기록](validation/leveling-adoption-2026-11-03/README.md)에 최종 소스 해시·원시 로그·화면을 보존한다.

GAP-05는 표준 설치 경로와 등록 정보에서 MS Project/P6 실행 환경을 찾지 못해 이번 세션에서 미실행이다. macOS/Linux·실제 제품 왕복·실제 데스크톱 조작·sanitizer/libFuzzer coverage·CI/스토어 제출을 이번 로컬 검증으로 대체하지 않는다.

진척 정책과 평준화의 조합을 지원한다. 비교 전 정책의 활성 관계를 적용하고 자원 배치를 수행한다. 정책을 바꾸거나 해제하면 현재 평준화도 해제한다. 평준화만 해제하면 정책을 유지한다. [조합·시나리오/schema14 계약](progress-policy-leveling.md).

채택 일정의 총/자유여유·임계·driving은 [엔진별 자원 여유 계약](leveling-float.md)을 따른다. 새 계획 기준선은 adopted-leveling 엔진1.8이며 기존1.0~1.7 기준선은 과거 결과로 재검산한다. 날짜/원가와 원본 입력은 유지한다.
