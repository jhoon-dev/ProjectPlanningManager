# XER 일괄 작업공간과 작업 코드 교환

2026-11-05. native Project schema18 / Workspace schema1 유지. 일괄 패키지 계약은 `jobs-xer-workspace-v1`이다.

파일 메뉴의 **XER 일괄 작업공간 가져오기…**에서 여러 XER을 선택하고 인코딩과 프로젝트 체크 목록을 확인한다. UTF-8(BOM 허용) 또는 Windows-1252를 명시하며 UI에서 선택한 인코딩은 모든 선택 파일에 적용한다. 읽은 원본 바이트를 선택·미리보기·저장 단계에서 다시 읽지 않는다. 이름과 프로젝트 ID를 함께 표시하며 기본 선택은 없다. 외부 수신/송신 관계가 있는 프로젝트는 선택할 수 없다.

**XER 일괄 작업공간 내보내기…**에는 현재 열린 프로젝트를 명시적으로 나열한다. 닫힌 프로젝트는 포함하지 않는다고 안내한다. 선택한 프로젝트의 현재 미저장 입력을 포함한 불변 사본을 사용하며 원본 파일과 dirty/undo 상태를 변경하지 않는다. 다른 프로젝트 창이나 공유 설정이 바뀌면 게시 직전 세대·세션·revision 검사로 오래된 사본 게시를 거절한다.

## 패키지

가져오기 폴더에는 다음이 있다.

- `workspace.ppmworkspace`: 상대 경로로 프로젝트를 참조하는 새 native 작업공간.
- `projects/001/project.ppm`, `projects/001/conversion.json`: 선택 순서의 프로젝트와 변환 보고서. 프로젝트 이름을 파일 경로로 사용하지 않는다.
- `originals/001.xer`: 선택하지 않은 프로젝트까지 포함한 전체 원본 바이트를 파일당 한 번 보관한다. 최상위 `conversion.json`에 원본 이름·인코딩·SHA-256·선택 ID와 생성 파일 경로를 기록한다.

내보내기 폴더에는 `workspace.ppmworkspace`, `workspace.xer`, `projects/001/source.ppm`, `projects/001/project.xer`, 프로젝트별 및 최상위 `conversion.json`이 있다. 모든 현재 native 데이터는 `source.ppm`에 보존한다. 통합 XER은 같은 통화의 프로젝트에 한하며 통화가 다르면 전체 내보내기를 거절한다. 환율을 추정하지 않는다. 부분 집합을 내보낼 때 공유 자원 연결도 선택한 프로젝트로 제한한다.

프로젝트별 XER과 통합 XER의 ID는 다를 수 있다. 보고서의 `mapping`은 프로젝트별 파일, `combinedMapping`과 `combinedProjectId`는 통합 파일을 가리킨다. PROJECT·SCHEDOPTIONS·CALENDAR·PROJWBS·TASK·TASKPRED·RSRC·RSRCRATE·TASKRSRC·ACTVTYPE·ACTVCODE의 숫자 ID와 모든 해당 외래 키를 다시 배정한다. 통합 파일의 전체 한도와 각 프로젝트를 다시 파싱해 검증한다. 기존 P6 프로젝트를 갱신하는 동일성 계약은 아니다.

## 원자성과 복구

기존 폴더는 덮어쓰지 않는다. 같은 상위 폴더의 임시 디렉터리에 모든 native 파일·XER·보고서를 기록하고 바이트와 native 객체를 다시 읽어 검증한다. 상대 참조 작업공간도 검증한 뒤 최종 취소·변경 검사를 거쳐 디렉터리 이름을 한 번 바꾼다. 실패·취소·대상 경합은 임시 폴더를 정리하고 기존 문서와 대상 파일을 보존한다. 최종 이름 변경이 성공하면 게시 완료이며 이후 취소로 지우지 않는다.

가져온 폴더를 저장한 뒤 기존 작업공간의 트랜잭션 열기 경로로 모든 프로젝트와 잠금을 준비한다. 이미 열려 있던 독립 문서는 유지한다. 작업공간 열기를 취소하거나 잠금 때문에 열지 못해도 게시 폴더는 완전한 결과로 남아 나중에 `workspace.ppmworkspace`를 열 수 있다. 폴더 전체를 이동해도 내부 상대 참조를 유지한다. 개별 `.ppm`만 옮기면 원본·보고서를 함께 복제하지 않는다.

원본은 최대100개, 합계64MiB, 선택 프로젝트는 최대100개다. 각 XER의 기존16MiB/행·셀·테이블 한도를 유지하며 통합 내보내기도 이 한도를 적용한다. 동일 바이트 원본의 중복 선택과 중복 프로젝트 ID 선택은 거절한다. 한 프로젝트라도 변환에 실패하면 일괄 결과를 게시하지 않는다.

## 달력과 자원

원본 안의 숫자 ID와 원본 SHA-256을 함께 식별자로 사용한다. 서로 다른 XER의 같은 ID나 같은 이름을 병합하지 않는다. 전역/상속 달력은 각 프로젝트에 필요한 달력과 부모를 해석해 복사한다. 다른 프로젝트 소유 달력 참조는 기존 정책대로 차단한다.

같은 원본 자원이 여러 선택 프로젝트에 쓰이고 이름·종류·가용량·예외·해석된 달력이 모두 일치하면 native 공유 자원으로 연결한다. 일치하지 않으면 로컬 자원을 유지하고 보고서에 연결하지 않은 이유를 남긴다. 가용량 미정은 미정으로 유지한다. 통합 XER의 자원·달력 ID는 프로젝트별로 분리하며, 명시적인 native 공유 자원 카탈로그와 연결은 작업공간 파일에 보존한다고 미리보기에서 안내한다.

## 작업 코드

ACTVTYPE의 코드 종류, ACTVCODE의 `short_name`·부모 계층, TASKACTV의 프로젝트·작업·종류·값 참조를 가져오고 내보낸다. 사전과 배정은 기존 native 작업 코드에 연결되어 그룹·필터·저장·undo 경로를 그대로 사용한다. 내보낼 때 프로젝트 범위(`AS_Project`) 사전을 생성한다. 선택 가져오기와 통합 내보내기 모두 프로젝트 소유 사전과 배정 범위를 분리한다.

종류64개, 값 합계10,000개, 계층16단계 등 기존 native 분류 한도를 유지한다. 중복 ID/배정, 없는 종류·값·작업, 다른 종류의 값, 부모 누락·순환은 차단한다. 이름이 다른 사전 간에 겹치는 값 ID도 올바르게 내보낸다. 전역 공유 범위, 별도 설명·색상·정렬/보안 속성 등 native에 없는 메타데이터는 원본에 보존하고 진단한다. EPS 소유 참조 등 native에 투영할 수 없는 범위는 차단될 수 있다.

필드 의미는 [Oracle P6 v26 XER Import/Export Data Map Guide, ACTVCODE·ACTVTYPE·TASKACTV](https://docs.oracle.com/cd/G48897_01/English/Mapping_and_Schema/xer_import_export_data_map_project/xer_import_export_data_map_project.pdf)를 확인했다. 이 문서 대조와 독립 parser 검증은 P6의 실제 재계산·재저장 검증이 아니다.

실적·기간 원가 원장, 단가 슬롯/다중 통화, UDF, MPP reader/라이선스·배포, 프로젝트 간 링크와 통합 일정은 후속이다. 외부 관계는 양 끝 프로젝트를 모두 선택해도 차단하며 조용히 삭제하지 않는다. 현재 native 작업공간에는 이 관계를 계산하는 모델이 없다.
