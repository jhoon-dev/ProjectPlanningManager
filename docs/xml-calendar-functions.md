# XML 계산식의 근무 달력 함수

2026-11-13 후속: [PPM 시간대 변환](xml-formula-timezones.md)을 명시 수식으로 지원한다. 기존 근무 달력 함수는 시간대 없는 민간 시각의 의미를 유지한다. 필요하면 먼저 시간대를 변환하며, 달력의 근무 분이 DST를 포함한 실제 경과 시간으로 자동 바뀌지는 않는다.

2026-11-11 · XMLC-01~05.

`ProjDateAdd`, `ProjDateSub`, `ProjDateDiff`를 실행한다. 함수 이름은 ASCII 대소문자를 구분하지 않는다. Microsoft의 [사용자 필드 함수 문서](https://support.microsoft.com/en-au/project/project-functions-for-custom-fields-in-project-desktop)에 제시된 이름·인수와 근무 분 의미를 기준으로 구현한 지원 부분이다. 전체 Project/VBA 실행 동등성은 별도 검증 대상이다.

| 함수 | 결과 |
|---|---|
| `ProjDateAdd(date, duration[, calendar])` | 근무 기간을 더한 일시 |
| `ProjDateSub(date, duration[, calendar])` | 근무 기간을 뺀 일시 |
| `ProjDateDiff(date1, date2[, calendar])` | 두 일시 사이의 부호 있는 근무 분 숫자 |

```text
ProjDateDiff([Start], [Finish])
ProjDateAdd([Finish], "1d")
ProjDateSub([Start], "2h", "오전")
```

표준 달력의 수요일09~18시는 점심을 제외하면480분이다. 기존 `DateDiff("n",...)`는540분이다. 금요일18시에 근무480분을 더하면 다음 근무일18시가 되며 휴일도 건너뛴다. 기존 `DateAdd`/`DateDiff`는 일반 날짜 계산을 유지한다.

## 값과 기간

날짜는 기존 ISO 일시 값·리터럴·ISO 문자열을 받는다. 초·최대 소수6자리 초를 보존하며 시간대 변환은 하지 않는다. 기간의 숫자는 분이다. 문자열은 `m/h/d/w` 또는 `em/eh/ed/ew`와 선택적인 추정 표시 `?`를 받는다. 1h=60분, 근무1d=480분·1w=2400분이며 달력의 하루 길이로 환산 단위를 바꾸지 않는다. 경과1ed=1440분·1ew=10080분이다. typed Duration/ProjDurValue의 근무·경과 구분도 반영한다. 지역 언어 단위·월 단위·일반 Variant 숫자 날짜는 추측하지 않는다.

음수 기간과 역순 날짜를 지원한다. 0기간은 비근무 시각도 그대로 보존한다. 경과 기간은 달력상 시각으로 더하고 빼며, 지정한 달력 이름의 유효성은 검사한다. 근무 분 결과는 소수6자리로 반올림하며 중간값은0에서 멀어지는 방향이다. 날짜 차이/이동은 스케줄러와 같은7,320일 범위로 제한하고 범위를 벗어나거나 필요한 근무 시간이 없으면 오류를 표시한다. 프로젝트 시작일 이전 날짜도 이 범위 안에서 계산한다.

## 달력 선택

생략하거나 빈 문자열이면 **식을 정의한 필드의 범위**를 따른다. 배정 식에서 프로젝트/자원 필드를 참조해도 각 필드의 기본 달력은 유지한다.

| 범위 | 기본 달력 |
|---|---|
| 작업 | 해당 작업의 명시 달력, 없으면 PPM 표준 달력과 프로젝트 휴일 |
| 자원 | 해당 자원의 명시 달력, 없으면 PPM 표준 달력과 프로젝트 휴일 |
| 배정 | 소유 작업의 달력 |
| 프로젝트·WBS/필터/자원 요약 | XML에서 보존한 프로젝트 달력, 없으면 PPM 표준 달력과 프로젝트 휴일 |

명시 달력은 이름이 정확히 일치해야 한다. 없는 이름이나 중복 이름은 오류이며 다른 달력으로 대체하지 않는다. `Standard`/`PPM standard`는 실제 동일 이름이 있으면 해당 달력을 사용한다. `Standard`만 없으면 유일한 `PPM standard`를 사용하며 둘 다 없으면 PPM 표준 달력을 사용한다. XML 재내보내기는 암묵 표준 달력의 이름 충돌을 피한다. 명시 이름 문자열은 필드의 안정 ID 바인딩과 다르므로 달력 이름을 바꾸면 해당 식도 갱신해야 한다.

커스텀 달력의 휴일은 프로젝트 표준 휴일을 대체하는 기존 스케줄러 정책을 따른다. 주간 근무 구간·자정 경계·주말·휴일을 계산하며 작업 분할, 자원 가용량/예외·배정 구간·평준화 순서를 달력으로 간주하지 않는다. 일정 자체에 반영된 이런 정책은 `[Start]`/`[Finish]` 날짜로 들어온다.

## 저장·교환과 화면

새 함수 또는 `PlanInput.xmlFormulaCalendarId`가 현재·동결/시나리오·채택·통화/ID 전후 사본에 있으면 조건부 schema46이다. 이전 데이터의 최소 writer를 유지하고 schema45 이하에서 새 의미를 거절한다. XML 가져오기는 원본 프로젝트 달력 ID를 프로젝트/요약 수식의 기본값으로 보존한다. 작업·자원은 기존의 명시 배정 달력을 사용하며 새 객체의 PPM 달력 정책을 바꾸지 않는다. 내보내기는 해당 프로젝트 달력 연결을 XML CalendarUID로 기록한다. 이 메타데이터와 식·원본 스냅샷은 native 저장/복구에 포함된다.

계산기는 도메인 내부의 결정적 달력 누적량으로 계산하며 스케줄러를 재귀 호출하지 않는다. 이름/요일/구간/휴일·객체별 기본 달력·프로젝트 달력 연결이 결과 캐시 키에 포함된다. 취소와 오류/미설정을 전파하고 원본 값으로 대체하지 않는다. 리터럴 날짜 계산은 일정 결과가 없어도 동작한다. `[Start]`/`[Finish]`와 함께 사용하면 [계획/예측 일정 참조 계약](xml-schedule-references.md)을 따른다.

XML 계산식 창에서 함수·달력을 골라 식을 삽입하고 백그라운드 미리보기를 확인한다. 저장·제거·undo·읽기 전용/stale 검사, 요약/roll-down·그룹/필터·보고서의 typed 결과는 기존 기능과 연결된다. XML/XER의 정적 값은 계획, 보고서는 활성 계획/예측을 사용한다. 실제 외부 제품에서 재계산한 결과는 검증하지 않았다.
