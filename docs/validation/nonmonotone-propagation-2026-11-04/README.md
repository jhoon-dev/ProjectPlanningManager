## 계산과 보존

현재 선택 엔진 `jobs-adopted-leveling-1.7`은 [NPROP-01~04](../../nonmonotone-propagation.md)를 구현한다. 실제 후보 구간을 같은 시각의 사건 합산으로 정규화하고 점별 최소 수요를 구한다. 다른 작업의 필수 부하 합과 충돌하는 후보를 제거하며 자신의 하한은 빼서 중복 계산하지 않는다. 내부 공백·자원 수요 소멸은0이다. 공통 하한이 모두0이면 추가 전역 부하 검사를 생략한다.

분기에서는 살아 있는 후보만으로 논리/자원 끝점 지지를 다시 계산하고 제외를 이웃 큐로 전파한다. 선택/고정 배경과 미선택 작업의 필수 부하를 합산한 임시 시간축으로 후보를 줄이고, 끝점/수요의 고정점까지 반복한다. 제외는 가역 마스크로 되돌린다. 작은 단위는 후보 총합32개 기준으로 추가 분기 비용을 제한한다. 실제 비단조 수요를 이진 탐색하거나 세 작업의 합산을 쌍별 용량 판정으로 대체하지 않는다. 최종 native 전체 자원 인증과1.6의 정확한 배치 인증 공유를 유지한다. 추가 전파는50,000판정 또는 전체1,900,000판정에서 기존 정확한 탐색으로 전환한다. 전역 제거는 한 작업의 검사 목록이 완성된 뒤 반영하고 분기 제외는 가역 기록으로 보존하므로 중단 시 부분 배열을 남기지 않는다. 이 상한만으로 미산정 처리하지 않는다.

현재 날짜·실적·원장·원본 관계·총/자유여유의 수학적 정책 resource-repartition-float-v3를 유지한다. 총여유는 작업별 가능한 재배치이며 개별 최후 날짜를 동시에 적용하는 공통 일정이 아니다. 새 기준선은1.7, 기존1.0~1.6은 당시 엔진으로 재현한다. `selected.ppm`은 기존1.6/신규1.7의 동일 승인 수치와 재열기/재검산을 확인한 schema12 파일이다. 입력 schema9~14와 불변 근거 창은 유지하며 새 입력 필드는 없다.

## 수치와 독립 검산

달력 공백 사례는 작업 달력이09:00부터8분 또는120분이며 R은09:02~09:04에 쉬는 모델이다. A/B는 시작 고정·전체 기간·각40% 부하이며 C들은1분·각40%다. 현재 C는09:02에 자원 수요 없이 실행되고09:03까지 늦출 수 있어 총/자유여유가1분이다.09:04 이후에는 A+B+C=120%로 불가능하다. 각 쌍은80%여서 합산 검사 없이는 이 충돌을 찾지 못한다.2/32/96개의 C에서 각각8/3,712/11,136후보를 사전에 제거한다. A/B/H의 여유는0이다.

공수 사례는 R0=50%(하루0~2/4~6분), R1=100%(하루8분 전체), 작업 공수151단위분이다. 마지막1분의 정수 배분으로 특정 자원의 수요가 없어지거나1%만 남는 경우가 있다. 작은8분 모델의 A/B/C 총여유는4/4/5, 자유여유0/0/5분이다.16분 모델은12/12/13과0/0/13분이다. 후자는 분기 끝점 지지 제외42회를 실행한다. 다일 용량 모델은 하루4분·10일, 화요일/마지막 금요일50%·첫 수요일0%이며 총36/38/36, 자유0/38/36분이다. 분기 지지62회·부하10회 제외를 실행하고 되돌린다.

독립 Python verifier는 작은 허용 배치 **4/55/673/17,366개**를 원시 시간축에서 전수 열거한다. C++ 탐색을 호출하지 않고 **145개 증인 / 163개 날짜 참조**를 재구성해 여유 최대값·현재 하한·종료일·순서·실제 합산과 공수/수요 소멸을 대조한다. 기존480분 교차 분할 사례에서는 추가 전파 상한과 기존 탐색 전환을 실제 실행하고1.6의 A660/B540분 수치와 TaskSchedule 전체가 일치함을 확인한다. 전환/작업량 계수도 보존한다. 별도 C++ 원시 합산 oracle은 무작위 프로파일200개/9,600좌표에서 중첩·공백·단위 변화의 점별 최소를 검사한다. 두 엔진의 TaskSchedule 전체 날짜/수치/임계를 대조하며, 분기 복구·반복 계산·잔여 공수의 실제 시작 고정·미정 용량의 부분 증인 차단·취소를 검사한다.
