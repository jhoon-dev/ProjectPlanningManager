# UX-W02 기간 입력·표시 검증

2026-11-17 · Windows11 / Qt6.8.3 / MinGW13.1 Release.
[사용법과 단위 계약](../../duration-input.md) · [최초 UX 점검](../../planning/21-weekly-update-ux-review.md).

## 변경 범위

계획 표, 공수·유형·분할 창의 기간, 실적 창의 실제 소요/잔여와 보고 이력을 같은 규칙으로 표시한다.
숫자 기본값은 일이며 d/h/m과 일/시간/분을 받는다. 작업 달력의 하루 근무 구간 합으로 환산하고
정수 분에 정확히 대응하는 입력만 허용한다. 표시를 반올림해 다시 저장하지 않는다.
기본480분과 사용자420분/1440분 등 서로 다른 하루 길이를 검사했다.
작업 선택 시 달력 이름·1d 환산 기준이 보이며, 경과일·공수와 구분한다.
공수와 선행 지연의 기존 의미, 엔진과 저장 schema는 변경하지 않았다.

입력 단위 변경을 기존 사용자에게 숨기지 않도록 주 창·도움말·편집창과 사용 문서에
**숫자=일, 기존 시간 숫자는 h를 붙여 입력**한다고 명시한다. 기존 파일의 정수 분은 그대로다.
소수 분 입력의 오류가 실적 창 아래에 숨어 있는 것도 발견해 공통 오류 표시 도우미로
설명이 보이도록 이동시켰고 실제 화면에서 재검사했다.

## 자동 검사

- `regression-final.log`: 최종 소스의 관련 CTest **19/19 통과**. 기간 단위·표시·복사/붙여넣기·
  대기 편집 취소·정렬·공수 역산·실적·달력·undo/redo·저장/재열기·화면 배치·기존 편집 성능 검사다.
- `units.txt`: 새 DurationInputTests의 실제 검사3개와 초기화/정리 포함5개 통과.
  기본/7h/24h 환산, 한글/영문 단위, 한도·overflow·소수 분 거절, 6개 하루 길이의 정확한
  표시 왕복, 7시간 달력의 숫자2→840분·11-10 17:00 계획 완료를 검사한다.
  같은14h/840m/2d 입력 불변, 오류 설명 가시성, 실제1d/잔여7h→각420분과 저장/재열기도 포함한다.
- `native-units.txt`: 위 검사 전체를 Windows 기본 렌더링에서도 실행해5개 통과했다.
- 기존 시간 기반 회귀 시나리오에는 `h`를 명시했다. 기존 계산 기간11분 같은 값은 계속 `11m`이며,
  공수 기준 계산 기간·미정·계획/예측 분리와 무변경 편집의 파일/공수/배정/이력 보존을 검사했다.
- `build-final.log`는 최종 빌드다. `build.log`, `build-layout.log`, `regression.log`,
  `layout-regression.log`는 구현 중간의 빌드/검사 기록이다.

Qt platform plugin 경로를 `.deps/Qt/6.8.3/mingw_64/plugins/platforms`로 지정했다.
전체 suite·macOS·OS DPI 변경·실제 PM 대상 사용성 시험은 이번 범위가 아니다.

## 실제 앱 조작

이전 합성 주간 갱신 파일 `weekly-prepared.ppm`의 사본을 새 빌드에서 열었다.
기준선1개·기존 보고3건을 보존하고 아래 입력은 모두 UI에서 수행했다. PNG를 판단 기준으로 삼았고
접근성 TXT는 보조 자료다. 01~07은 구현 중간 빌드, 08~21은 오류 가시성까지 보완한 최종 빌드다.

`plan-2d.ppm`과 `plan-equivalent.ppm`이 같고, `progress-applied.ppm`과
`progress-after-cancel.ppm`도 같다. 최종 `seven-hour-plan.ppm`/`review.ppm`의 시운전은840분,
하루 근무량은420분이다. 모든 사본에 최초 기준선이 그대로이며 정정 전 보고3건도 변경하지 않았다.
최종 보고는 실제960분·잔여720분이다. UI의 과거 보고 표시는 현재 작업 달력 기준이며 원본 분은
이력 셀 도움말에서 볼 수 있다. 해시와 확인 결과는 `manifest.json`에 기록한다.
7시간 달력을 배정한 사본은 기존 앱 정책대로 FS0에서 작업 달력 profile로 전환된다.
다른 작업의 빈 달력/관계 속성이 명시적으로 직렬화되는 차이도 이 기존 전환의 결과다.

이번 판정은 UX-W02와 작은 합성 사례의 기간 입력이다. 주간 갱신 전체 무도움 성공이나
MSP/P6 동등성, 전체 보고서/교환 파일의 일 단위 표시 통일을 선언하지 않는다.
