## 비용 판단과 보존

현재 엔진 `jobs-adopted-leveling-1.8`은 [COST-01~03](../../propagation-cost.md)을 구현한다. 후보·실행 구간·관계 끝점 방문의 순회 비용과 반복 탐색에서 피할 것으로 추정한 방문 수를 비교한다. 작은 입력의 추가 전역/분기 전파를 생략하고, 실제 후보 실패가 누적되면 활성화한다. 추가 판정 대비 제외 효과가 낮으면 새로운 실패가 쌓일 때까지 재시도를 늦춘다. 적용 여부는 실행 시간/OS 속도가 아닌 결정적인 입력 메타데이터와 탐색 사건으로 정한다.

W=min(2,000,000,C+3S+E), R=min(2,000,000,M×max(0,C−M))이며 M>1, R≥4max(1,W)일 때 최초 추가 순회를 적용한다. C는 이동 후보 수, S는 고정 작업을 포함한 후보 구간 수, E는 중복 관계를 제거한 끝점 후보 방문 수다. 실패 F≥max(64,W)이고 남은 예상 실패 (M−A)×ceil(F/(A+1))≥2max(1,W)일 때 활성화한다(A는 완료한 선택 작업 수). 이미 쓴 실패만으로 계산 후반에 활성화하지 않는다. 또한 한 번의 전파에 Q판정/X제외가 있을 때 Q>0·8X<Q이면 max(256,4W)개의 새로운 실패 전까지 재시도를 늦춘다. M≤4에서는 M(C−M)<4C≤4W로 최초 적용이 불가능하므로 S/E의 정밀 추정을 미룬다. 실패와 남은 예상 실패가 하한 C를 넘을 때만 정밀 W를 구하고 전체 조건을 다시 검사한다. 비용 추정은 실행 가능성의 근거나 실행 시간 보장이 아니다.

생략·지연·상한 전환 후에도 기존 정확한 탐색·관계/다중 작업 합산·native 전체 자원 인증을 유지한다. 가역 마스크는 필요하면 분기 도중 만들고 이전 조상의 복원 지점0을 처리한다. 완료한 안전한 제외만 유지하며 임시 부하를 공유 배경에 남기지 않는다.1.7의 추가 전파50,000판정/전체1,900,000판정에서 기존 탐색으로 전환하는 상한과 전체 예산도 유지한다.

현재 날짜·실적·원장·원본 관계·총/자유여유의 수학적 정책 resource-repartition-float-v3를 유지한다. 기존1.0~1.7 승인 기준선은 당시 경로로 재현하며 새 기준선은1.8이다. `selected.ppm`은 기존1.7/신규1.8의 동일 승인 수치와 재열기/재검산을 확인한 schema12 파일이다. 입력 schema9~14·불변 근거 창을 유지하고 비용/실패/재시도 상태를 파일에 저장하지 않는다. 기존 비단조 계약은1.7로 고정하고 공통 fixture만 추출했다.

## 적용/생략·정확성 검증

늦은 활성화 방지·달력 공백·151단위분 공수·다일 용량5사례는 추가 전파 판정0회로 계산한다. 큰96작업은 후보11,136개 제거를 유지한다. 6작업 사례는 뒤늦은 활성화를 생략한다.15작업 사례는 실패 관측 활성화·낮은 효과 지연·분기 도중 마스크 생성/복원을 실제 실행한다. 기존 분할 사례의 총 A660/B540, 자유 A660/B60분과 전체 TaskSchedule도 일치한다. 산식 경계·구간/관계 비용·포화·활성화/재시도 경계는 별도 원시 계약으로 검사한다.

독립 Python reader는 기존 원시 시간축 oracle을 재사용해 허용 배치4/55/673/17,366/64/32,768개와 분할155,761쌍을 전수 대조한다. C++ 탐색을 호출하지 않고 **138개 증인 / 400개 날짜 참조**를 재구성하여 최대 여유·하한·순서·완료 상한·수요 소멸·분수 공수와 실제 합산을 확인한다. 비용 진단은 실행 가능성 증명에 사용하지 않는다. 미정 가용량과 취소의 부분 증인 차단, native 체크섬/기준선 및 openpyxl3.1.5의1.8 출처·총/자유여유·새 진단 판독도 통과했다.
