## 변경과 보존

현재 선택 엔진 `jobs-adopted-leveling-1.6`은 [PROP-01~04](../../candidate-propagation.md)를 구현한다. 후보 생성 전 안전한 기간 수요의 끝점 상한을 논리 관계와 함께 전파하고, 이미 지지된 후보의 제거 순회를 생략한다. 큰 후보 집합에서는 선택 작업의 날짜로 이웃 후보를 제외하고 분기 실패 때 가역 마스크를 정확히 복원한다. 끝점 캐시는250,000항목 이내로 유지하고 초과 시 직접 판정한다. 실제 비단조 수요/용량을 이진 탐색하거나 세 작업 이상의 합산 검사를 쌍별 충돌로 대체하지 않는다.

같은 단위에서 연속으로 얻은 전체 날짜 벡터가 정확히 같으면 인증을 재사용한다. 서로 독립인 단위는 각 단위의 한 배치를 합쳐 native 전체 자원 부하로 인증한다. 단위 사이의 논리 조건은 모든 후보 조합에서 성립하고 같은 자원의 잠재 수요 범위는 겹치지 않으므로, 다른 단위를 현재 날짜로 되돌려도 각 증인의 유효성이 유지된다. 고정 배경은 유지한다. 모든 인증이 끝난 뒤에만 구조화된 증인과 수치를 공개하며 취소/실패 시 부분 결과를 노출하지 않는다.

수학적 정책은 `resource-repartition-float-v3`를 유지한다. 총여유는 가능한 작업별 재배치, 자유여유는 다른 날짜 고정 기준이다. 개별 최후 날짜를 하나의 공통 일정으로 합칠 수 있다는 뜻이 아니다. 현재 날짜·실적·원장·불변 근거 창·원본 관계·파일 schema9~14를 유지한다. 새 입력 필드는 없다. `selected.ppm`은 기존1.5/신규1.6 승인 기준선을 같은 수치로 저장하고 다시 열어 재검산한 schema12 파일이다. 기존1.0~1.5 재현 경로도 전체 회귀에 포함한다.

## 같은 입력의 교차 반복 관측

미리 계산한 동일 논리 일정에서 파생 여유 계산만 측정한다. 각 호출은 새 평가 캐시로 시작하고 캐시 해제까지 포함한다. 1.5/1.6 실행 순서는3회 중 교차하며, 전진 논리/직렬 평준화·UI·파일 I/O를 포함하지 않는다. 아래 시간은 밀리초 중앙값이며 모든 원시 표본과 checkpoint 수를 `metrics.json.gz`에 보존한다. 완료된 두 엔진의 TaskSchedule 전체 수치/날짜/임계를 C++ 계약에서 정확히 대조한다.

750개 사례의1.5 시간은 중단까지 걸린 단회 시간이다. 완료 시간의 속도 배율로 해석하지 않는다. 1.6은 생성 전 시작 좌표 상한을280,875분 축소하고2,250개 시작 좌표를 생성해 완료했다. 60개 체인은1,770분 축소·180후보, 결합256개는768후보, 분리1,000개는4,000후보다. 계수는 유효 후보 수나 고유 제외 수와 다르며 [진단 정의](../../candidate-propagation.md)를 따른다.

각 큰 사례의 native 증인 인증은1회이며 인증 절감 계수는 각각59/255/999/749회다. 최초 현재 배치의 전체 부하 검사는 별도로 수행하며 이 계수에서 제외한다. 1.6이 모든 입력의 중복 인증을 한 번으로 줄인다는 보장은 아니다. 비단조 작은 사례는 서로 다른 배치3회를 인증한다.

## 독립 검산과 실패 경로

독립 Python verifier는 C++ 탐색 구현을 호출하지 않고 **3,069개 증인 / 633,645개 날짜 참조**를 재구성한다. 자원 순서 체인과 고정 완료 경계에서 최대 총/자유여유를 유도하고, 모든 증인의 하한·순서·고정 날짜·완료 상한·합산 수요를 검사한다. 반복 날짜는 사전/인덱스로 손실 없이 보존한다. gzip 해제본 해시와 바이트 수는 `source-identity.json`에 있다.

작은 비단조 모델은 하루4근무분·10일, A/B/C 각2분·자원50%, 화요일/마지막 금요일50%·첫 수요일0% 용량을 사용한다. 현재 A/B는첫날09:00~09:02, C는09:02~09:04다. A→C 자원 반환을 유지하고17,366개 허용 배치를 전수 열거한다. A/B/C 총여유36/38/36분, 자유여유0/38/36분이 두 엔진과 일치한다. 개별 최후 시작(36,38,38)을 한꺼번에 적용하면 용량을 초과한다는 것도 검사한다. 분기 제외121회를 통해 실패/복구를 실행하며 반복 계산 동일성·미정 용량의 부분 증인 차단·취소를 검사한다.

openpyxl3.1.5는 `report.xlsx`의1.6 출처·총/자유여유와 새 진단을 다시 판독한다. 기존 보고서/인쇄·잔여 진척·native·XML/XER·근거 창의 별도 verifier를 포함해20종을 통과했다. MPXJ16.10/JPype1.6/Java21 및 비교기 자체시험은 실제 P6 실행과 구분한다.

## 소스·재현과 한계

src C++/헤더+CMake **207파일** SHA256은 `d5ed94d3a2ba04999b7a39abd660fffecd2f6180b6109fa347cddf42afd48d6b`다. 빌드 식별값과 일치하며 관련 테스트/스크립트/CI·실행 파일 해시를 `source-identity.json`에 보존한다. 전체 회귀 시작 전의 원시 해시 스냅샷과 대조해 제품/테스트/verifier 소스가 이후 바뀌지 않았음을 확인했다. 과거 검증 폴더는 수정하지 않았다.


CI reader/artifact 단계와 YAML50단계 구조를 로컬 확인했다. 원격 CI/macOS·신규 sanitizer/퍼징·실제 프린터/패키징은 미실행이다. P6는 사용자 확인대로 미설치이며 실제 P6 재계산 왕복은 실행하지 않았다.
