# PM 사용자 시험용 30개 작업 사례

2026-11-18 · 상태: 합성 자료와 시험 진행안 준비. 실제 PM 참여자 시험은 미실행.
[진행자용 계획·기대값](../../planning/22-weekly-pm-pilot.md) · [참여자 과업지](participant-tasks.md) ·
[빈 관찰 기록 양식](observation-template.md).

[pilot-start.ppm](pilot-start.ppm)은 반입 컨베이어·로봇 조립·비전 검사·전기 검사·포장·출하 컨베이어의
6개 셀, 총30개 기간 기반 작업이다. 각 셀은 설계2d→부품2d→조립2d/현장 설치 준비2d→시운전1d다.
셀마다 별도 기술자1명, 같은 셀의 조립과 현장 설치가100%씩 공유한다. 작업 ID는 C01-A~C06-E다.
셀 간 관계와 자원 공유는 넣지 않았다. 실제 현장의 상세 공정·WBS·휴일·다양한 달력을 대표한다고 보지 않는다.

기본 달력은 월~금09~12/13~18, 휴일 없음이다. 시작11-09, 상태일11-13 09:00,
동결 기준선1개(완료11-17 18:00), 이전 보고12건(각 셀 설계 완료·부품 실제2d/잔여2d), 현재 채택 없음이다.
이전 전문가 점검의5개 작업 사례를 구조적으로 확장한 **외부 작성 합성 fixture**다.
실제 UI로30개 계획과 기준선을 처음 작성하거나 실제 승인한 기록으로 취급하지 않는다.
[build_case.py](build_case.py)가 입력·동결 일정·보고 ID와 원본 문서 ID를 함께 만들고 Qt compact JSON 규칙의 무결성 해시를 기록한다.
생성 파일의 원본을 보존하고 참여자마다 사본을 사용한다.

## 자료 확인과 사용

Windows 통합 자동 검사 [WeeklyJourneyUiTests](../../../tests/WeeklyJourneyUiTests.cpp)의 pilot 행으로
실제 loader·검증·상태일 창·실적 입력창·자원 비교·회의용 PDF·저장·재열기를 확인한다.
[실행 결과와 화면·PDF](../weekly-update-integrated-2026-11-18/README.md)에 전문가 수동 점검과 자동 검사를 구분해 기록했다.
UI 입력 후 원장은14건, 보고 작업13/30이며 기준선·원래30개 작업·기존12건은 보존된다.
기준선/계획11-17, 논리 예측11-20, 조정 후보/채택11-24, 전체 과부하96h→0h를 독립 기대값과 대조한다.

생성 초기에는 기준선 입력 revision과 문서 revision을 모두1로 지정해 loader가 거절했다.
동결 입력 revision1보다 나중인 문서 revision2, 그 시점 이전 보고12건으로 자료를 바로잡았다.
이 실패는 합성 fixture 작성 오류이며 제품 오류로 집계하지 않는다.

```powershell
python docs/validation/weekly-pm-pilot-2026-11-18/build_case.py
```

참여자에게는 기대값이 있는 이 설명과 진행자 계획을 보여 주지 않는다.
결과·성공률·시간은 빈 양식에 실제로 관찰한 값만 기록한다. 첫3명은 제안 표본이며 모집·일정은 확정하지 않았다.
