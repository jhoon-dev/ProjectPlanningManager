# XML 계산식 FormatDateTime

2026-11-14 · XDT-01~06. 작업·프로젝트·자원·배정의 XML 계산식에서 `FormatDateTime(date[,namedFormat])`을 실행한다. 결과는 Text이며 기존 Format의 고정 Gregorian/en-US 날짜·시각 표시를 재사용한다.

| namedFormat | 의미 | `2024-02-29T13:04:05`의 결과 |
|---|---|---|
| 0 또는 생략 | 날짜 및/또는 시각 | 2/29/2024 1:04:05 PM |
| 1 | 긴 날짜 | Thursday, February 29, 2024 |
| 2 | 짧은 날짜 | 2/29/2024 |
| 3 | 긴 시각 | 1:04:05 PM |
| 4 | 24시간 짧은 시각 | 13:04 |

XDT-01: Date 값 또는 명시 ISO 날짜/일시 문자열을 받는다. 날짜만 있으면 자정으로 해석한다. 날짜 범위는 기존 native Gregorian1~9999년이다. 숫자 OLE 날짜·Boolean·지역별 날짜 문자열·시각만 있는 문자열은 추정하지 않는다. 시각 문자열은 TimeValue로 Date를 만든 뒤 사용할 수 있다. 시간대가 있으면 기존 명시 시간대 함수로 먼저 변환하며 출력 문자열 자체에는 시간대 표지가 없다.

XDT-02: 기본 형식0에서 시각이 자정이면 짧은 날짜만 표시한다. OLE 기준일 **1899-12-30**은 날짜 부분을 생략하고 시각만 표시한다. 기준일 자정은 `12:00:00 AM`이다. 그 외 날짜에서 시각이 있으면 날짜와 시각을 함께 표시한다. 형식1~4는 해당 날짜/시각 부분을 항상 표시한다.

XDT-03: 옵션은 짝수 쪽 정수 반올림 후0~4를 검사한다. 1.5와2.5는2, 3.5와4.5는4이며4.500001은 오류다. 옵션 문자열은 숫자로 암묵 변환하지 않는다. Date/옵션의 Null은 오류이며 미설정으로 바꾸지 않는다. `IIf(True,1,FormatDateTime(Null))`도 기존 모든 인수 평가 규칙에 따라 오류다. 미설정 결과는 안전한 기존 typed 식으로 명시할 수 있다.

소수 초는 기존 Format처럼 **표시에서 버린다**. 초·분·날짜로 반올림 이월하지 않으며 원본 Date의 소수 초는 그대로 남는다. 따라서 `FormatDateTime(#2024-02-29T00:00:00.6#)`은 `2/29/2024`, `FormatDateTime(#2024-02-29T23:59:59.999999#,4)`는 `23:59`다. 소수 초 보존에는 CStr를 사용한다. Windows VBScript는 일부 소수 초를 반올림하며, 이 차이를 검증 기록에 별도로 남긴다. Windows NLS가1601년 이전 표시를 거절할 수 있는 동작도 따르지 않는다. OS 로캘·달력·사용자 지역 설정을 읽는 전체 VBA/NLS 실행기가 아니다.

XDT-04: 활성 새 함수가 현재·기준선·시나리오·일정 채택·통화/ID 이력 전후 전체 사본에 있으면 조건부 **schema68**이다. schema67 이하는 활성 새 식을 거절한다. 비활성 원문은 기존 schema44부터 보존하고 다른 기능/참조의 최소 버전도 유지한다. native 필드는 추가하지 않는다. 안정 ID/이름 변경·undo/redo·저장/재열기·복구·읽기 전용·취소 checkpoint를 연결한다.

XDT-05: 편집기의 예시 삽입·worker 미리보기를 제공하며 네 범위·요약·roll-down·native 숫자 식과 결합한다. 예를 들어 `Len(FormatDateTime([입력일시],4))`를 native 숫자 식에서 참조할 수 있다. 환산 금액을 DateAdd의 일수로 사용하는 식도 통화 전환 후 다시 계산한다. XML은 정의·참조·현재 값과 재수입 실행, XER는 정적 결과, source.ppm은 전체 정의/이력, XLSX/PDF는 값과 별도 오류/미설정을 보존한다. 오류를 저장된 스냅샷이나0으로 대체하지 않는다.

XDT-06: 윤년366일×4개 시각×5개 형식7,320건과 기준일 전후·1601/9999년·1900/2000년 경계50건, 합계 **7,370건**을 Python calendar/datetime과 Windows VBScript(SetLocale1033)의 정수 초 입력에서 대조한다. 소수 초 및1600년의 의도한 차이는 별도 기록한다. 직접 식·반올림·Null/범위 오류·저장/전체 사본·교환·보고서·작은 화면도 검사한다. 실제 Project/P6 실행 왕복과 전체 VBA/로캘 동등성은 잔여다.

구문 기준은 Microsoft [FormatDateTime](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/formatdatetime-function)이다. [검증 기록](validation/xml-date-display-2026-11-14/README.md). 다른 함수·번호별 기준선·요약 기간과 기존 GAP도 계속 잔여다.
