# 실적 반영 잔여 일정의 여유·임계 계약

2026-11-02 사용자 개발 요청. GAP-01과 GAP-02의 첫 증분이다. 상태일 이후 예측의 총여유·자유여유·임계와 driving 선행을 계산한다. 외부 MSP/P6 동등성, 평준화 결과 채택, 다른 진척 정책의 구현 완료를 뜻하지 않는다.

## 계산 의미

- 기존 retained-remaining 전진 배치와 실제 날짜는 유지한다. 후진 계산 종점은 현재 예측 프로젝트 완료일이다. 별도 목표 완료일·음수 여유 모드는 이번 범위가 아니다.
- 미완료 작업의 잔여 실행 구간만 이동시킨다. 실제 시작이 있는 작업은 실제 시작을 고정하고 잔여 재개·예측 완료를 이동시킨다. 완료 작업은 미래 총/자유여유·임계의 적용 대상이 아니며 화면/출력에서 미정 표시한다.
- 총여유는 후행 잔여를 각자의 가장 늦은 구간까지 이동할 수 있을 때 해당 작업의 잔여 시작을 늦출 수 있는 작업 달력 근무분이다. 자유여유는 후행 잔여를 현재 예측 구간에 고정했을 때의 같은 값이다. 두 계산 모두 예측 완료일·유효 날짜 제약을 지킨다. 임계는 미완료 작업의 총여유가 0인 경우다.
- 완료 후행의 과거 관계 위반은 진단으로 보존하고 미래 잔여를 제한하지 않는다. 진행 중 선행의 SS/SF 출발점은 고정 실제 시작이며 잔여 지연으로 이동하지 않는다. FS/FF 출발점은 예측 완료다. 미완료 후행의 시작 관계는 잔여 재개를 대상으로 한다.
- driving 선행은 현재 잔여 시작을 결정하는 활성 관계다. 완료 선행과 고정 실제 시작에서 출발하는 관계는 미래 driving 표시에서 제외한다. 제약/상태일 때문에 임계인 작업은 driving 선행이 없을 수 있다.
- 기간·공수 작업, 작업/자원 달력과 수동 중단은 각각 기존 실행 모델을 재사용한다. 양/음의 지연은 후행 작업 달력 기준이다. 실제 시작 제약은 실제 날짜에, 완료 제약은 예측 완료에 적용한다. 예측 ALAP의 전진 재배치는 하지 않고 현재 예측으로부터 여유를 산정한다.
- 마감일은 기존 native 경고·별도 마감 여유 정책을 유지하며 CPM 여유에 반영하지 않는다. 상용 제품과의 의도된 차이로 기록한다. 날짜 제약 충돌은 기존처럼 정상 완료일/여유를 확정하지 않는다.
- 자원 달력에 따른 공수 수행 가능성과 자원 간 용량 충돌은 별개다. 이 결과는 자원 용량까지 평준화한 임계가 아니다. 평준화 시나리오에는 이 여유를 복사하지 않는다.

## 버전과 표시

예측 정책에 `/remaining-float-v1`을 덧붙여 새 후진 계산을 식별한다. 최초 계획 엔진·native schema 9·승인 기준선 형식/결과는 변경하지 않는다. 새 여유 계산의 가용 여부는 세션 계산 결과에만 두고 파일에 저장하지 않는다. 저장된 시나리오의 배치 정책과 결과 날짜도 변경하지 않는다.

작업 표는 총여유와 예측 임계/여유 상태, 툴팁은 총/자유여유를 제공한다. 간트는 예측 임계 막대·driving 선과 텍스트를 제공한다. 보고서는 기존 계획 임계 지표와 별개로 잔여 예측 임계 지표와 예측 총/자유여유를 제공하고 같은 스냅샷으로 XLSX/PDF를 출력한다. 완료·충돌·미계산·오래된 결과는 0으로 표시하지 않는다.

## 수용조건과 검증 상태

1. GAP-T01(A 완료, B→C와 독립 D)의 독립 기대값 B/C 0h, D 8h를 기간/공수 프로필에서 검증한다.
2. 4종 관계·양/음의 지연·혼합 달력·휴일·마일스톤·수동 분할·고정 실제 시작/완료·제약·마감과 상태일/잔여 정정을 포함한다. 작은 네트워크는 전진 결과를 고정한 독립 분 단위 열거와 대조한다.
3. 기존 기준선/시나리오·저장/재열기·복구·실적 원장과 표/간트/보고 출력이 일관된다. 후진 계산 취소는 부분 여유를 정상 결과로 반영하지 않는다.
4. 1천/1만 작업에서 전후 실행을 측정하고 실제 측정 환경과 미검증 범위를 남긴다.

구현과 로컬 Windows의 수용 시험·기존 회귀·독립 출력 검증 결과는 [검증 기록](validation/forecast-float-2026-11-02/README.md)에 보존한다. 다른 OS와 실제 MSP/P6 실행 검증은 별도 미완료다.

[진척 정책 비교](progress-policy-comparison.md)의 B는 계산 전용 관계 overlay에서 같은 후진 엔진을 실행한다. 비활성 수신 관계는 총/자유여유와 driving에서도 제외하고 완료 실적은 미래 여유에 포함하지 않는다. 이는 원본 retained 정책 변경이나 P6 동등성 판정이 아니다.

진척 정책을 명시적으로 채택하면 활성 예측은 선택한 A/B 관계로 여유·임계를 계산하고 adopted-progress-v1 출처를 기록한다. 원본 계획과 기준선은 유지한다. 선택은 [schema13/복구/실행 취소 계약](progress-policy-adoption.md)에 따라 저장한다.

평준화 후에는 별도 [자원 슬롯 순서 후진 계산](leveling-float.md)을 사용한다. 논리 잔여 여유와 같은 값으로 해석하지 않으며 실제 완료는 여전히 미래 여유에서 제외한다.
