# 진척 정책과 평준화 함께 적용

추적 → 진척 정책 비교에서 A 또는 B를 채택한 뒤 자원 → 평준화 비교에서 계산·시나리오 저장·현재 일정 채택을 수행한다. 원본은 선택한 정책의 논리 예측이며, 제안은 그 예측에 자원 가용량을 반영한 일정이다.

## 계산·편집 계약

- 원본 전체 계획을 검증한 후 진척 정책을 적용하고 평준화한다. B는 상태일 현재 진행 중인 작업의 수신 관계를 준비 순서·날짜 경계 모두에서 제외한다. 원본 관계를 삭제하지 않는다. 완료 실제일과 진행 중 실제 시작은 고정한다.
- FS0·PDM·제약·공수/분할 엔진과 기존 우선순위·탐색 범위를 사용한다. 자원 달력/가용량·중단·잔여 공수·날짜 제약은 각 엔진의 기존 계약을 따른다. 미정 용량/배치 불가 결과는 채택할 수 없다. 미해결 시나리오의 저장·재검토는 가능하다.
- 표·간트·기간별 잔여 공수/원가·보고서·인쇄·공유 부하는 채택한 조합을 재계산해 사용한다. 평준화 후 총/자유여유·임계·driving은 자원 슬롯 순서를 고정해 재계산한다. 계산 불가 시 미산정 사유를 표시한다. 기존 논리 CPM 값을 재사용하지 않는다.
- 평준화만 해제하면 진척 정책을 유지한다. 진척 정책 채택·교체·해제는 기존 평준화 채택을 함께 해제하는 하나의 편집이다. 새 정책으로 다시 평준화해 채택한다. 정책 비교의 A/B는 평준화 전 논리 예측을 비교한다.
- 작업/달력/배정/실적/상태일 등 평준화 입력 수정 시 채택 평준화를 해제하는 기존 규칙을 유지한다. 진척 정책 설정은 유지한다. 상태일 미설정 시 진척 정책은 비활성이며 계획 평준화가 가능하다.
- 원본 계획·승인 기준선·실적/원가 원장을 보존한다. 프로젝트의 평준화 채택·해제 및 정책 변경은 Undo/Redo를 지원한다. 저장 시나리오는 기존 불변 이력으로 취급한다.

## 저장·재현

진척 정책과 현재 평준화가 함께 있거나, 진척 정책을 포함한 저장 시나리오가 있으면 조건부 native schema14를 사용한다. 단독 정책은 schema13, 기존 평준화는 schema12 등 종전 조건을 유지한다. schema13 이하 파일은 조합을 거절한다.

시나리오는 PlanInput·상태일·실적뿐 아니라 `progressPolicy`의 ID·담당자·사유·UTC·검토 출처도 동결한다. 과거 시나리오에 이 필드가 없으면 기존 기본 잔여 논리 유지로 재생한다. 현재 입력과 진척 정책이 다른 저장 시나리오는 직접 채택하지 못한다. 저장·재열기·SaveAs·복구에서 조합을 보존한다.

비동기 계산/채택에는 문서 ID·revision·열기 세션과 취소 검사를 적용한다. 실제 P6 재계산 동등성은 미설치로 미검증이다. XML/XER는 현재와 같이 원본 기간 기반 논리 계획만 교환하며, 선택한 두 설정과 근거는 native source.ppm에 보존하고 손실을 알린다.

조합의 후진 계산은 B 비활성 관계를 제외한 활성 논리와 별도 자원 연결을 함께 사용한다. [자원 순서 여유·임계](leveling-float.md)를 따르며 계산 불가 시 기존 날짜는 유지하고 여유만 미산정으로 표시한다.

교차 분할 실행 창의 후진 계산에도 채택한 A/B 관계 마스크와 pendingTask의 잔여 기간·공수를 사용한다. 실제 시작/완료는 고정하며 원본 관계를 수정하지 않는다. [계산·지원 경계](leveling-float.md).

엔진1.3~1.8 재분할도 같은 활성 관계와 잔여 공수/기간을 사용한다. 실제 시작/완료를 고정하고 미래 구간만 재생성한다. 작업별 총여유 증인과 다른 날짜를 고정한 자유여유를 구분한다. 1.4 이상은 같은 활성 관계로 후보를 제거하고 고정 작업을 탐색 분기에서 제외한다. 1.5의 탐색 단위 분해도 이 활성 관계와 실제 잔여 수요 범위를 보존하며128개를 넘는 잔여 작업을 같은 예산 안에서 계산한다. [정의](leveling-float.md). 1.6의 안전한 상한 축소·조건부 후보 제외/복구·인증 공유도 같은 활성 관계와 실적 고정을 따른다. [효율화 계약](candidate-propagation.md). 1.7의 점별 필수 수요와 살아 있는 후보의 연쇄 전파도 잔여 구간만 사용한다. [비단조 전파](nonmonotone-propagation.md).1.8은 같은 잔여 후보의 비용 추정·실패 관측·효과 피드백으로 추가 전파 적용만 조절한다. [비용 계약](propagation-cost.md).
