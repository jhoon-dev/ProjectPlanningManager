# 자원 생산성·외부 고유 곡선 교환

2026-11-09 구현. **자원 → 자원 생산성·외부 고유 곡선…**에서 자원별 물량 생산성을 정의하고 선택 배정의 계획 공수를 산정하거나 MS Project 기본/사용자 21지점 곡선을 적용한다. [실행 증거](validation/resource-productivity-curves-2026-11-09/README.md)를 따른다.

## 물량과 계획 공수

- 생산성은 `물량 단위 / 자원 1단위·1시간`이다. 단위, 양수 생산성, 기준일, 측정/가정 근거와 작성자를 저장한다. 물량/생산성은 각각 0.001 단위 정수이며 최대1,000,000, 생산성은0보다 커야 한다. 자원 카탈로그 저장만으로 기존 계획을 바꾸지 않는다.
- 명시 적용 시 `ceil(물량 × 6,000 / 시간당 생산성)`을 1/100 자원분으로 산정한다. 총공수 상한은500,000,000,000이다. 가격·가용률·자원 종류의 자동 배수로 사용하지 않는다.
- FixedDuration은 현재 계산 기간을 유지하고 선택 자원의 필요 배정률 구간을 생성한다. 단일 자원 FixedWork/FixedUnits는 기존 배정률·상대 곡선을 유지하고 총공수에서 기간을 역산한다. 다중 자원 작업은 ‘현재 계산 기간 유지’를 명시해야 하며 다른 배정의 물리 공수를 보존한다. 이 방식에서 기간 기준 FixedUnits는 명시 총공수를 갖는 공수 기준으로 바뀐다.
- 기존 작업/자원 달력·휴일·중단·제약과 정수 배정률을 사용한다. 불가능한 양수 공수, 배정률 상한 초과, 검산 불일치는 거절한다. 고정 날짜 잔여 목표와 관측 실적은 별도 입력으로 유지한다.
- 적용 당시 생산성 사본·물량·결과 공수·적용 방식·작성자/사유/UTC와 확인을 배정에 보존한다. 이후 카탈로그·구간·달력 변경은 산정 기록을 자동 재계산하지 않으므로 재검토한다. 산정/곡선 기록만 해제하면 계획 구간은 유지된다.

## 곡선의 계획 투영

21지점의 첫0% 값은0, 뒤20개는 각5% 기간 구간의 공수 비중이며 합계100%다. 비중은 백분율의 소수점6자리 정수(100%=100,000,000)로 보존한다. MS Flat/Back Loaded/Front Loaded/Double Peak/Early Peak/Late Peak/Bell/Turtle과 사용자 정의를 지원한다. 이 값은 순간 배정률이 아니다.

총공수를 각 비중으로 나누고 최대 나머지 순서로 1/100 자원분을 배분한다. 동률은 앞 구간 우선이다. 각 구간은 현재 작업 기간 축을 사용하고 실제 자원 가용 근무분으로 정확한 정수 배정률을 생성한다. 기간20분 미만의21지점 적용, 양수 비중인데 가용시간이 없는 구간 등은 거절한다. 총공수와 다른 자원 공수를 검산한다. 달력이 다른 외부 제품의 곡선 보간/이동/재계산 결과와 동등함을 선언하지 않는다.

원본 형식·ID·이름·코드·21값 또는 수동 시간대별 계획 공수의 투영 구간, 당시 배정률/기간/공수를 보존한다. 현재 구간/배정률/기간/공수가 일치할 때 원본 정의를 재사용한다. 이후 편집으로 달라지면 현재 계획에서 새 교환 투영을 만든다. 원본 정의는 과거 근거로 유지한다.

## XML·XER·MPP 교환

- MS Project XML: WorkContour0~7, Type1 계획/잔여 시간대별 공수를 읽는다. 실제공수0/미지정인 Type1만 계획으로 채택한다. 실제공수가 있는 Type1 및 실제 시간대 데이터는 계획 곡선으로 추정하지 않고 손실 진단을 남긴다. 수동 코드8의 데이터 누락·미지원 단위/정밀도/참조도 진단/거절한다. 내보내기는 Work/RemainingWork·ActualWork0과 정확한 Type1 계획 공수, 배정 시작/완료를 기록한다. 변경된 사용자 구간은 코드8로 투영한다. 시간대 데이터는 배정당1,024개까지다.
- P6 XER: RSRCCURVDATA의 pct_usage_0~20과 TASKRSRC.curv_id, target_qty를 읽고 자원별 총공수에 적용한다. 미해결 곡선 참조·잘못된 합계·미지원 배정 lag는 거절한다. 내보내기는 현재 정의 또는 현재 구간을20개 구간으로 집계한21값과 총공수를 기록한다. 집계 시 세부 배정률 손실을 진단한다. 같은 작업의 배정도 함께 투영하고 결합 XER에서는 곡선 ID를 재매핑한다. 기간20분 미만은 해당 곡선 투영의 손실을 진단한다. 0공수 역산 작업은0기간/0수량으로 교환한다.
- MPP는 기존 오프라인 MPXJ→XML 경로가 제공하는 기본 곡선/계획 데이터를 같은 검사로 처리한다. 후속 [MPP 수동 정규 계획 곡선](mpp-manual-curves.md)도 지원한다. MPP 쓰기나 바이너리 원본의 모든 수동 곡선 복원은 지원 범위가 아니다. XML/XER의 생산성 필드에는 표준 매핑을 만들지 않으며 native 산정 근거는 native 파일/보고서로 전달한다.

관측 공수·AC·기준선·동결 시나리오는 계획 편집 시 유지한다. 실제공수/진척·원가 수입은 기존 별도 계약을 따른다. 원본 XML/XER/MPP는 기존 동반 파일 보존 경로를 유지한다.

## 편집·저장·보고

검산은 취소 가능한 worker로 수행하고 확인한 결과를 한 revision/undo 단위로 적용한다. 입력 변경·문서 revision/세션 변경·취소·읽기 전용/권한 철회는 준비 결과를 무효화한다. 생산성/산정/곡선 근거만 바뀌면 기존 평준화 채택을 유지하고 실제 공수/구간이 바뀌면 이력과 함께 무효화한다. 기본 크기와800×600 화면, 메뉴 연결을 검사한다.

조건부 schema36은 현재 계획, 기준선/시나리오, XER 일정 채택 전후/원본 및 통화/ID 이관 전체 사본 안의 생산성/산정/곡선을 검사한다. 기존1~35 최소 writer를 유지하며 미래37과 구 envelope의 새 필드를 거절한다. 저장/재열기·사본·복구에서 같은 구조를 보존한다. 보고서 XLSX/PDF에 자원 생산성, 배정 산정 근거와 외부 곡선 정의/투영 상태를 추가한다.

형식 근거는 [Oracle Resource Curves](https://docs.oracle.com/cd/F74771_01/client_help/en_US/resource_curves.htm), [Microsoft WorkContour](https://learn.microsoft.com/tr-tr/office-project/xml-data-interchange/workcontour-element?view=project-client-odc), [MPXJ timephased data](https://www.mpxj.org/howto-use-timephased/)와 저장소의 MPXJ16.10 대응 소스를 대조했다. 실제 Microsoft Project/P6 실행·재저장 검증은 별도 환경이 필요하다.
