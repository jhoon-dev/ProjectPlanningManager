# 진척 정책 채택·저장

추적 → 진척 정책 비교에서 유효한 A(잔여 논리 유지) 또는 B(진행 중 작업의 수신 관계 무시)를 선택하고 담당자·사유를 입력해 채택한다. 비교만 실행하면 현재 일정은 바뀌지 않는다. 채택 시 표·간트·기간별 사용량의 잔여 공수/원가·보고서의 예측은 선택한 정책을 사용한다. 현재 계획 예산과 기준선 PV/EV/AC의 의미는 바꾸지 않으며 잔여 배정 원가는 EAC/ETC와 별개다. 원본 관계와 기준선 계획은 보존한다.

## 저장 계약

- 프로젝트 전용 `progressPolicy`에 정책 ID, 담당자, 사유, UTC 시각, 검토한 문서 ID/revision을 저장한다. 기준선의 PlanInput에는 포함하지 않는다.
- 정책 ID는 `native-retained-remaining-v1`, `native-progress-override-v1`만 허용한다. 이 정책은 P6 엔진과의 동등성을 보증하지 않는다.
- 단독 선택은 native schema 13, 평준화와 조합하거나 정책을 동결한 시나리오가 있으면 schema14를 사용한다. 선택이 없는 기존 프로젝트는 종전 schema 9–12 조건을 유지한다. 복구 세대에도 선택을 저장한다. 이전 schema에서 이 필드를 받지 않는다.
- 선택은 계산 결과 스냅샷이 아니라 재계산 설정이다. 작업·실적·상태일 변경 후에도 유지한다. 상태일을 지우면 설정은 보존하되 계획만 계산한다. 상태일을 다시 설정하면 선택한 정책이 적용된다.
- 채택·교체·해제는 각각 하나의 실행 취소 단위다. 저장·재열기·다른 이름으로 저장 시 유지한다. 메타데이터는 현재 선택의 기록이며 별도의 불변 승인 원장이나 전자서명이 아니다.

## 적용 안전성

원본 문서 ID/revision/열기 세션이 같은 최신 비교에서만 채택한다. 비교/정책 B 재계산은 10,000 작업·100,000 관계까지 지원하며 이를 초과하면 정상 결과를 확정하지 않는다. 선택한 예측이 유효해야 한다. 백그라운드 편집 준비 중 취소·문서 변경·읽기 전용 전환이 있으면 적용하지 않는다. 채택 해제는 기본 잔여 논리 유지로 돌아가며, 현재 계산이 불완전해도 가능하다.

[진척 정책과 평준화 조합](progress-policy-leveling.md)을 지원한다. 진척 정책을 채택한 뒤 그 논리 예측에 평준화를 계산·저장·채택한다. 평준화만 해제하면 정책을 유지하고, 정책 채택·교체·해제는 기존 평준화 채택을 함께 해제한다. A/B 비교는 평준화 전 논리 예측을 사용한다.

B는 상태일 현재 실제 시작이 있고 실제 종료가 없는 작업의 수신 관계를 예측 계산에서 비활성화한다. 원본 관계는 삭제하지 않는다. 완료 작업의 실제일은 고정하며 미착수 작업의 관계는 유지한다. 원본 순서 위반 진단은 코드·대상을 보존하고 B의 비활성 관계 정책에 맞는 설명을 표시한다. 네트워크와 간트는 비활성 관계를 구분해 표시한다.

XML/XER의 기간 기반 계획 교환에는 이 설정을 전달하지 않는다. native 원본을 별도로 보관해야 한다. P6가 설치되어 있지 않아 P6 실제 재계산 왕복은 미검증 상태다.
