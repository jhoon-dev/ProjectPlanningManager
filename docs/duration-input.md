# 기간을 일·시간·분으로 입력하기

2026-11-17 · UX-W02. 계획 표, 선택 작업 공수·유형·분할 창, 실제 소요·잔여 기간 입력과
보고 이력은 같은 기간 표기 규칙을 사용한다.

- 숫자만 입력하면 **일**이다. `2`, `2d`, `2일`은 같다.
- `h`/`시간`과 `m`/`분`으로 정확한 시간·분도 입력한다. 소수는 최대6자리이며 정수 분으로
  정확히 환산되어야 한다. `1.5d`는 가능하고 `0.1m`은 거절한다. 반올림해 저장하지 않는다.
- 기본 달력은 `1d=8h=480m`이므로 `2d`, `16h`, `960m`은 같은 값이다.
  하루7시간 작업 달력에서는 `2d=14h=840m`이다. 주 창에서 작업을 선택하면 달력 이름과
  `1d` 환산 기준이 보이고, 기간 셀의 도움말과 편집창에서도 확인할 수 있다.
- `d`는 작업 달력에 등록된 하루 근무 구간 길이의 합이다. 주말·휴일을 포함한 24시간
  경과일이 아니며 자원 수를 곱한 공수도 아니다. 실제 일정은 기존 달력·휴일·중단·자원 규칙으로 계산한다.
- 표시는 정확한 소수3자리 이내의 일 단위가 가능하면 `d`를 사용한다. 나누어떨어지지 않으면
  정수 시간 또는 분으로 표시해 정확한 값을 보존한다. 예: 기본 달력의 `240m → 0.5d`,
  `1m → 1m`, 7시간 달력의 `60m → 1h`.
- 계획 기간의 빈칸은 미정, `0`은 마일스톤이다. 실제·잔여 보고는 명시적 숫자가 필요하다.
  완료 보고의 실제 날짜·잔여0과 기존 보고/정정 검증은 그대로다.

이전 UI의 **접미사 없는 숫자=시간** 입력은 이제 **숫자=일**로 바뀌었다. 이전 지침이나
외부 TSV가 시간 숫자라면 `8` 대신 `8h`처럼 단위를 붙여 넣는다. 기존 파일은 정수 분으로
저장되어 있으므로 열기만 해서는 기간이 달라지지 않는다. 엔진·저장 schema·기준선·원장의
저장 단위는 변경하지 않았다. 과거 보고 이력의 일 표시는 현재 작업 달력으로 환산하며,
도움말에는 원본 실제/잔여 분을 함께 표시한다.

공수는 계속 자원시간(h)이다. 공수 기준 작업의 잔여 기간은 비활성화하고 명시 잔여 공수를
사용한다. 선행관계의 `+1d`는 기존의 **480분 지연** 계약을 유지하며 기간 셀의 일 환산과
별개다. 관계 도움말에도 이 기준을 명시한다. `ed` 경과일, 주·월, 음수·소수 분은 받지 않는다.
