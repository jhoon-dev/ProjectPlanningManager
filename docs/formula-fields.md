# 계산식 사용자 필드

2026-11-11 후속: [XML 외부 계산식](xml-external-formulas.md)을 별도 문법으로 실행한다. native 숫자 식과의 양방향 참조·혼합 순환/깊이 검증을 지원하며 기존 native 단위/정밀도 계약은 유지한다.

2026-11-06. FF-01~05, GAP-03, PRD-01/02/06/07/08, J-01/02/05/14/16에 연결한다. 작업·프로젝트·자원의 **숫자 필드**에 선택적인 계산식을 정의한다. 결과는 읽기 전용이며 기존 일정·배정·원가·진척 입력에 자동 합산하거나 역산하지 않는다.

## 정의와 사용

각 범위의 사용자 필드 정의 창에서 형식을 숫자로 선택한다. **참조 삽입**은 이름으로 선택한 참조를 안정 ID 토큰으로 넣는다. **수식 검사**는 문법·참조·단위와 첫 객체의 결과 예시를 보여준다. 저장 전 검사만으로 문서를 바꾸지 않는다. 실제 저장은 현재 문서 ID/revision/session·권한과 전체 사전/값을 다시 검증한다. 값이 있는 수동 숫자 필드를 계산식으로 전환하려면 먼저 그 수동 값을 명시적으로 제거해야 한다.

| 참조 | 범위와 의미 |
|---|---|
| `[field:ID]` | 같은 범위의 숫자 필드. 수동 값 또는 다른 계산식 결과 |
| `[project:ID]` | 프로젝트 숫자 필드. 작업/자원에서도 참조 가능 |
| `[durationHours]` | 작업의 명시 입력 기간을 시간으로 변환. 미정 입력은 미설정 |
| `[workHours]` | 작업의 명시 입력 공수(h). 달력/배정으로 추정한 공수가 아니며 입력이 없으면 미설정 |
| `[capacity]` | 자원의 기본 가용률(%). 미정과 0% 구분. 날짜별 예외를 선택하지 않음 |
| `[taskCount]`, `[resourceCount]` | 프로젝트의 현재 입력 객체 수 |

필드/옵션 표시 이름을 바꿔도 ID 참조는 유지된다. 프로젝트 식은 작업/자원의 행 값을 참조할 수 없고, 작업과 자원 사이의 행 참조도 없다. 텍스트·목록·날짜 필드의 숫자 변환, 외부 데이터·시각·파일·네트워크·임의 코드 호출은 지원하지 않는다. 저장된 계산 결과를 다시 입력처럼 사용하지 않고 원래 값과 정의에서 재계산한다.

참조 삽입은 ID 안의 닫는 대괄호와 역슬래시도 이스케이프해 보존한다. 직접 토큰을 입력할 때는 각각 `\]`, `\\`를 사용한다.

## 문법·단위·정밀도

- 사칙 연산 `+ - * /`, 단항 부호, 괄호, 두 인수 `min/max/coalesce`, 한 인수 `abs`를 지원한다. 곱/나눗셈은 덧/뺄셈보다 먼저, 같은 우선순위는 왼쪽부터 계산한다. 지수·쉼표 숫자·암시적 곱셈·조건문/문자열 함수는 지원하지 않는다.
- 상수는 소수 6자리 이내다. `8{h}`, `100{%}`, `2{점}`처럼 단위 태그를 붙일 수 있다. 태그는 대소문자까지 정확히 일치해야 하며 단위 자동 변환은 없다. `h`와 `min` 또는 `시간`을 같다고 취급하지 않는다.
- 덧/뺄셈·min/max/coalesce는 양쪽 단위가 같아야 한다. 곱셈은 적어도 한쪽이 무단위다. 나눗셈은 무단위 분모이거나 같은 단위끼리 나눠 무단위가 되어야 한다. 최종 결과 단위가 선언한 필드 단위와 같아야 한다. 예: `[durationHours] * ([project:percent] / 100{%})`.
- 값과 각 연산 결과는 정수 배율 1,000,000의 고정 소수점이다. 곱/나눗셈마다 소수 6자리로, 정확히 절반이면 0에서 멀어지는 방향으로 반올림한다. 부동소수점이나 플랫폼별 128-bit 확장에 의존하지 않는다. 예: `1/3*3 = 0.999999`, `-0.000001/2 = -0.000001`.
- 범위는 기존 숫자 필드와 같은 ±999999999.999999다. 중간 연산이 범위를 넘으면 뒤 연산으로 다시 작아질 수 있어도 오류다. 0 나눗셈과 범위 초과를 저장 거절이나 0으로 대체하지 않고 객체별 계산 오류로 표시한다.
- 미설정은 연산에 전파된다. `coalesce(미설정, 대체값)`은 같은 단위의 대체값을 사용한다. 알려진 0을 미설정으로 바꾸지 않는다. 계산 오류는 coalesce로 숨기지 않으며 사용하지 않는 대체식은 실행하지 않는다.

사전은 기존 범위별 64개 한도를 따른다. 식 2,048 bytes, 식당 128개 값/연산, 문법 중첩 32단계, 필드 참조 64단계, 전체 평가 의존 깊이 128단계로 제한한다. 제어문자·미정의 참조·비숫자 참조·단위 불일치·순환 참조·지원하지 않는 문법은 원자적으로 거절한다. 정의 컴파일 캐시는 불변이며 숫자 입력·객체 수·기간/공수·가용률이 바뀌면 값 캐시를 재사용하지 않는다. 표의 별도 결과 캐시는 512개로 제한한다.

## 조회·보존·출력

작업 표와 그룹/필터/정렬, 자원 그룹/필터, 프로젝트/자원 값 조회에 계산 결과를 연결한다. 계산식 열/값은 직접 입력·값 제거를 차단한다. 의존 입력이나 정의 변경 후 새 결과를 표시한다. 그룹/필터에서 계산값이 없는 경우는 미설정 조건에 포함하며, 상세 셀과 진단에서 실제 미설정/계산 오류를 구분한다. 자원 보기에는 계산 오류 건수를 표시한다.

계산식 정의는 PlanInput의 일부다. 기존 기준선/시나리오의 정의·원래 값은 동결하며 당시 입력으로 결과를 재현한다. 현재 정의 변경은 기존 동결 기록을 바꾸지 않는다. 정의/값 편집은 기존 undo/dirty·권한/세션·평준화 보수적 무효화 정책을 따른다. 새 보기를 저장하는 것과 달리 사전 편집은 PlanInput 변경이다.

현재 또는 동결 사전에 계산식이 있으면 조건부 schema23을 사용한다. 새 데이터가 없으면 기존 writer 선택을 유지하며 schema1~22를 계속 읽는다. 구 schema의 expression 속성은 거절한다. 복구/사본은 정의와 원래 값만 보존한다. 날짜별 잔여 입력(schema22)·자원 저장 보기(schema21)와 함께 사용할 수 있다.

보고서는 계산 결과를 기존 사용자 필드의 숫자 셀로 출력하고, 결과가 없으면 기존 ‘미정’ 표시를 사용한다. 별도 **계산식 필드 정의**, **계산식 미설정과 오류** 표에 원인과 상태를 남긴다. XLSX에 실행 수식이나 외부 링크를 넣지 않는다. 2026-11-06 후속 [XML/XER UDF 매핑](external-udf-mapping.md)은 현재 결과를 숫자로 투영하고 식·의존성·단위 손실과 오류로 생략한 값을 진단한다. native 원본에는 정의와 입력을 보존하며 외부 계산식을 실행하지 않는다.
