# XML 계산식 Str·Val·Hex·Oct

2026-11-13 후속: 다음 후보였던 [추가 수학 함수6개](xml-math-functions.md)를 구현했다. Atn/Cos/Exp/Log/Sin/Tan의 활성 호출/전체 사본은 schema58이며 이 문서의 Str/Val/Hex/Oct 계약과 최소57을 유지한다.

2026-11-13 · XNT-01~06. 사용자 필드의 **XML 계산식…**에서 숫자와 문자열 사이의 명시 변환을 지원한다. 점 소수와 고정된32비트 진수 규칙을 사용하며 PC 로캘·현재 통화·단위를 추측하지 않는다.

```text
Str([입력금액])
Val("12.3456785 hours")
Hex(255.5)
Oct(-1)
Val("&H" & Hex(65535) & "&")
```

입력금액12.34의 Str 결과는 선행 공백이 있는 ` 12.34`이다. 나머지 예시는12.345679, `100`, `37777777777`,65535를 반환한다. 계산 결과를 일정·공수·원가 입력이나 원장에 자동 채택하지 않는다.

## 함수

| 함수 | 고정 규칙 |
|---|---|
| `Str(number)` | 양수와0의 부호 자리에 공백을 두고 음수는 마이너스를 쓴다. 점 소수와 native 소수6자리를 보존한다. |
| `Val(text)` | 문자열에서 숫자로 읽을 수 있는 접두부만 Number로 변환한다. 나머지 문자열은 해석하지 않는다. |
| `Hex(number)` | 짝수 쪽 반올림 후32비트 정수의 대문자16진수 문자열이다. |
| `Oct(number)` | 같은 정수의8진수 문자열이다. |

Str/Hex/Oct는 숫자·Boolean 또는 기존 CDbl과 같은 점 소수6자리 숫자 문자열을 받는다. Boolean의 True=-1, False=0 의미를 유지한다. Hex/Oct는 반올림 뒤-2147483648~2147483647 범위를 검증한다. 음수는 **32비트2의 보수**이며 Hex(-1)은FFFFFFFF다. CInt로 만든 값도 별도16비트 Variant 하위 형식을 갖지 않는다. 64비트 진수 변환은 지원하지 않는다.

Str는 절댓값이1보다 작으면 소수점 앞0을 생략한다. 예를 들어0.5는 ` .5`, -0.5는 `-.5`다. 0이 아닌0.0001 미만은 정확한 native 값의 지수 표기를 사용한다. 0.000001은 ` 1E-06`,0.000099는 ` 9.9E-05`다. 그 밖에는 고정 점 소수를 쓰며 전체 중간 범위±9조와 소수6자리를 보존한다. VBA Double의 유효 숫자 손실·일반 서식 전체를 재현하지 않는다. 선행 공백이 필요 없으면 CStr 또는 Format을 사용한다.

## Val 입력

- ASCII 공백·탭·CR·LF를 문자열 전체에서 제거한 뒤 읽는다. `1 2.3h`는12.3이다. 쉼표·통화 기호는 숫자 기호가 아니며 첫 숫자도 읽지 못하면0이다. `1,234`는1, `$12`와빈 문자열은0이다.
- 소수점은점이며 앞뒤 정수 부분을 생략할 수 있다. `1.`, `.5`를 받는다. e/E/d/D 지수와 부호도 받는다. 지수 뒤 숫자가 없으면 그 앞의 숫자까지만 읽는다. 지수는±10000까지다.
- 소수 접두부는 부동소수점을 거치지 않고 정확한 십진 정수 연산으로 소수6자리까지 반올림한다. 절반은0에서 멀어지는 방향이다. `1.2345675`는1.234568, `-0.0000005`는-0.000001이며 더 작은 값은0이 될 수 있다. 반올림 전의 실제 절댓값이9조를 넘으면 오류다.
- `&H`/`&h`·`&O`/`&o`는 각각16/8진수 접두부다. 유효 숫자를 읽다가 해당 진수에 없는 문자를 만나면 멈춘다. 부호를 접두부 앞에 붙이면 숫자를 읽지 못해0이다. 진수 상수는 표현식 리터럴로 추가하지 않았으므로 Val 문자열로 입력한다.
- 진수의 기본 부호 폭은 값이65535 이하면16비트, 그 밖에는32비트다. `Val("&HFFFF")`는-1이며 선행0을 추가해도 같다. 접미사 `&`를 붙이면32비트로 읽어65535가 된다. Hex/Oct와32비트 왕복할 때는 이 접미사를 명시한다. 입력 비트는최대FFFFFFFF다.
- `%`는16비트, `&`는32비트 정수 형식 접미사다. 소수 접두부에서는 소수점·지수가 없는 정수 표기에만 지원한다. `50%`는50이고 `50.5%`·`1e2%`는오류다. 진수의 `%`는 해석한 부호 있는 결과의16비트 범위를 검증한다. `#`는 native 소수6자리 규칙을 유지한다.
- `!/@/$/^` 형식 접미사는 명시적으로 거절한다. 문자열의 어느 곳에 있든 오류가 되는 것은 아니며 숫자 접두부 바로 뒤에서 접미사로 인식했을 때 적용한다. 전체 VBA의 Single/Currency/String/LongLong 강제 변환은 구현하지 않는다.

Val의 입력은 문자열이고 최대4096bytes다. 숫자·날짜를 암묵적으로 문자열화하지 않는다. Null은 기존 native 규칙대로 전파하며 모든 인수를 평가한다. 잘못된 형식/범위와 미설정은 구분하고 저장된 스냅샷으로 대체하지 않는다. Val은 시간·통화 환산 함수가 아니다. 예를 들어12.5h에서 얻은12.5를 분750으로 자동 바꾸지 않는다.

최종 Number·Cost·Duration 필드에는 기존 각 형식의 범위를 적용한다. 중간32비트 값이나9조가 최종 Number 범위보다 클 수 있으며 이 경우 Text/CStr로 확인하거나 목적에 맞게 식을 구성한다.

## 저장·화면·교환

활성 Str/Val/Hex/Oct 또는 그 전체 보관 사본이 있으면 조건부 schema57이다. 이전 태그의 활성 호출은 거절하며 비활성 원문은 기존44부터 자동 활성화 없이 읽는다. 새 native 필드는 없다. 기준선·시나리오·일정 채택·통화/ID 이력·복구·실행 취소/다시 실행·읽기 전용을 연결한다. 다른 기능과 기존 문서의 최소 저장 버전은 유지한다.

예시5개와 비동기 미리보기·저장/취소·문서 변경 검증을 제공한다. 네 범위·요약/배정 전파·native 숫자 식을 사용한다. 통화 전환은 원래 Cost 입력을 환산한 뒤 Str 결과를 다시 계산하며 식의 숫자 상수나 텍스트 단위를 환산하지 않는다.

XML은 정의·참조 이름과 현재 값을 교환하고 XER는 정적 값을 기록한다. XLSX/PDF는 결과·정의·오류/미설정을 기록한다. Str의 선행 공백은 native·XML·XER·XLSX에서 보존한다. XML에는 native 비활성 설정이 없어 지원 식을 재가져오면 활성화될 수 있다. 전체 설정·원본 이력은 source.ppm을 보관한다.

의미를 확인한 원문은 Microsoft의 [Project 함수 목록](https://support.microsoft.com/en-us/project/project-functions-for-custom-fields-in-project-desktop), [Str](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/str-function), [Val](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/val-function), [Hex](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/hex-function), [Oct](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/oct-function)이다. 위의 고정점·접미사·32비트 제한은 이 앱의 명시 지원 부분이며 전체 VBA/NLS·실제 제품 왕복의 동등성을 주장하지 않는다.
