# 새 XER 버전의 일정·WBS·달력 채택

2026-11-08 · XSA-01~06 · GAP-09. **파일 → 새 XER 일정·WBS·달력 채택…**에서 후속 XER의 지원되는 계획 투영을 현재 프로젝트에 명시적으로 채택한다. [재무 원본 재연결](xer-source-relink.md)·[통화/자원 전환](xer-source-conversion.md)과 별개다. 원본 실적을 현재 원장에 이관하는 작업은 포함하지 않는다.

## XSA-01 원본·작업 연결

UTF-8/Windows-1252 XER 파일과 프로젝트를 선택하고 원본 이름·SHA256·프로젝트 ID·원본 시작일/상태일, 교환 진단을 검토한다. 기존 XER reader의 지원 부분과 명시적 손실 진단을 사용하며 native 입력으로 보존한다. 상태일·실적·외부 날짜를 채택 과정에서 관측값으로 생성하지 않는다.

같은 작업 ID를 우선 후보로, 없으면 유일한 동일 이름을 후보로 제시한다. 중복 이름은 추정하지 않는다. 모든 원본 작업에 현재 작업·새 작업 추가·제외 중 하나를 명시한다. 기존 대상은 일대일이며 작업 ID를 유지한다. 새 작업은 새 ID를 발급하고 별도 확인 후 추가한다. 제외한 원본 작업은 현재의 작업을 삭제하지 않는다. 채택할 작업의 선행도 모두 연결해야 하며 누락 간선을 조용히 제거하지 않는다.

## XSA-02 독립 채택 범위

**일정**은 연결 작업의 이름·계획 기간·선행 종류/지연·제약/마감·계획 작업 유형/공수·분할과 프로젝트 시작일을 채택한다. XER reader의 기간 기반 투영과 그 진단을 따른다. 현재 task 속성/사용자 필드는 유지하며 새 작업에 원본 분류 사전·원가·자원 배정을 추정해 붙이지 않는다. 기존 고정 공수/단위 작업을 원본의 고정 기간 투영으로 바꾸는 경우 전후 유형·공수를 표시한다. 새 작업 추가는 일정 채택과 함께 사용한다.

**WBS**는 원본 계층을 별도 ID로 추가하고 연결 작업의 소속을 바꾼다. 현재 WBS와 로컬 작업의 소속은 유지한다. 채택본은 새 ID 공간을 사용하므로 기존 로컬 계층을 같은 이름/ID로 덮어쓰지 않는다. 반복 채택 시 이전 계층을 자동 삭제하지 않는다.

**달력**은 원본의 평일·근무 구간·휴일 정의를 별도 ID로 추가하고 연결 작업에 배정한다. 프로젝트 기본 달력·휴일도 채택하므로 기본 달력을 상속하는 로컬 작업에 영향을 줄 수 있다. 현재 자원/다른 작업이 참조하는 기존 달력 정의는 바꾸지 않는다. 미선택한 범위는 기존 입력을 유지하고 새 작업의 미선택 WBS/달력은 프로젝트 루트/기본값을 사용한다.

## XSA-03 계산·원장 보존

기간과 기존 배정 구간 불일치, 참조 누락·중복/ID 충돌, 선행 순환, 계산할 수 없는 제약/달력은 거절한다. 현재 공수·배정 구간을 맞추기 위해 관측값이나 배정률을 임의로 줄이지 않는다. 일정/달력 채택 후 native 공수·달력 엔진으로 계획 날짜를 검증한다. WBS만 채택할 때는 계획이 미완성인 문서도 구조 유효성을 검증해 허용한다.

현재에만 있는 작업과 간선, 자원·역할/자재·배정·단가·고정비, 통화·상태일, 사용자 필드/Steps·지원 활동 정의, 기준선·진행/원가/날짜별 관측 원장, 사용자 기간 마감·외부 EV/PV 채택, 기존 XER 최초 원본/정정/병합 이력은 보존한다. WBS 이동이나 달력/기간 변경에 따른 향후 계획 계산값은 바뀔 수 있다. 평준화 선택은 해제하고 기존 결정 원장에 해제 근거를 남긴다.

## XSA-04 미리보기·원자 제출

미리보기는 모든 현재/신규 작업의 계획 기간, 시작/완료, WBS·달력, 선행 종류/지연, 계획 유형·공수를 전후로 표시한다. 기존 날짜는 기준선이 아닌 채택 직전 현재 계획의 재계산값이다. 원본 연결·범위·작성자/사유가 바뀌면 미리보기와 확인을 무효화한다. 확인한 결과만 단일 revision으로 제출한다.

파일 읽기·계산은 worker에서 실행한다. 닫기·취소·읽기 실패·문서/revision/session 변경·권한 회수/읽기 전용에는 제출하지 않는다. 채택은 불변 계획 이력으로 등록하며 일반 undo로 지우지 않는다. 채택 후 일반 편집/undo는 계속 사용할 수 있다. 읽기 전용 문서에서도 저장된 채택 이력과 전후 계획을 조회할 수 있다.

## XSA-05 저장·재실행·교환

채택 이력이 있으면 schema32다. 원본의 typed PlanInput·파일 지문/프로젝트·시각·교환 진단, 연결표·범위·확인·작성자/사유·기록 revision, 전후 PlanInput을 보존한다. 재열기 때 원본과 직전 계획에서 채택을 재실행해 저장된 결과와 대조한다. 채택 직후 현재 계획 및 연속 revision의 계획 연결도 검사한다. 독립 사본/복구는 기존 새 문서 계보를 적용하면서 기록을 유지한다.

원본 XER 전체 바이트는 선택한 파일을 별도로 보관한다. 채택 이력이 없는 이 기능만 있는 기존 schema32 writer는 유지한다. 후속 원장 ID 이관은 schema33이며 미지원 미래34를 거절한다. 기존 XER16MiB/native64MiB·작업/자원10,000개 등 각 계획 한도를 유지하며, 채택 이력128건·원본/전후의 작업/WBS/달력/자원/배정 합계300,000행, 교환 진단1MiB를 제한한다.

XER 내보내기는 채택한 현재 일정·WBS·달력을 사용한다. 채택 이력은 `source.ppm`에 보존하고 교환 보고의 `actualCosts.scheduleAdoptionCount`에 건수를 기록한다. 기존 재무 집계가 일정 변경으로 현재 투영과 달라지면 기존 stale 원본 규칙을 적용한다. 재무 원본 병합/재연결을 별도로 검토할 수 있으며 현재 원장을 자동 이관하지 않는다.

## XSA-06 검증

전체 회귀, 원본/원장/기준선 보존·구조/ID 재실행·손상 schema, 독립 근무분/선행 날짜 oracle·XER 판독, Windows 기본/800×600 UI의 근거는 [실행 기록](validation/xer-schedule-adoption-2026-11-08/README.md)에 남긴다. 관측 원장 ID 변경은 별도 [명시 이관](ledger-id-migration.md)에서 지원한다. 실제 P6 재계산/재저장은 별도 범위다.
