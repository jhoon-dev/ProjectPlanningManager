# 조직·포트폴리오·협업·위험·자동화 native 계약

2026-11-05, GAP-13/14의 로컬 운영·분석 증분이다. 서버 운영이나 외부 제품 동등성 완료를 뜻하지 않는다.

## 사용 경로와 운영 경계

작업공간 창 → **조직·포트폴리오·협업·위험·자동화**에서 설정한다. EPS/OBS, 구성원, 역할, 포트폴리오와 위험 등록부의 표를 편집하고 **설정 적용**, **작업공간 저장**을 실행한다. 프로젝트의 미저장 변경은 먼저 저장해야 한다. 각 표의 ID 참조는 아래 프로젝트·작업 ID 목록에서 확인한다. 초기 설정에는 전체 범위 `owner`가 한 명 이상 필요하다. 구성원 전환으로 현재 로컬 프로필을 선택한다. 재열기 시 구성원은 선택하지 않은 상태이며 명시적으로 선택한다.

이 기능은 같은 데스크톱 세션에서 역할별 업무 흐름을 점검하는 로컬 정책이다. 구성원 선택은 인증이 아니며 OS 파일 권한·사용자 신원 인증·서버 권한 검증·암호화·변조 방지 원장을 제공하지 않는다. 파일을 직접 열거나 변경할 수 있는 사용자를 이 정책으로 격리하지 않는다. 네트워크 리스너와 서버/계정을 요구하지 않는다.

## 조직·역할·협업

EPS/OBS는 독립된 계층이며 같은 유형끼리만 부모를 연결한다. 순환·고아·중복 ID를 거부한다. 구성원은 OBS, 프로젝트 포트폴리오는 EPS와 책임자를 선택적으로 참조한다. 프로젝트 ID는 작업공간 참조를 사용한다.

| 역할 | 범위 | 조회·의견/요청 | 프로젝트 편집 | 요청 승인/반려/해결 | 작업공간 설정 |
|---|---|---|---|---|---|
| owner | 전체만 | 가능 | 가능 | 가능 | 가능 |
| editor | 전체 또는 특정 프로젝트 | 가능 | 가능 | 불가 | 불가 |
| reviewer | 전체 또는 특정 프로젝트 | 가능 | 불가 | 가능 | 불가 |
| viewer | 전체 또는 특정 프로젝트 | 가능 | 불가 | 불가 | 불가 |

권한은 합집합이며 미지정 구성원/프로젝트의 변경은 거부한다. 프로필이 전혀 없는 기존 작업공간의 단일 사용자 동작은 유지한다. 문서 편집·undo/redo·저장 및 준비된 편집의 최종 적용도 현재 역할을 확인한다. 구성원/설정 변경은 문서 세션을 갱신하여 이전 비동기 편집을 무효화한다. 읽을 수 있는 프로젝트를 별도 파일로 복사하는 기존 SaveAs 흐름은 유지한다.

협업은 `comment`, `request`, `approve`, `reject`, `resolve`의 추가 전용 기록이다. 프로젝트/작성자/내용/시각/관측 revision을 저장한다. 처리 기록은 앞선 같은 프로젝트 요청과 같은 revision을 참조하며 요청 하나에 처리는 한 번이다. UI는 열린 원본의 현재 revision도 검사한다. 승인 기록이 기준선 승인이나 이후 revision의 승인을 자동 생성하지 않는다. 기록의 undo·수정·삭제는 제공하지 않는다. 설정 변경의 구성원·시각·구성 해시와 GUI 자동화 실행의 요청 ID·해시·원본 revision은 운영 감사에 추가된다. 이 감사는 로컬 증거이며 디지털 서명은 아니다.

## 포트폴리오

프로젝트당 포트폴리오 한 개, 통화, 최소 화폐 단위 예산, 책임자, EPS, 우선순위 0~100을 저장한다. KRW/USD/EUR/JPY를 지원한다. 집계는 포트폴리오×통화별로 나누며 환산하지 않는다. 등록 프로젝트 수·열린 프로젝트 수·정상 계획 CPM 수·열린 위험 수·로드된 정상 일정 중 마지막 완료를 함께 표시한다. 닫힌/미완성 프로젝트를 0 기간이나 정상 완료로 간주하지 않는다. GUI 집계 대상은 현재 구성원에게 조회 권한이 있는 프로젝트다. 조직별 투자 최적화·수요/용량 최적화는 후속이다.

## 위험·확률 일정

위험은 프로젝트·작업의 qualified ID, 책임자, open/closed 상태, 삼각 분포의 낙관/최빈/비관 **전체 작업 기간(근무 분)**, 발생 확률(0~10000 basis points), 상관 그룹을 갖는다. 열린 위험은 작업당 하나를 지원한다. 위험이 발생하면 표본 기간을 사용하고, 발생하지 않거나 위험이 닫혔으면 원래 계획 기간을 사용한다. 위험이 없는 작업은 고정한다. 비용 위험이나 추가 지연량으로 해석하지 않는다.

`0 ≤ a ≤ m ≤ b ≤ 5,000,000`이며 U가 균등분포일 때 `U < (m-a)/(b-a)`이면 `a + sqrt(U(b-a)(m-a))`, 그 밖에는 `b - sqrt((1-U)(b-a)(b-m))`을 정수 분으로 반올림한다. a=b는 상수다. RNG는 명시적인 SplitMix64와 상위 53bit [0,1) 변환이다. 위험 ID 순으로 처리한다. 같은 그룹은 반복마다 발생용 U와 기간용 U를 각각 공유하여 완전한 양의 순위 상관을 모델링한다. 빈 그룹은 독립 표본이다. 임의 Pearson 상관 행렬이나 음의 상관을 지원한다고 표시하지 않는다.

입력과 seed가 같으면 같은 결과를 만든다. 각 표본은 기존 native `calculatePlan`으로 계산한다. 고정 기간·미분할 계획만 지원하며 기간 미정, 고정 공수/단위, 지원 활동(LOE/WBS Summary), 채택 평준화, 변동 작업의 기간별 배정 구간은 사전 차단한다. 실제/잔여 일정, 날씨 달력의 확률 변경, 자원 평준화의 확률 결과는 후속이다. 결정론 계획이 정상이어야 하며 표본 중 하나라도 제약 충돌/계산 실패이면 분위수를 게시하지 않는다. 결과는 원본을 변경하지 않는다.

반복 2~10,000, 작업 수 10,000 이하, 작업×반복 2,000,000 이하이다. 결정론 완료, 원본 ID/revision, 모델 버전, seed/반복 수, 최근접 순위 `ceil(n*p)-1` P10/P50/P80/P90, 작업별 임계 빈도, 선택한 마감 이내 표본 비율을 제공한다. 첫 절반/뒤 절반 표본의 P50 차이를 프로젝트 근무 분으로 표시한다. 이 값은 표본 안정성 참고치이며 수렴 보장이나 신뢰구간이 아니다. UI는 백그라운드 계산·취소와 원본/역할 변경 시 결과 게시 차단을 지원하고 텍스트로 출처를 포함해 저장한다.

## JSON API·자동화

`PPM-Automation`은 Qt Core 기반 로컬 명령줄 API다. GUI의 JSON 자동화 탭도 동일한 요청 해석기와 Document 준비/적용 명령을 사용한다. 외부 프로그램/셸 실행, HTTP 서버, 반복 스케줄러는 제공하지 않는다.

```powershell
# 안정 ID와 현재 revision 조회
.\PPM-Automation.exe --project C:\plans\project.ppm
# 검증/미리보기: 파일 저장 없이 종료
.\PPM-Automation.exe --project C:\plans\project.ppm --request C:\plans\request.json
# 한 번의 원자적 파일 교체로 저장
.\PPM-Automation.exe --project C:\plans\project.ppm --request C:\plans\request.json --apply
# 로컬 작업공간 역할 정책을 명시적으로 사용
.\PPM-Automation.exe --project C:\plans\project.ppm --request C:\plans\request.json --apply --workspace C:\plans\team.ppmworkspace --actor editor-id
```

```json
{
  "format": "PPM-AUTOMATION-1",
  "documentId": "project-id",
  "revision": 42,
  "requestId": "batch-2026-11-05-01",
  "operations": [
    {"taskId": "task-id", "name": "검토", "durationMinutes": 960}
  ]
}
```

요청은 1MiB, 변경 1~10,000개, 안정 작업 ID마다 한 번이며 이름/기간 변경을 지원한다. 기간 null은 명시적 미정이다. 알 수 없는 키, 잘못된 형식·수·참조, 중복 ID, source revision 불일치와 읽기 전용을 거부한다. 실적·승인·원장 등 다른 입력을 JSON으로 직접 덮어쓰지 않는다. 마지막 변경 하나가 잘못돼도 전체 요청은 적용하지 않는다. 미리보기에는 원본 ID/revision·요청 ID/원본 바이트 SHA256·변경 목록을 표시한다. 적용은 기존 Document의 단일 batch 명령으로 revision 한 번과 undo 한 번을 사용한다. 적용 전 원본/session/취소/역할을 다시 확인한다.

GUI에서 미리보기 입력을 바꾸면 폐기되며, 적용은 메모리에 수행한다. 프로젝트 저장과 작업공간의 감사 저장은 각각 명시적으로 수행한다. 두 파일의 분산 트랜잭션은 제공하지 않는다. CLI는 기존 native 파일 lease·fingerprint 검사·QSaveFile을 사용하며 실패 시 기존 파일을 보존한다. stdout JSON receipt는 요청 해시·원본/결과 revision·성공 여부를 제공하고 exit 0/1을 사용한다. 실행 기록을 남기려면 호출 측에서 stdout을 보존한다. 상태를 바꾼 요청의 재실행은 오래된 revision으로 거부한다. requestId만으로 영구 중복 제거를 보장하지 않으며 no-op은 revision을 올리지 않는다. 미리보기도 쓰기 lease를 일시 사용해 충돌한 편집을 거부한다. `--workspace/--actor`는 쌍으로 사용하고 해당 파일의 ID/경로/역할을 확인한다. 정책 없는 로컬 호출은 기존 파일 접근 권한을 따른다.

## 파일·검증·한계

조직 확장은 `.ppmworkspace` schema 3의 선택적 governance이다. 기존 1/2 파일과 governance 없는 저장 형식을 유지한다. 프로젝트 `.ppm` schema와 복구 형식은 바꾸지 않는다. 기존 workspace SHA256·바이트 한도·외부 변경 확인·원자 저장을 공유한다. 계층/참조/금액/확률/기록·JSON의 불명 키/소수 정수를 검사한다. 조직·구성원 각 1,000, 역할/협업/감사 각 10,000, 위험 1,000, 포트폴리오 100개 한도다. 구성원 선택은 저장하지 않는다.

검증은 governance_risk_automation_contract와 governance_ui, workspace/parser/Document 기존 회귀 및 독립 Python reader를 사용한다. 삼각 분포 분석식·퇴화 분포의 정확 CPM·공통 순위 꼬리·seed 재현·마감 빈도·취소·불변 입력과 revision/역할/마지막 잘못된 변경의 원자성을 대조한다. [검증 기록](validation/organization-risk-automation-2026-11-05/README.md)을 따른다.

서버 인증/동시 병합/동기화, 조직 운영 배포, 타임시트·실제 승인 통합, 일반 상관 행렬·확률 자원/비용/날씨, 다중 파일 원자 채택, HTTP API·스케줄러·외부 서비스 연계는 독립 후속이다. 다른 OS·스토어 패키지의 실제 실행은 해당 환경 검증으로 남긴다.

2026-11-05 후속 요청으로 서버 인증·실시간 변경 동기화·HTTP API·영속 주기 실행을 별도 선택 서비스로 구현했다. [서버 계약과 실행법](../server/README.md)을 따른다. 위 로컬 역할 프로필/CLI의 운영 경계는 그대로 유지하며 서버 신원과 혼동하지 않는다.
