# 날짜별 잔여 공수

2026-11-06 초기 범위. 자원 → **날짜별 잔여 공수…**. DRW-01~05, GAP-04/11, PRD-05/06/07/08, J-05/08/09/14/16에 연결한다. 기간 확정·고정 기간·공수 역산 비활성인 작업/자원 배정에 적용한다. Steps는 허용한다. 2026-11-08 후속으로 [FixedWork/FixedUnits 날짜 고정 잔여 목표](dated-effort-targets.md)를 추가했다. 공수 기준에서는 아래의 기간 유지/총공수 가변 규칙 대신 명시 잔여 총공수를 유지하고 완료를 역산한다. 지원 활동의 직접 잔여 공수 역산은 별도 범위다.

## 입력 의미

상태일을 먼저 설정하고, **평준화 채택 전 현재 논리 잔여 예측**을 기준으로 입력한다. 날짜별 목표 시간(h)은 소수 4자리까지이며 1/100 자원분 단위로 반올림한다. 빈칸은 기존 계획 곡선의 잔여 구간을 사용하고, 명시한 0은 해당 날짜에 수요가 없음을 뜻한다. 기록된 목표 시간은 고정 날짜에만 적용한다. 상태일 당일도 상태 시각 이후의 실행 구간에 자원 가능 시간이 있을 때 입력할 수 있다.

입력은 `RemainingWorkPlan{taskId, resourceId, statusAt, days[{date,workUnitMinutes}]}`에 저장한다. 배정당 1,024일, 프로젝트 전체 100,000일/10,000배정까지다. 날짜는 정렬·비중복, 입력 기준 상태일 이후여야 한다. 현재 작업/배정과 정의를 참조하고 금지된 작업 유형 변경·배정 해제·삭제는 먼저 날짜 입력을 해제해야 한다.

현재 작업·자원 달력, 각각의 휴일과 수동 중단의 교집합을 사용한다. 명시한 달력은 기본 달력 휴일을 자동 상속하지 않는 기존 정책을 유지한다. 일별 목표 W를 그 날짜의 남은 교집합 근무분 N에 대해 q=W/N, r=W%N으로 나누고 처음 r개 실제 근무분에 q+1%, 나머지에 q%를 배정한다. 생성한 실행 구간을 정수 공수로 검산한다. 양수 목표에 N=0, 필요 배정률 100,000% 초과는 거절한다. 자원 가용률로 묵시적으로 잘라내지 않으며 과부하는 부하 분석에서 별도 진단한다.

날짜별 목표는 원래 계획 구간/배정률을 변경하지 않는다. 계획 예산·기간·실제 시작/완료·진척·실제공수/원가·관측 기간 원장·기존 기준선은 보존한다. 이는 **미래 배정 수요 입력**이며 실제 실적 추정이나 작업 잔여 기간/공수 보고의 자동 정정이 아니다. 기간 기준의 미래 총공수는 명시 날짜 목표와 나머지 날짜의 기존 곡선을 합한 값이다. 실행 구간이 늘어나 새 날짜가 생기면 미입력 날짜에는 기존 곡선을 사용한다. 공수 기준의 총공수/완료 규칙은 위 후속 계약을 따른다.

## 재검토와 적용

상태일이 바뀌거나 입력 날짜가 현재 잔여 실행 구간 밖에 놓이면 잔여 예측을 Conflict로 표시하고 원인을 제시한다. 목표를 새 날짜로 옮기거나 0으로 대체하지 않는다. 자원 달력 변경 후에도 같은 날짜에 목표를 충족할 수 있으면 배정률을 다시 나누며, 근무시간이 사라지면 재검토를 요구한다. 계획 계산은 원래 입력으로 계속 조회할 수 있다.

입력 창은 현재 실행 날짜와 저장된 날짜의 합집합을 보여준다. 실행 밖 날짜도 숨기지 않는다. 잘못된 과거 목표는 빈칸으로 해제하거나 선택 배정/전체 날짜 입력을 명시적으로 해제할 수 있다. 다른 배정의 오래된 입력이 있어도 한 배정씩 새 상태일로 검산·수정할 수 있으며, 모든 입력이 유효해질 때까지 전체 잔여 예측은 충돌 상태를 유지한다.

**검산 미리보기 → 문서에 적용**을 구분한다. 미리보기는 문서를 바꾸지 않고, 목표 수정은 준비된 결과를 무효화한다. 적용·해제는 기존 PreparedEdit의 현재 권한·문서 ID/revision/session 검사와 한 번의 undo/redo를 따른다. 취소·닫기·stale·권한 철회는 미적용이다. 읽기 전용은 조회만 가능하다. 저장/복구/사본은 조건부 schema22이며 구 schema에서 새 입력을 거절한다.

## 일정·부하·원가·출력

공통 TaskExecution의 잔여 실행 구간으로 통합한다. Usage 잔여 공수/유효 단가 원가, 자원 수요/공유 부하·잔여 보고서는 같은 구간을 사용한다. 기존 EVM의 budget-remaining/cpi/cpi-spi EAC 공식은 대체하지 않는다. 잔여 계산 엔진 `jobs-dated-remaining-1.0`, 평준화 정책 `serial-dated-remaining-v1`을 사용한다. 이 입력이 없는 과거 계산의 의미와 엔진은 유지한다.

논리 잔여 여유는 각 후보 실행 구간에서 날짜별 목표 충족을 검산한다. 자원 평준화도 날짜를 옮기지 않고 후보의 실제 수요를 검사하며 불가한 과부하는 충돌로 남긴다. 2026-11-06 후속으로 **날짜 고정 수요의 자원 순서 여유/임계와 증인**을 추가했다. [후보별 정확 검산·총/자유여유 계약](dated-resource-float.md)을 따른다. 평준화 채택은 새 정책으로 검산하고 입력 수정 시 무효화/결정 원장·undo를 따른다.

기존 승인 기준선은 변경하지 않는다. 새 기준선의 계획 입력/예산에도 현재 잔여 목표를 합산하지 않는다. 평준화 시나리오는 날짜별 미래 입력을 따로 동결하고 당시 상태일·진척과 함께 재현한다. 보고서에는 날짜별 입력 명세를 추가하며 XLSX 공수는 숫자 셀이다. XML/XER는 미지원 손실을 공개하고 source.ppm에 보존한다.
