# XER 집계 편집·날짜별 배분

2026-11-07 사용자 지정 후속 증분이다. [원본 스냅샷](xer-financial-snapshots.md)은 그대로 보존하고 정정한 집계·명시한 날짜 배분을 별도 불변 이력으로 제출한다. 실제 날짜를 관측하지 않은 집계를 자동으로 배분하지 않는다.

후속 [원본·현재 원장 병합](xer-ledger-merge.md)을 구현했다. 문서/원장이 달라졌다면 병합 메뉴에서 대조·검토한 새 집계를 제출한 뒤 이 편집기를 다시 연다. 병합은 기존 실제와 누계 AC를 바꾸지 않는다. 일반 정정만 있으면 schema26, 병합 이력이나 독립 외부 요약/경비의 분리 구간이 있으면 schema27이다.

## XAE-01 집계 정정

**파일 → XER 집계 편집·날짜별 배분…**에서 작업 누계 AC, 배정별 정규/초과근무 공수·원가, 자원 재무기간의 시작/종료·공수·원가, 작업 재무기간의 인력/장비 공수와 비용 종류·경비·외부 EV/PV를 편집한다. 작업/자원 ID·이름·종류와 원본 출처는 바꾸지 않는다. 기존 기간 행의 소유자도 바꾸지 않는다. 잘못된 값은 미리보기 검증에서 거절하며 어떤 기록도 반영하지 않는다.

원본과 문서가 일치하는 상태에서 시작한다. 첫 제출 이후에는 최신 정정 집계와 현재 문서가 일치해야 한다. 다른 창이나 편집에서 문서/원장을 바꿨다면 자동으로 합치지 않고 제출을 차단한다. 계획 변경을 undo해 내용이 돌아오면 다시 일치할 수 있다. 저장/독립 사본은 내용이 같으면 정정 집계 재내보내기를 유지한다.

공수는 시간 또는 `6001u` 같은 정확한 정수 `%·분`이다(6000u=1h). 금액은 프로젝트 통화 최소 단위로 검사한다. 빈칸은 미보고, 0은 명시 0이다. 배정 누계는 모든 자원 기간 합계 이상이어야 하고 자원 누계 원가와 작업 경비 명세는 작업 AC를 초과할 수 없다. TASKFIN의 자원 비용/공수·외부 EV/PV는 별도 외부 요약이며 내부 AC/EV/PV에 추가하지 않는다. 서로 다른 요약/자원 보고를 자동으로 일치시켜 덮어쓰지 않는다.

## XAE-02 미지정 잔량을 기간으로 지정

배정 누계 탭에서 배정을 선택하고 새 시작/종료 날짜를 입력한 뒤 **배정 잔량 기간 추가**를 누른다. 정규+초과근무 누계에서 기존 자원 기간 합계를 뺀 공수·원가가 새 기간에 들어간다. 추가한 행도 수정할 수 있다.

작업 누계 탭에서는 **작업 직접비 잔량 기간 추가**를 사용한다. 작업 AC에서 자원 누계와 기존 경비 명세를 뺀 금액을 새 작업 경비 기간으로 지정한다. 이는 기존 누계 안의 재분류이며 신규 지출을 더하는 동작이 아니다. 신규 지출이면 작업 AC와 관련 누계도 사용자가 명시 정정한다. 기존 소유자의 기간과 겹치거나 상태일 이후인 구간은 거절한다. 기존 기간 철회는 값을 비우고 해당 날짜 배분을 비우는 정정으로 남긴다.

## XAE-03 명시 날짜와 정수 배분

재무기간 집계 탭에서 행을 선택하고 `YYYY-MM-DD,비중`을 한 줄씩 입력한다. 비중은 1~1,000,000의 정수다. **선택 기간의 날짜·비중 적용**으로 초안에 반영한다. **선택 기간의 모든 날짜에 균등 배분**은 366일 이하 구간의 모든 civil 날짜를 비중1로 채운다. 휴일/비근무일도 포함하므로 사용자가 날짜를 확인하고 필요하면 줄을 제거한다. 원본의 일 단위 명세는 처음부터 해당 날짜의 비중1로 표시한다. 여러 날짜 집계에는 날짜를 자동 생성하지 않는다.

각 기간의 알려진 공수/원가 전체를 비중 합계로 나눈 뒤 정수 나머지가 큰 날짜부터 최소 단위를 하나씩 배분한다. 나머지가 같으면 빠른 날짜가 우선이다. 입력 행 순서와 관계없이 같은 결과다. 큰 금액도 중간 곱셈이 넘치지 않도록 몫과 나머지를 분리한다. 공수와 원가는 각각 정확한 총액을 유지하며 미보고 값은 미보고로 남긴다.

예: 공수12001u·원가7013센트를 날짜19일 비중1,20일 비중2로 나누면 공수4000/8001u, 원가2338/4675센트다. 날짜는 선택한 기간 안이어야 하고 중복 날짜/기간·범위 밖 날짜·0/음수/소수 비중은 거절한다. 현재 증분의 명시 배분은 전체1,000개 날짜 줄, 한 원자적 제출은 기존 날짜 철회를 포함해1,000개 원장 행을 제한한다.

## XAE-04 원장·원가와 원자적 제출

작성자·사유를 입력하고 **검증·배분 미리보기**를 누른다. worker가 모든 집계와 native 원장 대사를 검사한다. 검증된 날짜 행과 작업 누계 AC를 확인한 뒤 **미리본 집계·배분 제출**을 누른다. 초안이 바뀌면 이전 미리보기의 제출은 비활성화한다. 취소·닫기·권한/문서/session/revision 변경·검증 실패에는 기록을 반영하지 않는다. 읽기 전용에서는 제출할 수 없다.

원본 일 단위 명세 또는 직전 XER 정정이 소유한 원장 행만 교체한다. 다른 경로에서 입력한 같은 키의 실제와 충돌하면 거절한다. 같은 키에 차액을 더하지 않고 전체 값을 새 정정 기록으로 제출한다. 날짜 이동/배분 철회는 예전 날짜에 미보고 정정을 추가하며 원래 기록을 지우지 않는다. 같은 집계를 다시 제출해도 최신 배분을 중복 합산하지 않는다. 공수 배분은 실제 날짜·진척·잔여 일정·계획/기준선을 자동 변경하지 않는다.

`CostEntry`가 AC/EVM의 유일한 누계다. 날짜 원가와 집계는 포함 명세이며 추가 AC가 아니다. AC 변경은 명시 누계 보고로 기록하고 기존 물리 진척을 유지한다. 모든 과거/미래 상태일의 대사는 기존 [기간 실적 원장](period-actuals.md)의 규칙을 적용한다. 제출 이력은 일반 undo로 제거하지 않고 새 정정으로 변경한다. 이후 계획 편집 undo는 원장과 집계 이력을 보존한다.

## XAE-05 저장·조회·외부 교환

일반 정정만 있으면 조건부 schema26, 병합/독립 외부 요약·경비의 분리 중첩은27, [새 원본 ID 재연결](xer-source-relink.md) 이력은28이다. 일반 원본만 있으면25, 없으면 기존9~24 writer를 유지한다. 구 envelope의 새 의미/필드와 미래31을 거절한다. 저장/재열기·복구·독립 사본에 원본, 매 제출의 전체 정정 집계·날짜 비중·생성 원장 ID·작성자/사유/UTC/원본 문서/revision을 보존한다.

**XER 보존 재무기간·누계 조회…**는 최신 정정과 이력을 보여주며 **가져온 원본 집계 별도 조회**에서 원래 값을 확인할 수 있다. 이력은 최대128건이며 전체 정정 스냅샷의 작업/자원/배정/기간 합계300,000행과 native 파일64MiB·원장50,000기록 한도도 적용한다.

XER 재내보내기는 현재 문서와 일치하는 최신 정정의 정규/초과근무 누계·원본 또는 수정한 기간과 외부 요약을 쓴다. 날짜 배분은 native 원장에 보존하며 집계를 다시 날짜별 XER 기간으로 이중 출력하지 않는다. 재무기간 총액+작업 직접/미배분 원가는 작업 누계 AC와 대사한다. 다른 문서 편집 이후에는 현재 원장만 내보내고 집계 이력은 source.ppm에 보존한다. conversion.json의 `actualCosts.financialAdjustmentCount`와 `preservedFinancials`로 판정을 확인한다. XML은 원장·정정 전용 필드를 투영하지 않고 source.ppm 보존 진단을 표시한다.

## XAE-06 검증과 후속

`xer_financial_edit_allocation_contract`는 독립 기대값, 최대 금액·나머지·null/0, 원자적 실패·불변 이력·반복/이동/철회·AC-only, stale/취소/읽기 전용, schema26/복구/사본과 실제 편집기 미리보기·메뉴 연결을 검사한다. `scripts/verify-xer-allocation.py`는 별도 Decimal 배분 oracle, native/projection SHA256·TSV·고정 MPXJ16.10.0 reader로 다시 읽는다. [전체 회귀와 실행 증거](validation/xer-allocation-2026-11-07/README.md)를 보존한다.

원본과 달라진 현재 원장 병합은 후속 XFM-01~06에서 지원한다. 원본 소유자/통화·인력-장비 단위 전환, 내부 기간 EVM, MPP reader와 실제 Oracle P6 재계산/재저장은 후속 범위다. 외부 프로그램 왕복에서 native 날짜 배분·정정 이력을 복원하려면 source.ppm을 사용한다.
