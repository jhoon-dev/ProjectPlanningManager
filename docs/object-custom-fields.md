# 프로젝트·자원 사용자 필드 (GAP-03)

2026-11-10 [배정 사용자 필드](enterprise-assignment-udf.md)의 독립 사전/일괄 값 편집·보고와 schema37/복구를 추가했다. XML 기업 신원과 프로젝트 필드·XER 배정 교환은 새 계약을 따른다.

2026-11-05 후속 개발 계약. PRD-01/06/08, J-01/05/14에 연결한다.

- 작업 필드·코드는 그대로 유지하고 프로젝트 필드와 자원 필드 사전을 각각 별도로 둔다. 범위별 최대 64개, 네 형식(텍스트/소수 6자리 숫자/날짜/안정 ID 목록), 옵션 1,000개와 텍스트 16KiB 제한을 재사용한다. 같은 이름·ID도 범위가 다르면 별개다.
- 프로젝트에는 필드별 한 값, 각 로컬 자원에는 필드별 한 값을 둔다. 미설정·빈 텍스트·숫자 0을 구분한다. 이름/옵션 이름 변경은 ID 배정을 유지하고, 값이 있는 필드의 형식 변경과 참조 중인 정의/옵션 삭제는 원자적으로 거절한다. 다른 범위의 키·작업 코드 값을 혼합하지 않는다.
- 정의·값은 PlanInput의 일부로 기준선/시나리오가 동결한다. 현재 사전 삭제는 동결 사전에 영향을 주지 않는다. 작업 보기/열/그룹에는 프로젝트·자원 필드를 추가하지 않는다. 자원 삭제는 해당 현재 자원 값도 삭제하고 undo로 함께 복원한다. 관측 실적이 보호하는 자원은 기존 삭제 제한을 따른다.
- 프로젝트 메뉴에서 프로젝트 필드 정의/값을, 자원 메뉴에서 자원 필드 정의/값을 편집한다. 자원 값 화면은 복수 자원에 같은 값을 원자적으로 적용하고 현재 값·미설정을 조회한다. 읽기 전용은 조회만 가능하며 문서 ID/revision/session 변경 후 열린 입력을 적용하지 않는다.
- 일반 편집의 undo/redo·dirty·사본·복구를 지원한다. 기존 보수적 PlanInput 변경 규칙에 따라 활성 평준화는 무효화하고 결정을 보존한다. 필드 값은 CPM·공수·원가에 자동 합산하지 않는다. 2026-11-06 [숫자 계산식](formula-fields.md)과 [자원 그룹/필터·저장 보기](resource-views.md), 후속 [XML/XER UDF 매핑](external-udf-mapping.md)을 추가했다. 외부 형식의 스칼라 지원과 정적 투영·손실 계약을 따른다.
- 현재 입력 또는 기준선/시나리오에 새 사전/값이 있으면 schema16을 쓴다. schema1~15를 계속 읽고 새 데이터 없는 writer는 기존 버전을 유지한다. 구 schema의 새 필드는 거절한다. 복구 envelope1은 projectSchema16을 지원한다.
- 보고서에 프로젝트 필드와 자원 필드 명세를 추가한다. 프로젝트 값은 프로젝트 전체 자료로 명시하고, 자원은 전체 범위에서 미배정 자원도 포함하되 WBS 범위에서는 그 작업에 배정된 자원만 포함한다. 숫자는 XLSX 숫자 셀로 출력하며 기존 집계에 합산하지 않는다. XML/XER는 손실 진단과 native 원본 사본을 제공한다.

수용조건: 네 형식/미설정/정밀도/범위 격리·삭제 영향·다중 자원 실패 원자성·undo/dirty·기준선/시나리오·계산/원가 불변·schema/구버전·복구/사본·읽기 전용/오래된 입력·보고서 독립 판독 및 기존 전체 회귀를 검사한다. 실제 MSP/P6·다른 OS 검증은 별도로 남긴다.

[검증 기록](validation/object-fields-2026-11-05/README.md): 전체 CTest97/97·파서132 seeds·형식168파일·독립 reader8종 통과. 프로젝트/자원 입력 화면과 1만 자원 모델·일괄 적용·실행 취소 관측을 보존한다.
