## PCC-01 환율과 정밀도

KRW/JPY/USD/EUR을 지원한다. **원래 1통화 단위 = 분자/분모 대상 통화 단위**이며 분자·분모는1~1,000,000,000의 양의 정수다. 예를 들어 USD1=KRW1300이면1300/1이다. 실제 환율을 자동 조회하지 않으며 기준일·출처/근거·작성자·사유를 명시한다. 기준일은 환율의 근거이며 금액 날짜를 고르는 필터가 아니다. 과거·현재·미래의 해당 금액을 같은 환율로 재표현한다.

원래/대상 통화의 최소 단위 차이를 적용한다. USD/EUR은 소수2자리, KRW/JPY는0자리다. 부동소수점 곱셈 없이 정수 나눗셈으로 처리하고 ±9,000,000,000,000 최소 단위 범위를 검사한다. 반올림은 각 금액별로 정확히 절반이면0에서 멀어지는 방식이다. 별도로 **정확한 최소 단위만 허용**을 선택하면 나머지가 있는 금액을 거절한다. 미정과 명시0은 구분해서 유지하고 지원되는 음수 기간 EV/정정 차액도 부호를 유지한다.

## PCC-02 전환 범위

현재 계획·모든 승인 기준선 입력·저장 시나리오의 유효일별 자원 단가, 작업 고정비, 자재 단가·경비를 환산한다. 누계 원가와 날짜별 원장, 사용자 기간 예산/인정 EV 및 마감 당시 BAC/PV/EV/AC·날짜 배분 차액, 외부 EV/PV 채택의 명시 개시 누계도 환산한다. 기준선과 시나리오의 통화도 대상 통화를 사용한다.

원장/정정 ID·이전 보고/누계 링크·작성자/사유·원본 문서·기록 revision/시각·상태일/관측일, 실제/잔여 기간·공수·가용량/배정률·자원 종류·물리 진척·Steps·관계/달력/날짜는 유지한다. 기준선 계산 행은 다시 계산해 동결 날짜와 대조한다. 선택된 평준화는 기존 결정 원장에 invalidate 근거를 남기고 해제한다.

개별 입력/단가 환산 뒤 재계산한 합계와 원래 계산 합계를 한 번에 환산한 값은 반올림 순서 때문에 다를 수 있다. 마감 금액은 당시 동결 금액의 환산이며 새 단가에서 다시 산정한 마감값으로 바꾸지 않는다. 원장 배분이 누계를 넘거나 외부 집계/재실행·EV/PV 기간 연속성이 깨지는 경우에는 임의 잔액·새 실적을 만들어 맞추지 않고 전환을 거절한다.

다른 출발 통화의 금액에는 해당 환율이 필요하므로 단일 출발 통화로 설명되지 않는 입력은 거절한다. 사용자 숫자/단위·계산식 상수·자유 텍스트는 통화처럼 보이더라도 추정해서 고치지 않는다. 조직/포트폴리오 예산·다른 프로젝트·외부 원본 파일은 이 작업에서 변경하지 않는다.

## PCC-03 연결 재무와 원래 이력

최초·정정/병합 XER의 현재 연결 재무 투영, 배정별 병합 선택도 대상 통화로 환산한다. 재연결의 원래 `incoming` 입력과 기존 원본 변환 규칙은 그대로 유지하고 `incomingCurrencySteps`에 이번 환산 단계를 추가한다. 기존 변환과 이후 전환을 순서대로 실행하므로 여러 반올림을 하나의 합성 환율로 축약하지 않는다. 이전 원본의 동일 통화1/1·자원 종류 규칙은 환산된 입력의 통화에 맞춰 연결하며, 복합 이전 환율은 조용히 추정하지 않고 거절한다.

원본 파일·과거 투영 SHA256은 당시 출처로 유지한다. 현재 입력과 달라진 재무 투영은 stale 규칙을 따르고 별도 재무 병합으로 현재 투영을 다시 등록할 수 있다. XER 기간 배분·native 원장·원가와 재연결을 재검증한다.

과거 일정/WBS/달력 채택 및 ID 이관의 원래 스냅샷은 그때의 통화·금액으로 보존한다. 이번 전환 전/후의 전체 native 상태도 불변 이력으로 보존한다. 현재 금액은 대상 통화의 환산 투영이며 원래 작성자가 그 통화로 제출했다는 뜻이 아니다. 원래 제출/승인 값은 전환 전 원본 조회에서 확인한다.

## PCC-04 검토·제출·복구

검증과 금액 전후 표·저장 이력 조회 준비는 worker에서 실행한다. 표는 현재/기준선/시나리오·기록 ID/위치, 원래 통화·금액·대상 통화·환산 금액을 표시한다. 전후 원본 조회는 읽기 전용 전체 JSON을 제공한다. 환율·정책·근거/작성 정보가 바뀌면 준비 결과와 확인을 무효화한다.

명시 확인한 결과만 단일 revision으로 제출한다. 취소·닫기·문서/session/revision 변경·권한 회수/읽기 전용에는 제출하지 않는다. UI는 native 저장64MiB 한도에 여유를 둔 사전 크기 검사도 수행한다. 일반 실행 취소로 원래 전환 이력을 삭제하지 않는다. 추가 환산/복원은 새 전환 이력으로 기록하며 일반 계획 편집/undo는 계속 가능하다. 반대 환율로 다시 환산해도 이전 반올림으로 잃은 정밀도까지 복원되는 것은 아니다.

읽기 전용 문서에서는 저장된 전환 이력/원본을 조회할 수 있다. 저장·재열기·복구·독립 사본과 통화 전환/ID 이관의 교차 실행에서 이전 원본을 유지한다. 단순 통화 설정으로 단가·자재/경비·재무 이력을 재해석하는 경로는 차단하고 전환 메뉴로 안내한다.

## PCC-05 저장·보고·교환

전환 이력 또는 추가 XER 통화 단계가 있으면 조건부 **schema34**다. 기존1~33 최소 writer는 유지하고 구 envelope의 새 의미를 거절한다. 후속 날짜 고정 잔여 역산까지 포함한 현재 reader 상한은35·미지원 미래36이며 해당 새 의미가 전환 전후 원본에 있으면 schema35로 보존한다. `currencyConversions`는 `project-currency-v1`, 환율/정책/기준일/근거·확인/작성 정보·문서/revision과 전후 전체 스냅샷을 저장한다. 스냅샷 안에는 통화 전환/ID 이관 이력을 중첩하지 않고 루트 배열에서 각각 보존한다. 각 원본에서 환산을 재실행해 저장 결과의 모든 필드를 대조하고 연속 전환·전환 직후 루트도 검사한다. 사본의 새 문서 계보와 정확한 평준화 해제1건만 정규화한다.

전환 이력16건, 원본 재연결의 추가 통화 단계16건, 전후 주요 스냅샷 합계300,000행 및 기존 native/컬렉션 한도를 적용한다. 알 수 없는 필드·정수/확인/UTC 오류·중첩 이력·변조한 결과를 거절한다. SHA256은 무결성 검사이며 작성자의 디지털 서명은 아니다.

원가·기간 EVM·사용자 기간 보고와 XLSX/PDF에 프로젝트 통화 전환 이력/근거를 포함한다. XML/XER은 현재 대상 통화의 지원 투영을 내보내고 전환 전 원본/전후 이력은 `source.ppm`에 보존한다. XER 변환 보고의 `actualCosts.projectCurrencyConversionCount`에 건수를 기록한다. 보고서/교환만으로 원본 이력 전체를 대체하지 않는다.
