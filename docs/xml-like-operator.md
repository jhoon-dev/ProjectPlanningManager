# XML 계산식 Like 패턴 비교

2026-11-14 · XLK-01~06. `text Like pattern`을 작업·프로젝트·자원·배정 계산식에서 지원한다. 함수 호출이 아닌 이항 비교 연산자이며 결과는 Boolean이다. 편집기의 패턴 비교 예시 삽입·worker 미리보기와 표·요약·전파·저장/복구·XML/XER·XLSX/PDF를 연결한다.

| 패턴 | 뜻 | 예 |
|---|---|---|
| `*` | 문자0개 이상 | `"Alpha" Like "A*"` → True |
| `?` | BMP 문자1개 | `"가나다" Like "가?다"` → True |
| `#` | ASCII 숫자0~9 한 자리 | `"A1" Like "A#"` → True |
| `[abc]` | 목록의 문자1개 | `"b" Like "[abc]"` → True |
| `[a-z]` | 오름차순 범위 | `"b" Like "[a-z]"` → True |
| `[!0-9]` | 목록/범위 밖의 문자1개 | `"가" Like "[!0-9]"` → True |
| `[*]`·`[?]`·`[#]`·`[[]` | 특수 문자 그대로 | `"*" Like "[*]"` → True |
| `[]` | 빈 문자열 | `"x" Like "[]x"` → True |

XLK-01: 비교는 **대소문자를 구분하는 BMP 코드 포인트 기준**이다. `"A" Like "a"`는 False다. Unicode 정규화·언어별 정렬·ANSI 코드페이지·Option Compare Text는 추측하지 않는다. `#`은 ASCII만 의미하므로 아라비아/전각 숫자는 해당하지 않는다. 범위를 명시하면 `[가-힣]` 같은 BMP 범위도 쓸 수 있다. 보조 평면 문자·서로게이트·비정규/잘못된 UTF-8은 오류다. 전체 Microsoft Project/VBA/NLS 동등성을 주장하지 않는다.

XLK-02: 문자 목록은 첫 `]`에서 닫힌다. `]` 자체는 목록 밖에 쓰며 `[]]`는 `]`와 일치한다. `[!]`는 느낌표 자체, `[!!]`는 느낌표 이외 문자다. 하이픈은 범위의 가운데 표지이며 범위를 만들지 않는 위치에서는 그대로다. `[-]`, `[a-]`, `[a-b-c]`의 문자 하이픈도 지원한다. 여러 범위/문자가 섞인 목록은 합집합이다. 닫히지 않은 목록과 `[z-a]` 같은 역방향 범위는 오류다.

XLK-03: Null이 없으면 **패턴 전체를 먼저 검증**한다. 앞부분에서 불일치하거나 입력이 비어 있어도 잘못된 뒤쪽 패턴은 오류다. 예를 들어 `"x" Like "a["`와 `"" Like "["`도 오류다. VBA/.NET이 일부 경우 먼저 False를 반환하는 동작과 구별한다. 어느 피연산자가 Null이면 미설정이고 패턴 검증에 들어가지 않는다. 모든 피연산자를 평가하므로 `IIf(True,1,"x" Like "[")`도 오류다. 저장된0/777·임의0을 결과 대신 쓰지 않는다.

문자열 피연산자만 받는다. 숫자·Boolean·날짜는 문자열로 암묵 변환하지 않는다. 숫자는 `CStr`로 명시한다. Boolean 결과는 Flag에1/0, Text에True/False로 표시하며 최종 필드의 기존 변환 규칙을 적용한다. XLSX의 값 시트는 결과 없음으로, 별도 `계산식 미설정과 오류` 시트는 상태/사유로 구분한다.

XLK-04: 입력과 패턴은 각각4,096 bytes까지다. 연속 `*`는 합치고, `*`가 없으면 직접 비교한다. `*`가 있으면 토큰 수×(입력 문자 수+1)이2,000,000 이하일 때만 유한 상태 비교를 수행한다. 제한을 초과하면 사유가 있는 오류다. 재귀 백트래킹 없이 두 행의 상태만 보관하고 취소 checkpoint와 기존 식 크기·깊이·단계 제한을 유지한다. 따라서4,096자 동일 리터럴 비교와 단일 `*`는 지원하고, 큰 입력과 복잡한 패턴의 조합은 제한할 수 있다.

XLK-05: **Like를 포함한 식 단위**로 VBA 우선순위를 적용한다. Like는 `= <> < > <= >=`와 같은 비교 순위이며 Not보다 먼저다. 산술 → 결합 → 비교 → Not → And → Or → Xor → Eqv → Imp 순서다. `Not "abc" Like "a*"`는 False이고 `"a" & "b" Like "a?"`는 True다. 새 연산 없는 기존 식과 앞선 schema63/64 문법은 유지한다. 새 식에 기존 Mod/Or/Xor를 섞을 때는 괄호로 의도를 명시한다. 연산자 이름은 ASCII 대소문자 무관이며 Like1/Like_2 같은 다른 식별자는 거절한다. 리터럴·이스케이프된 필드 참조 안의 Like나 Likely 같은 이름은 새 연산으로 판정하지 않는다.

활성 새 연산이 현재·기준선·시나리오·일정 채택·통화/ID 이력 전후 전체 사본에 있으면 조건부 **schema65**다. schema64 이하는 활성 새 식을 거절한다. 비활성 원문은 기존 schema44부터 보존하고 기존 참조/기능의 최소 버전도 적용한다. native 데이터 필드는 추가하지 않는다. 안정 ID 바인딩/이름 변경·저장/재열기·복구·읽기 전용·undo/redo를 연결한다. 통화 전환 후 CStr 금액 패턴도 환산 입력에서 다시 계산한다.

XLK-06: XML은 식·참조·현재 값을 내보내며 재수입 후 실행한다. XER는 정적 결과, 전체 정의/이력은 source.ppm에 보존한다. Python 정규식과 Windows .NET Binary Like의 **유효한 BMP/ASCII 숫자 부분8,932건**을 독립 비교한다. .NET의 비ASCII 숫자 처리와 빈 입력/잘못된 패턴 처리 차이는 별도로 기록한다. 실제 Project/P6 실행 왕복 검증은 아니다.

개념·구문 원문은 Microsoft의 [Like](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/like-operator)와 [MS-VBAL](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/792d4f80-72c1-49da-98a7-37d5783a8615)이다. 번호별 기준선 대응·요약 기간·다른 함수/연산·전체 VBA/로캘과 기존 GAP는 잔여다.
