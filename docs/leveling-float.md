# 평준화 후 총여유·자유여유·임계경로

2026-11-17 후속: [자재 제약 총/자유여유·임계](material-float.md)는 기존 재배치 탐색에 정확한 재고 검사를 추가한다. 계획/잔여·공유 통합과 새 승인 기준선 엔진을 지원하며 이전 승인 결과는 당시 엔진으로 재현한다.

2026-11-06 [날짜 고정 잔여 입력의 여유](dated-resource-float.md)를 추가했다. 각 후보에서 목표·실제 배정률·자원 용량을 검산하고 개별 최대 총여유 증인을 인증한다. 기존 날짜 입력 없는 경로와 한도 초과/미정 가용량의 미산정 정책은 유지한다.

평준화 비교와 채택 일정에서 날짜를 바꾸지 않고 후진 계산을 수행한다. 계획/잔여 평준화와 A/B 진척 정책 조합에 적용한다. 표·간트·네트워크·보고서·인쇄는 같은 계산 결과를 사용한다.

## 전체 구간 계산 (엔진1.1 보존 경로·영향 없는 작업 묶음)

이 값은 현재 평준화 배치에서 도출한 자원 슬롯 흐름을 고정한 여유다. 다른 자원 배정 순서로 재최적화했을 때의 최대 여유나 순수 논리 CPM과 구분한다. 자원 연결은 원본 선후행 관계에 쓰지 않는 파생 정보다.

1. 각 미완료 배정의 잔여 시작~완료 전체 구간을 배정률만큼 예약한다. 가용량을 정수 단위의 슬롯 흐름으로 분해하고, 반납한 슬롯을 뒤 작업이 사용하면 별도 자원 FS 연결을 만든다. 병렬 용량은 여러 슬롯을 사용한다. 처리 순서는 날짜·종료/가용량 변경/시작·원본 행 순서로 결정한다.
2. 가용량 감소 때 회수되는 슬롯의 이전 작업에 완료 상한을 둔다. 원본 논리 관계, 채택 B에서 비활성화하지 않은 관계, 자원 연결, 날짜 제약과 현재 평준화 완료일을 함께 적용한다.
3. 작업/자원 달력과 잔여 기간·공수·중단의 기존 실행 모델로 최후 시작/완료를 구한다. 관계를 반복 전파하므로 SF/SS와 자원 연결이 만드는 작업 단위 순환도 단순 DAG로 잘못 처리하지 않는다. 최후 배치의 전체 자원 부하를 다시 검증한다.
4. 총여유는 최후 배치와 현재 잔여 시작의 작업 달력 근무분 차이다. 자유여유는 다른 작업의 현재 날짜를 고정한 같은 계산이다. 총여유 0인 미완료 작업이 평준화 임계다. 실제 완료는 미래 여유 적용 대상에서 제외하고 진행 중 실제 시작은 고정한다.

임계경로는 원본 논리의 driving 관계와 별도의 자원 driving 관계로 탐색한다. 달력 비근무 구간을 사이에 둔 연결도 실행 모델에서 다음 작업의 시작을 결정하면 driving이다. 여러 임계 분기와 자원 연결을 포함한 임계망일 수 있다.

## 실행 창 유지 (엔진1.2 보존 경로)

전체 구간 예약이 겹치면 `resource-segment-float-v2`로 실제 자원 점유 구간을 분해한다. 각 자원의 FIFO 슬롯 인계는 A의 앞 구간→B→A의 재개 구간처럼 같은 작업을 다시 방문할 수 있다. 이 관계를 작업 전체의 FS로 변환하지 않는다. 원본 논리의 구조 순환 판정은 유지하고 자원 구간망은 후진 고정점으로 계산한다.

실행 창의 내부 시작/완료 경계는 현재 점유 구간의 시각이다. 후보의 예약 시작은 후보 잔여 시작과 원래 구간 시작 중 늦은 시각이며, 예약 완료는 후보 완료와 원래 구간 완료 중 빠른 시각이다. 원래 작업 완료에 닿는 마지막 구간은 후보 완료까지 연장한다. 기존 구간은 모두 비어 있지 않아야 하므로 앞 구간을 없애거나 다른 순서로 재분할하는 이동은 포함하지 않는다. 각 창의 작업량을 동결하지 않고 기존 TaskExecution으로 기간·공수·수동 중단을 다시 적분한다.

논리/구간 인계·가용량 회수·제약·완료일의 단조 상한을 구한 뒤, 실제 자원 수요가 창 예약에 포함되는 허용 시작 중 가장 늦은 것을 선택한다. 서로 다른 자원 달력이나 마지막 분의 공수 배분 때문에 수요 검증이 비단조일 수 있으므로 이를 단순 이진 탐색하지 않는다. 최후 창 예약과 실제 자원 부하를 둘 다 검증한다. 간트 연결과 네트워크 tooltip, 보고서의 선행 실행 완료/후행 실행 시작은 실제 인계 시각을 보여 준다.

예를 들어 A는 8시간이고 월요일 12시~화요일 9시 중단, B는 같은 인력의 4시간 작업이다. A는 월요일 9~12시와 화요일 9~15시(점심 제외), B는 월요일 13~17시에 배치된다. 완료일 화요일 15시에서 A의 총/자유여유는 0, B는 60분, 독립 8시간 C는 300분이다. 독립 C를 24시간으로 늘리면 A는 월요일 11:59까지 늦춰 179분의 총/자유여유를 갖는다. 12시 이후로 옮기면 앞 구간이 사라져 현재 인계 순서가 달라진다.

## 구간 소멸·재분할 (엔진1.3~1.8)

현재 기본 엔진은 수동 중단·작업/자원 달력·가용량 예외의 영향을 받는 연결 작업 묶음에 `resource-repartition-float-v3`를 적용한다. 기존 창 유지 계산이 성공했더라도 새 후보에서 창이 없어지거나 늘어날 수 있으므로 해당 묶음은 다시 계산한다. 나머지 묶음은 종전 계산을 유지한다.

각 후보 시작을 작업 달력의 1분 좌표로 생성하고 기존 TaskExecution으로 전체 실행 구간·공수·자원 수요를 다시 계산한다. 원래 수동 중단과 달력은 편집하지 않는다. 이는 달력·중단에 따른 분할 재생성이며, 자원 충돌마다 임의의 새 중단을 넣는 자동 선점 최적화는 별도 범위다.

순서의 기준도 구분한다. 현재 FIFO 슬롯 인계에서 실행 범위가 겹치지 않는 두 작업은 자원 최종 반환→후행 첫 사용 순서를 유지한다. 교차하는 두 작업은 해당 자원의 최종 반환 순서만 유지한다. 후보에서 특정 자원 수요가 없어지면 그 자원의 인계 조건은 적용 대상이 아니다. 원본 논리 관계·채택 진척 정책의 활성 관계·날짜 제약은 계속 적용한다. 모든 미래 작업은 현재 잔여 시작보다 앞당기지 않는다. 따라서 자원 순서를 완전히 자유롭게 바꾸는 전역 최적해라는 의미는 아니다.

- 총여유: 현재 프로젝트 완료일까지, 같은 묶음의 다른 미완료 작업도 늦출 수 있는 **실제 가능한 배치가 존재하는** 가장 늦은 시작과 현재 시작의 작업 달력 근무분 차이다.
- 자유여유: 다른 모든 작업 날짜를 현재 배치에 고정했을 때 가능한 가장 늦은 시작의 근무분 차이다.
- 실제 자원 부하는 비단조일 수 있어 이진 탐색하지 않는다. 유효 후보를 검사하고 유한 제약 탐색으로 존재 여부를 확인한다. 세 작업이 각 50%씩 겹치는 경우와 유효일별 용량·자원 달력·마지막 분 공수 배분도 실제 합산 수요로 검사한다.
- 총여유마다 별도의 전체 프로젝트 재배치 증인을 검증하고 `LEVELING_REPARTITION_WITNESS` 진단에 작업별 날짜를 남긴다. 각 작업의 최후 시작/완료는 그 작업의 증인 값이다. **모든 최후 날짜를 한꺼번에 적용할 수 있는 공통 최후 일정은 아니다.** 실제 날짜와 현재 평준화 날짜를 바꾸지 않는다.

현재 간트/네트워크/보고서의 인계선은 현재 배치의 참고 정보다. 후보에서 같은 인계선이 유지된다는 보장은 없다. 새 자원 driving은 현재 선행을 1분 늦출 때 해당 후행과 실제 용량 충돌이 생기는지로 확인하고, 임계는 새 총여유 0으로 판정한다. 원본 논리 driving과 구조 순환은 구분한다.

엔진1.4~1.8의 검증된 증인은 [총여유 근거 창](leveling-witness.md)에서 현재/재배치 날짜와 함께 이동하는 작업을 확인할 수 있다. 계산 worker가 제공한 불변 구조화 날짜를 사용하며 진단 문장을 역파싱하지 않는다. 원본 일정에 적용하거나 다른 작업의 최후 날짜를 합치지 않는다.

앞 예제에서 독립 C가 24시간이면 A의 앞 구간을 없애고 수요일 09~18시로 재생성할 수 있어 총/자유여유가 660분이다. B는 A도 함께 수요일로 늦추면 화요일 14~18시까지 이동하므로 총여유 540분이지만, 다른 날짜를 고정한 자유여유는 60분이다. 수요일 자원 용량이 0이면 A는 화요일 09~18시까지만 가능해 총/자유여유 180분, B는 60분이다.

## 연결 묶음 확장 (엔진1.4 보존 경로)

2026-11-04 증분은 여유의 수학적 기준과 `resource-repartition-float-v3`를 유지한다. 논리 관계와 자원 반환 순서의 부등식에서 선행 최소값·후행 최대값으로 지지할 수 없는 후보를 반복 제거한다. 자원 수요가 사라진 후보는 그 자원 순서 조건을 비활성화한다. 이는 이진 탐색이나 자원 쌍별 충돌 검사로 전체 합산 부하를 대체하는 방식이 아니다. 후보가 하나인 작업은 현재 날짜에 고정하고 탐색 분기에서 제외한다. 재귀 대신 명시적 탐색 스택을 사용한다. 연결 묶음 전체의 64개 제한을 이동 가능한 작업 128개 제한으로 바꾸며 전체 작업 10,000개와 기존 후보/실행 구간/탐색 한도를 유지한다. 한도 초과는 여유 미산정으로 표시한다.

고정 작업이 섞인 65개 이상 연결 묶음과 128개 이동 가능 작업의 총/자유여유·임계를 수기 값과 대조한다. 기존 재분할 fixture의 수치·날짜·진척 사실을 보존하고, 기존 엔진1.3의 64개 제한 및 승인 기준선 재현을 별도로 검사한다. 새 엔진은 `jobs-adopted-leveling-1.4`이며 파일 schema는 추가하지 않는다. 증인은 해당 작업과 현재 날짜에서 이동한 작업만 기록하며 생략한 작업은 현재 날짜 그대로다. `LEVELING_REPARTITION_SEARCH_POLICY` 진단에 연결/고정/이동 가능 작업 수와 생략 규칙을 표시한다. 고정 작업의 0여유는 현재 유효 배치로 증명하며, 이동하는 작업은 총여유마다 전체 프로젝트 부하를 검증한다.

## 128개 초과 탐색 (엔진1.5부터)

2026-11-04 사용자 요청으로 연결 묶음의 이동 가능128개 고정 제한을 제거했다. 후보 제약 전파 뒤 모든 후보 조합에서 성립하는 논리/자원 순서 조건은 탐색 결합에서 제외한다. 같은 자원의 후보 수요 범위가 겹치는 작업은 배정률과 관계없이 같은 탐색 단위로 묶는다. 후보 수요의 자원별 포괄 범위를 보수적으로 사용하므로 분해할 수 있는 모든 경우를 찾아낸다는 뜻은 아니다. 세 작업 이상의 합산 수요를 쌍별 충돌만으로 대체하지 않는다. 고정 작업과 다른 단위는 현재 날짜로 예약하고 선택 작업의 단위를 탐색한다. 분해되지 않는 큰 단위도 반복형 탐색으로 처리하며 연결이 많은 작업을 우선 검사한다. 모든 총여유 증인은 전체 프로젝트 자원 부하로 다시 검증한다.

총여유/자유여유의 수학적 기준은 resource-repartition-float-v3를 유지한다. 전체10,000작업·후보250,000·후보 구간2,000,000·판정2,000,000·증인 날짜2,000,000 등 기존 예산은 계속 적용하며 모든128개 초과 입력의 완료를 보장하지 않는다. 한도/미정/검증 실패는 날짜를 보존하고 여유만 원자적으로 미산정 처리한다.

1.5 증분은 jobs-adopted-leveling-1.5를 도입했으며 기존1.0~1.4 승인 기준선은 당시 엔진으로 재현한다. 증인 전체 날짜는 구조화된 불변 정보와 근거 창에 보존한다. 1.5 이상 진단에는 최대20개/16,000byte의 날짜 미리보기와 명시적인 생략 개수를 제공해 큰 증인 때문에 XLSX 한 셀 한도를 넘지 않도록 한다. 작은 증인과 기존1.4 진단 형식은 유지한다. 파일 schema는 추가하지 않는다.

129/512개 결합 작업, 같은 자원을 쓰지만 후보 범위가 겹치지 않는 이동 가능1,000작업, 교차 분할2작업과130개 이동 가능 논리 동료, 삼중 합산 용량·129개 잔여 예측/실제 시작·기존1.4 미산정 기준선·예산/취소/반복 계산과 전체 증인 독립 재구성 및 XLSX/PDF·근거 창을 검증한다.

## 후보 축소·조건부 전파 (엔진1.6부터)

[PROP-01~04](candidate-propagation.md)에 따라 후보 생성 전 자원 상한을 안전한 기간 모델에서만 논리 상한과 함께 전파한다. 비단조 공수/다른 달력/수요 소멸 후보는 실제 후보 검사를 유지한다. 모든 후보의 지지가 증명된 제약은 제거 순회를 생략한다. 큰 후보 집합에서는 선택 작업의 날짜로 이웃 후보를 가역 제외하고 분기 실패 시 복원한다. 끝점 캐시는 제한하며 가득 차면 직접 판정한다.

정확히 같은 단위 전체 배치는 인증을 재사용하고, 독립 단위는 논리 보편 조건과 겹치지 않는 잠재 수요 범위를 근거로 native 전체 부하 인증을 함께 수행한다. 고정 배경과 현재 날짜를 유지하며 모든 인증 후에만 결과를 공개한다. 새 진단 LEVELING_REPARTITION_PROPAGATION_POLICY는 상한 좌표 축소·생성 후보·분기 제외·native 인증/절감·제거 순회 생략을 기록한다. 총/자유여유의 정의와 resource-repartition-float-v3는 유지하고, 기존1.5를 포함한 승인 기준선은 당시 엔진으로 재현한다. [반복 측정·독립 검산·한계](candidate-propagation.md).

## 비단조 필수 부하·연쇄 전파 (엔진1.7부터)

엔진1.7부터 [비단조 수요 전파 NPROP-01~04](nonmonotone-propagation.md)를 추가한다. 실제 후보의 내부 공백·수요 소멸·마지막 분수 공수를 보존해 점별 최소 부하를 구하고 다른 작업의 필수 부하 합과 충돌하는 후보를 제거한다. 분기에서는 살아 있는 후보의 끝점 지지와 선택/고정/필수 부하를 연쇄 전파하고 제외를 되돌린다. 추가 전파50,000판정 상한에서는 기존 정확한 탐색으로 전환하며, 기존 전체 예산·native 증인 인증과 여유 정의를 유지한다. 작은 입력은 추가 전파 비용이 더 클 수 있다. [반복 관측·전수 검산·회귀](validation/nonmonotone-propagation-2026-11-04/README.md).

## 추가 전파의 비용 판단 (현재 엔진1.8)

[COST-01~03](propagation-cost.md)에 따라 이동 후보·실행 구간·관계 순회 비용으로 추가 전역/분기 전파를 선택한다. 생략한 단위도 실제 후보 실패가 누적되면 활성화하고 낮은 제외 효과에서는 재시도를 늦춘다. 가역 마스크를 필요할 때 만들며 생략/중단 뒤에도 정확한 탐색·합산/native 인증을 유지한다.1.7까지의 승인 결과를 별도 재현하고 schema와 전체 예산은 유지한다. 작은 입력에서도 추가 비용이 남는 사례를 포함해 [반복 관측·전체 검증](validation/propagation-cost-2026-11-04/README.md)에 기록한다.

## 계산 불가와 표시

검증용 재배치 증인을 원본 일정에 자동 반영하거나 미산정을 정상 0으로 표시하지 않는다. 탐색 영역의 미정 가용량, 모델/현재 배치 불일치, 최후 자원 검증 실패, 계산 한도 초과는 기존 평준화 날짜·유효 상태를 유지하면서 여유만 미산정으로 둔다. `LEVELING_FLOAT_UNAVAILABLE`에 사유를 기록하며 표는 —로 표시한다. 완료 실적도 미래 여유는 —다.

작업 10,000개·원본 실행 구간 100,000개·논리/자원 연결 250,000개를 한도로 한다. 1.3 재현은 연결 묶음당64개, 1.4 재현은 제약 후보 제거 후 이동 가능128개 제한을 유지한다. 1.5 이상에는 별도의128개 제한이 없다. 한 연산의 후보 시작250,000개·후보 구간2,000,000개·탐색 판정2,000,000회·증인 날짜2,000,000개 예산은 유지하므로 크기만으로 계산 가능을 보장하지 않는다. 한도에서 멈춘 결과를 최대 여유나 임계로 확정하지 않는다. 1.1/1.2는 기존 후진 판정 한도를 유지한다. 네트워크 화면은 자원 연결을 포함해 기존200,000개 한도를 따른다. 실제 시간대 부하만으로 가능한 모든 교차/선점 배치를 분석한다는 의미는 아니다.

## 보존과 호환

- 배치 날짜, 기간·공수, 단가·원가, 원본 관계, 진척 원장, 기존 승인 기준선을 수정하지 않는다.
- 결과의 `levelingFloatCalculated`와 자원 연결은 재계산 가능한 세션 파생 정보다. 기존 조건부 native schema9~14 선택을 유지한다.
- 새 평준화 계획의 기준선 엔진은 `jobs-adopted-leveling-1.8`이다. 기존 `1.0`은 미산정, `1.1`은 전체 구간, `1.2`는 실행 창 유지, `1.3`은64개 묶음 제한, `1.4`는 이동 가능128개 제한, `1.5`는 당시 후보 결합/인증 방식, `1.6`은 당시 안전한 상한/이웃 전파/인증 공유 방식, `1.7`은 당시 비단조 필수 부하/연쇄 전파와 상한으로 별도 재검산하여 승인 결과를 보존한다. 저장 시나리오는 입력/정책으로 현재 파생 계산을 다시 수행한다.
- 이전 직렬 정책의 시나리오를 재생하면 후진 실행 모델에도 같은 legacy 마일스톤 경계 규칙을 적용한다. 전진 배치 정책과 파생 여유 정책 식별값은 출처에서 함께 확인한다.
- 전체 구간은 `resource-order-float-v1`/`LEVELING_FLOAT_POLICY`, 실행 창 유지는 `resource-segment-float-v2`/`LEVELING_SEGMENT_FLOAT_POLICY`, 재분할은 `resource-repartition-float-v3`/`LEVELING_REPARTITION_FLOAT_POLICY`로 식별한다. P6/MSP와의 여유 동등성이나 실제 P6 재계산 왕복은 검증하지 않았다.

## 검증

[Windows Release 검증 기록](validation/leveling-float-2026-11-03/README.md)에 회귀·독립 XLSX/PDF 판독·화면·1천/1만 파생 계산 관측과 소스 식별값을 보존한다. 충분한 자원에서 네 종류 관계와 양음 지연의 값이 기존 논리 CPM으로 환원되는지 검사하고, 병렬 용량·가용량 감소·진척 조합·기준선 버전 보존을 별도 사례로 확인한다.

교차 분할 증분의 [최종 검증 기록](validation/segment-leveling-float-2026-11-03/README.md)에 새 수기 수치·실제 인계 시각·native 및 독립 출력 판독을 추가한다. 이전 검증 기록은 당시 코드의 증거로 보존한다.

구간 소멸·재분할의 [검증 기록](validation/repartition-float-2026-11-03/README.md)은 분 단위 독립 전수 대조와 native/XLSX/PDF·기준선 버전 재현을 보존한다.

연결 묶음 확장의 [2026-11-04 검증](validation/scaled-repartition-float-2026-11-04/README.md)은 전체89/89·독립17종·1,514개 증인 재구성과65/128/256/1,000 작업의 제한된 규모 사례를 보존한다. 큰 고정 묶음과128개 이동 가능 작업 검증을 모든 대규모 프로젝트의 계산 가능/성능 보장으로 확대하지 않는다.

128개 초과 증분의 [최종 검증](validation/expanded-repartition-float-2026-11-04/README.md)은 전체91/91·독립19종·2,641개 증인/280,785개 날짜 참조 재구성, 129/512개 결합·1,000개 이동 가능 분리·132개 교차 분할/논리 묶음·기존1.4/신규1.5 기준선·근거 창과 큰 XLSX/PDF 미리보기를 보존한다.

후보 축소·조건부 전파1.6의 [최종 검증](validation/candidate-propagation-2026-11-04/README.md)은 같은 입력의1.5/1.6 반복 관측, 후보 한도에서 중단하던750작업 체인의 완료, 비단조 용량 전수 검산·분기 복구·인증 재사용과 구버전 기준선을 보존한다.
