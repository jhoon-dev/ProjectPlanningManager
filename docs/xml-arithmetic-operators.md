# XML 계산식 거듭제곱·정수 나눗셈

2026-11-14 · XOP-01~06. `^`와 `\`를 작업·프로젝트·자원·배정 계산식에서 지원한다. 편집기의 산술 연산 예시 삽입, worker 미리보기, 표·요약·전파, 저장/복구와 XML/XER·XLSX/PDF를 연결한다.

| 식 | 결과 | 규칙 |
|---|---|---|
| `2 ^ 3` | 8 | 거듭제곱 |
| `2 ^ 3 ^ 2` | 64 | 같은 우선순위는 왼쪽부터 |
| `2 ^ (3 ^ 2)` | 512 | 괄호로 순서 지정 |
| `-2 ^ 2` / `(-2) ^ 2` | -4 / 4 | 거듭제곱이 단항 부호보다 먼저 |
| `2 ^ -3` | 0.125 | 음수 지수 |
| `9 ^ 0.5` | 3 | 양수 밑의 분수 지수 |
| `7.5 \ 2.5` | 4 | 각각8과2로 짝수 반올림 후 나눗셈 |
| `7 \ -2` | -3 | 몫의 소수부를0방향으로 버림 |
| `8 \ 3 * 2` | 1 | 곱셈이 정수 나눗셈보다 먼저 |

XOP-01: 새 연산을 포함한 식은 `^` → 단항 부호 → `* /` → `\` → `Mod` → `+ -` 순서다. 이후 결합·비교·논리 연산의 기존 순서를 따른다. 이름이 같은 문자·날짜 리터럴과 이스케이프된 필드 참조 안의 기호는 연산자가 아니다. 기준은 Microsoft의 [VBA 연산 우선순위](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/operator-precedence)와 [거듭제곱](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/caret-operator), [정수 나눗셈](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/backslash-operator) 문서다. 전체 VBA 실행 동등성을 주장하지 않는다.

XOP-02: **새 연산이 없는 과거 식은 기존 문법을 유지한다.** 과거 `Mod`는 `* /`와 같은 우선순위였다. `8 Mod 3*2`는 계속4이고, 새 문법을 사용하는 `8 Mod 3*2+0^1`은2다. 기존 식에 새 연산을 넣으면서 이 연산들을 섞을 때는 괄호로 의도를 명시한다. `Mod`의 정수 전용 제약은 유지한다.

XOP-03: 피연산자는 native 숫자·Boolean이며 True=-1, False=0이다. 문자열·날짜는 암묵 숫자 변환하지 않는다. 문자열 숫자는 `CDbl`로 명시하며 날짜의 숫자 환산은 추측하지 않는다. `^`는 음수 밑에 정수 지수만 허용한다. `0^0`은1이고0의 음수 거듭제곱은 오류다. 중간 범위는 ±9,000,000,000,000이며 결과는 소수6자리로 절반을0에서 멀어지는 쪽으로 반올림한다. 유한 범위 초과는 오류이며 매우 작은 값은0으로 반올림될 수 있다. 거듭제곱은 C++ 부동소수 근사 계산이며 전체 Double/Decimal 정밀도를 보장하지 않는다.

`\`는 피연산자 각각을 짝수 반올림한 뒤 **32비트 부호 있는 정수**로 검증하고 정수 몫을 반환한다. 반올림한 제수가0이면 오류다. `2147483647.5\2`는 피연산자 초과, `(-2147483648)\(-1)`은 몫 초과다. 오류를 포화·순환시키지 않는다. 새 두 연산의 결과는 단위 없는 숫자이며 기간의 근무/경과/추정 태그를 전파하지 않는다. 최종 Number·Cost·Duration 필드의 기존 범위/단위 규칙은 별도로 적용한다. Cost 입력은 현재 통화의 주요 단위다.

XOP-04: Null은 전파하고 모든 피연산자를 평가한다. `Null\0`은 미설정, `IIf(True,1,0^-1)`은 오류다. 입력/결과 미설정과 오류를 저장된99/777이나 임의0으로 대체하지 않는다. XLSX 값 시트는 결과 없음으로 표시하고 별도 `계산식 미설정과 오류` 시트에서 두 상태와 사유를 구분한다. 취소와 기존 크기·깊이·단계 제한을 유지한다.

XOP-05: 활성 새 연산이 현재·기준선·시나리오·일정 채택·통화/ID 이력 전후 전체 사본에 있으면 조건부 **schema63**이다. schema62 이하의 활성 식은 거절한다. 비활성 원문은 기존 schema44부터 보존하며 이전 기능의 최소 버전은 유지한다. native 저장 필드는 추가하지 않는다. 저장/재열기·읽기 전용·복구·undo/redo, 안정 ID 바인딩과 이름 변경을 연결한다. 통화 전환은 입력을 환산하고 식을 다시 계산하므로 제곱 결과에 단순히 환율을 곱하지 않는다.

XOP-06: XML은 정의·참조 이름·현재 값을 내보내며 재수입 후 다시 실행한다. XER는 정적 결과이고 전체 정의/이력은 source.ppm에 보관한다. 독립80자리 거듭제곱/정확한 유리수 정수 나눗셈과 Windows VBScript의 공통 이항 숫자 부분을 비교한다. **VBScript의 `-2^2`는4로 관측되며 이 구현의 VBA 문서 기준 -4와 다르다.** VBScript 비교는 괄호/단항 부호의 파서 동등성이나 실제 Microsoft Project/P6 왕복 검증이 아니다.
