# XER 후속 원본의 통화·자원 종류 전환

2026-11-08 · XSC-01~06 · GAP-09. [새 원본·삭제 ID 재연결](xer-source-relink.md)의 명시적 전환 단계다. 프로젝트의 계획 통화나 과거 관측 원장을 다시 해석하지 않는다. 새 원본과 이전 집계를 현재 프로젝트의 통화·인력/장비 종류에 맞춰 변환한 후 기존 재무 병합 절차로 검토한다.

## XSC-01 입력과 범위

현재 계획·관측 원장까지 함께 바꾸는 별도 기능은 [프로젝트 전체 통화 전환](project-currency-conversion.md)이다. 이 기능을 실행하면 raw 후속 원본과 기존 전환 규칙은 보존하고 `incomingCurrencySteps`에 추가 환율을 기록해 순서대로 재실행한다.

`XerRelinkAudit.incomingConversion`과 `previousConversion`은 각각 선택적이다. 미지정 시 기존 통화·종류 동일성 검사를 그대로 적용한다. 각 규칙에는 대상 통화, 기준일, 환율·단위 환산 근거, 양의 정수 분자/분모를 저장한다. 분자·분모 범위는 1~1,000,000,000이다. 기준일은 사용자가 적용한 환율/단위 명세의 날짜이며 원본 실적 날짜를 이동하지 않는다.

환율은 **원본 주통화 1단위 = 대상 주통화 × 분자/분모**다. USD→KRW 1,350원은 1350/1, KRW→USD는 1/1350이다. KRW/JPY 0자리와 USD/EUR 2자리를 최소 단위 변환에 반영한다. 같은 통화는 1/1만 허용한다. 자동 환율 조회나 날짜별 환율 추정은 하지 않는다.

자원 규칙은 원본의 인력·장비 종류마다 최대 하나다. 해당 종류의 **모든 자원**을 지정 종류로 전환하며 관측 공수에 분자/분모를 곱한다. 두 종류 교환과 한 종류로의 통합, 동일 종류의 단위 환산을 지원한다. 서로 다른 종류의 이름/ID가 같아도 연결 대상을 자동 추정하지 않는다. 기존 ID 연결표에서 사용자가 지정한다. 일부 자원에만 서로 다른 생산성 규칙을 적용하는 흐름은 이 계약에 포함하지 않는다.

## XSC-02 정확도와 대사

원본 task AC, 배정 정규/초과 원가, 자원별 기간 원가, TASKFIN 인력/장비/자재/직접비·EV/PV를 통화 최소 단위에 half-up 반올림한다. 공수는 1/100 근무분 정수로 정확하게 나누어져야 한다. 공수를 반올림하거나 관측 공수에서 계획 생산성을 추정하지 않는다. 64비트 중간 곱셈의 넘침을 피하는 정수 장제법을 사용한다.

인력·장비 집계 공수와 원가는 두 종류의 원본값에서 동시에 계산해 종류 교환 시 이중 환산을 막는다. 같은 종류로 모이는 보고된 항목은 합산하며 명시 0과 미보고를 구분한다. 미보고 원본은 감사 기록에 보존한다. ID·날짜·출처 지문은 유지한다.

지원 금액/공수 한도 초과, 정수가 아닌 공수, 중복/없는 종류 규칙, 잘못된 기준일·빈 근거를 거절한다. 개별 금액 반올림 후 기간 합계가 배정 누계를 초과하는 등 원래 대사 조건이 깨지면 거절한다. 임의로 한 관측값을 줄여 맞추지 않는다. 현재 원장과 충돌하는 유효한 전환값은 기존 병합 검토에서 명시적으로 해결해야 제출할 수 있다.

## XSC-03 불변성과 재실행

`audit.incoming`에는 전환 전 원본을 저장한다. `xerFinancials`, 이전 재무 revision, 현재 PlanInput/단가/기간별 배정, 기준선, 진행·원가·날짜별 원장, 사용자 기간 마감, 외부 EV/PV 채택 이력은 변경하지 않는다. 변환된 후보를 현재 원장과 병합한 결과만 새 재무 revision에 추가한다. 이전 집계의 종류 전환도 동일한 기록을 남긴다. 재열기 때 보존 원본·환산비·연결표·병합 선택을 재실행해 저장 결과와 대사한다.

## XSC-04 저장과 편집

전환 기록이 있으면 schema31이다. 전환 없는 기존 문서는 기존 schema를 유지한다. 이전 schema에 전환 필드를 섞으면 거절한다. 미지원 버전33도 거절한다. 저장/재열기·다른 이름 저장·복구에서 원본과 환산비를 보존한다. worker 준비는 읽기 전용이며 취소·문서/revision/session 변경·읽기 전용 상태에서 적용을 거절한다. 사실 등록은 기존 재연결과 동일하게 일반 undo 대상에서 제외한다.

## XSC-05 UI

프로젝트의 새 XER 원본 재연결 창에서 새 원본·이전 집계별 전환을 켠다. 대상 통화, 환율, 종류별 공수 환산비, 기준일/근거를 입력한다. 전환값 미리보기는 원본/전환값을 모든 task·배정·기간 지표별로 표시한다. 전환/연결/누락 처리 설정 변경은 확인 체크를 해제한다. 확인 후 기존 재무 병합의 분석/충돌 해결·보고자/사유·최종 제출을 거쳐 적용한다. 닫기·취소는 현재 문서를 변경하지 않는다.

## XSC-06 교환과 검증

재내보내기는 현재 문서의 통화/자원 종류와 최신 병합 집계로 작성한다. 원본 출처 지문은 원본 파일의 것으로 유지하고 현재 투영 지문은 문서에 다시 결합한다. 독립 수치 oracle·원본/원장 동일성·schema 손상·저장/복구·후속 병합·XER 재판독·Windows UI와 전체 CTest 결과는 [검증 기록](validation/xer-source-conversion-2026-11-08/README.md)을 따른다. 실제 P6 재계산/재저장과 MPP 판독은 별도 검증이다.

후속 [새 일정·WBS·달력 채택](xer-schedule-adoption.md) 이력은 schema32에 저장한다. 통화/자원 전환만 있는 문서는 기존31 writer를 유지한다.
