# 계획 공수로 기간별 배정률 생성

2026-11-06 후속으로 [FixedWork/FixedUnits 상대 곡선 역산](work-contour-inverse.md)을 추가했다. 이 문서의 일/주/월 목표 하위 창은 고정 기간 범위를 유지하며, 고정 공수/단위는 작업 기간/공수 입력과 곡선 편집을 사용한다. 아래 과거 후속 표기보다 새 계약과 [최신 잔여 점검](planning/19-work-contour-remaining-review.md)을 우선한다.

자원 → **기간별 계획 배정·자원 곡선… → 계획 공수로 배정률 생성…**에서 사용한다. 고정 기간·기간 확정·공수 역산 비활성인 작업/자원 배정을 지원한다. Steps는 허용하며 LOE/WBS Summary 지원 활동의 직접 공수 입력은 지원하지 않는다.

## 입력과 검산

현재 배정률 초안을 기준으로 **평준화 채택 전 논리 계획**을 계산하고 일/주(월~일)/월별 시작·끝, 자원 가능 근무분과 현재 공수를 표시한다. 작업 달력·자원 달력·각 달력의 휴일·점심·작업 중단은 공통 실행 모델의 교집합을 따른다. 명시한 달력은 프로젝트 기본 달력의 휴일을 자동 상속하지 않는 기존 정책을 유지한다. 자원 maxUnits와 일별 가용률은 작업 가능 시간과 별개이며 목표의 상한으로 자동 적용하지 않는다. 적용 후 부하/과부하를 확인한다.

작업 근무분이 없는 날은 경계가 겹쳐 별도 행을 만들지 않는다. 작업은 근무하지만 자원만 비근무인 구간은 가능 근무분 0으로 표시한다. 이 구간의 현재 공수 0을 유지할 때는 기존 배정률을 보존하며, 이후 달력이 바뀌면 그 배정률을 재생한다.

목표 공수는 소수점 `.`을 사용하는 시간(h), 소수 4자리까지다. 빈칸·부호·지수·쉼표·비수치·음수를 거절한다. `6000 = 1 h`인 정수 공수로 half-up 반올림한다. 예: `0.0001 h`는 정수 공수 1이며 표시 `0.0002 h`를 다시 입력해도 1을 보존한다. 네 자리 시간 표시는 모든 지원 정수 공수를 왕복한다. 목표 자체는 별도 영속 필드로 저장하지 않는다.

각 구간의 자원 가능 근무분이 N, 반올림 목표 공수가 W이면 `q=W/N`, `r=W%N`을 사용한다. 처음 r개의 **실제 교집합 근무분**에는 q+1%, 나머지는 q%를 배정해 최대 두 구간으로 표현한다. 교집합이 없는 사이 시간에는 같은 배정률이 연장되어도 공수를 소비하지 않는다. `N=0,W>0`, 100,000% 초과 필요량, 저장 한도 초과는 오류다. 목표 0은 0%로 표현한다. 현재 공수와 같으면 혼합률 곡선을 그대로 보존한다.

변경 구간만 덮어쓰며 선택하지 않은 구간·기본률 공백·현재 기간 밖 구간을 유지한다. 생성 결과를 공통 실행 모델로 다시 적분해 각 목표와 정수 단위까지 일치해야 한다. 입력 수정은 이전 검산을 무효화한다. 기간 단위 변경은 현재 공수로 초기화한다. 기간 행 최대 1,024개를 넘으면 주/월로 변경한다. 생성 후에도 기존 배정당 1,024개·계획당 100,000개 한도를 적용한다.

## 적용과 보존

**배정률 변환·검산 → 배정률 초안에 반영 → 문서에 적용** 순서다. 하위 창에서 문서·dirty·revision을 바꾸지 않는다. 최종 적용은 기존 AssignmentPeriodsEdit의 원자 검증·프로필 승격·평준화 자동 무효화/결정 원장과 한 번의 undo/redo를 따른다. 취소/닫기는 worker를 취소하며 문서·세션·revision·권한 변경은 반영을 차단한다. 읽기 전용에서는 기존 배정률 조회만 가능하다.

실제 날짜·진척·실제공수/원가·기간 실적 원장과 동결 기준선/시나리오는 변경하지 않는다. 저장되는 입력은 기존 Assignment.periods다. 목표 공수의 날짜를 영속 제약으로 추가하지 않는다. 작업 이동·평준화·기간/달력 변경 후에는 상대 배정률을 재생하므로 새 날짜에서 같은 총공수를 보장하지 않는다. 잔여는 기존 계획 곡선 뒤쪽 재생 정책을 유지한다.

기존 schema17 선택과 jobs-effort-periods-1.0 엔진을 재사용하며 과거 파일/동결 기록의 의미를 변경하지 않는다. native 저장/복구, Usage·유효 단가 원가·부하·보고서는 생성 구간을 사용한다. XML/XER는 기본률 투영 손실을 공개한다.
