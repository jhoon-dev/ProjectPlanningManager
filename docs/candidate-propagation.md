# 후보 영역 축소·조건부 제약 전파

2026-11-04 후속 요청은 [평준화 여유 계약](leveling-float.md)의 계산량을 줄이는 엔진1.6 증분이다. 총/자유여유의 수학적 정책·현재 날짜·실적·파일 schema9~14를 유지하고 기존1.0~1.5 기준선을 당시 엔진으로 재현한다.

## 수용조건

- PROP-01: 자원 수요의 처음/마지막 시각이 후보의 잔여 시작/완료와 항상 일치함을 보장할 수 있는 기간 기반 작업만, 자원 순서의 단조 상한을 후보 생성 전에 논리 관계와 함께 전파한다. 공수 적분·다른 자원 달력·자원 수요 소멸 등 보장이 없는 경우에는 기존 비단조 후보 검사를 유지한다. 실제 용량/수요의 이진 탐색은 하지 않는다.
- PROP-02: 전파에서 이미 모든 후보가 지지를 받으면 불필요한 제거 순회를 생략한다. 큰 후보 집합을 탐색할 때 선택한 작업의 날짜로 이웃 후보를 제외하고, 실패/되돌림 시 제외 상태를 정확히 복구한다. 끝점 키 캐시는 메모리를 제한하고 초과 시 직접 판정으로 처리한다. 용량 합산 판정은 기존 정확한 시간축을 사용한다.
- PROP-03: 같은 탐색 단위의 동일한 전체 날짜 배치는 검증을 재사용한다. 독립 단위는 한 배치로 묶어 native 전체 자원 부하를 검증하여 각 단위의 증인을 인증한다. 독립성은 기존1.5의 모든 후보 논리 조건/보수적 자원 범위 결합으로 보장한다. 날짜 배치의 동등성은 해시만으로 판정하지 않는다. 증인은 모든 인증이 끝난 뒤 공개하며 실패/취소 시 부분 결과는 노출하지 않는다.
- PROP-04: 생성 전 좌표 축소량·실제 생성 후보·분기 제외·native 검증/재사용 계수를 진단한다. 같은 입력의1.5/1.6 완료 여부·수치·날짜·진단 계수·반복 표본을 함께 측정한다. 1.5가 예산에서 중단한 입력은 가짜 속도 배율로 보고하지 않는다. 자원 순서만 있는 큰 체인, 결합/분리 묶음과 비단조 달력·용량·분기 복구를 독립 검산한다.

기존 작업/후보/구간/판정/증인 예산과 미산정 처리를 유지한다. 모든 큰 프로젝트의 완료나 일정한 속도 향상을 보장하는 기능은 아니다. 근거 창은 전체 구조화 날짜, 보고서는 기존 명시적 미리보기를 사용한다.

## 구현과 계산 의미

이 증분의 엔진은 `jobs-adopted-leveling-1.6`이다. 후속 엔진1.7은 [비단조 수요 전파](nonmonotone-propagation.md)를 추가한다. 현재1.8의 [비용 판단](propagation-cost.md)도 함께 따른다. 후보 생성 전에 논리 상한과 안전한 자원 반환 상한을 고정점까지 전파한다. 일반 기간 모델의 양수 배정, 또는 공수 적분을 사용하지 않는 기간 모델에서 작업/해당 자원 달력이 같은 경우에만 자원 수요 끝점을 잔여 시작/완료로 대체한다. 두 끝점 작업 모두 이 보장을 충족해야 한다. 공수 적분·다른 달력·수요가 사라지는 후보는 실제 후보별 끝점과 합산 부하로 계속 판정한다. 실제 자원 가용성의 단조성을 가정하지 않는다.

후보 생성 후 기존 전체 제약 전파에서 모든 후보의 지지가 이미 증명되면 제거 순회를 생략한다. 탐색 단위 안에 후보가32개를 넘는 작업이 있으면 선택한 날짜와 양립할 수 없는 미선택 이웃 후보를 가역 마스크로 제외한다. 분기를 되돌리면 해당 분기의 제외만 정확히 복원한다. 이는 선택된 이웃의 조건부 전파이며, 모든 미선택 작업 사이의 완전한 제약 전파를 뜻하지 않는다. 불변 후보 배열의 끝점 키는 최대250,000개 항목을 캐시하며, 캐시 예산을 넘으면 직접 계산한다. 캐시가 찼다는 이유로 계산을 중단하지 않는다. 실제 세 작업 이상의 자원 합산은 기존 정확한 시간축 검사를 유지한다.

전체 부하 인증의 중복도 줄인다. 같은 탐색 단위에서 연속으로 얻은 전체 날짜 배치가 정확히 같으면 한 번 인증한다. 날짜 벡터를 직접 비교하며 해시 충돌 가능성에 의존하지 않는다. 서로 독립인 단위는 각 단위에서 하나씩 선택한 날짜를 합쳐 한 번의 native 전체 부하 검사로 인증한다. 단위 사이의 논리 조건은 모든 후보 조합에서 성립하고 같은 자원의 잠재 수요 범위는 겹치지 않으므로, 나머지 단위를 현재 날짜로 되돌려도 각 증인의 유효성이 유지된다. 고정 작업·실적은 같은 배경으로 남는다. 모든 인증을 통과한 뒤 작업별 증인과 수치를 공개한다.

개별 작업의 총여유 증인은 여전히 서로 다른 가능한 일정이다. 개별 최후 날짜를 모두 합친 일정의 실행 가능성을 주장하지 않는다. 자유여유는 다른 작업의 현재 날짜를 고정한 값이다. 수학적 정책 `resource-repartition-float-v3`, 진척 활성 관계, 현재 날짜와 원장, 불변 근거 창을 유지한다. 구버전1.0~1.5 승인 결과는 당시 엔진으로 재현한다.

## 진단과 측정

`LEVELING_REPARTITION_PROPAGATION_POLICY`는 다음 계수를 순서대로 남긴다.

| 계수 | 의미 |
| --- | --- |
| 생성 전 상한 축소 | 후보 생성 전 작업별 시작 좌표 상한 감소량의 합. 최종 유효 후보 제거 개수와 구분한다. |
| 생성 후보 | 중복 날짜/단항 조건 제거 전에 실제로 시도한 시작 좌표 수 |
| 분기 제외 | 탐색 중 후보 제외 사건 수. 복구 후 다시 제외하면 다시 센다. |
| native 인증 | 재배치 증인의 전체 부하 검사 횟수. 최초 현재 배치 검사와 고정 작업의 현재 날짜 증명은 제외한다. |
| 인증 절감 | 비고정 선택 작업의 인증 요청 수에서 실제 인증 횟수를 뺀 값. 동일 배치 재사용과 독립 단위 배치를 포함한다. |
| 제거 순회 생략 | 전체 제약 전파에서 모든 후보의 지지가 증명되어 제거 순회를 생략한 횟수 |

측정은 미리 계산한 동일 논리 일정에서 파생 여유 계산만 비교한다. 각 호출은 새 평가 캐시로 시작하며 캐시 해제까지 포함한다. 완료된3개 사례는1.5/1.6 순서를 교차해 각3회 측정하고 중앙값과 원시 표본을 보존한다. 전진 논리/직렬 평준화·UI·파일 I/O 시간은 포함하지 않는다. 후보 한도로 중단한1.5 사례에는 속도 배율을 붙이지 않는다. 측정 fixture 밖의 성능과 최악 계산 시간을 보장하지 않는다.

검증 계약은 `candidate_propagation_contract`, 독립 검산은 `scripts/verify-candidate-propagation.py`다. 자원 순서 체인·결합/독립 단위·비단조 용량·분기 실패/복원·미정/취소·반복 계산·기존1.5/신규1.6 기준선과 native/XLSX를 검사한다. 독립 작은 사례는17,366개 허용 배치를 전수 열거해 총/자유여유를 대조하고, 개별 최후 날짜의 동시 적용이 불가능한 경우도 확인한다. [최종 수치와 실행 근거](validation/candidate-propagation-2026-11-04/README.md).
