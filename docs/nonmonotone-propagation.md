# 비단조 수요 후보 축소·제약 전파

2026-11-04 사용자 요청의 엔진1.7 증분이다. [1.6 효율화](candidate-propagation.md)와 [여유 계산 계약](leveling-float.md)을 확장하고, 기존1.0~1.6 승인 기준선·현재 날짜·실적·원장·schema9~14를 유지한다.

## 수용조건

- NPROP-01: 실제 후보 구간의 시간별 수요를 정규화하고 모든 후보의 점별 최소 수요를 구한다. 빈 구간·사라진 자원 수요는0이며, 첫/마지막 수요 사이를 채우지 않는다. 다른 작업들의 필수 수요 합과 충돌하는 후보를 제거하고 논리/자원 끝점 전파와 함께 전파 작업량 상한 안에서 고정점까지 반복한다.
- NPROP-02: 분기에서는 선택된 날짜·현재 고정 배경과 미선택 작업의 필수 수요를 함께 검사한다. 살아 있는 후보만으로 끝점 지지를 재계산하고, 후보 제거를 이웃 관계로 연쇄 전파한다. 제외 상태는 분기 복원 지점까지 정확히 되돌린다. 실제 용량의 단조성·자원별 수요의 존속을 가정하지 않는다.
- NPROP-03: 점별 하한으로 후보를 줄이되 실제 다중 작업 합산과 native 증인 인증을 유지한다. 기존 전체 예산·미정/검증 실패·원자성/취소를 유지하고 새1.7 출처와 전파 계수를 기록한다. 기존1.6까지의 엔진을 별도 재현한다.
- NPROP-04: 다른 자원 달력·수요 소멸·분수 마지막 공수·용량 구멍·세 작업 합산·분기 복구를 검증한다. 독립 작은 시간축 전수 검산과 같은 입력의1.6/1.7 반복 관측, native 승인 기준선·출력 판독을 보존한다. 단회/중단 시간과 반복 완료 관측을 구분한다.

필수 수요는 모든 후보가 같은 시각에 최소한 요구하는 부하이며, 각 작업이 실제로 선택할 후보를 뜻하지 않는다. 필수 수요와 충돌하지 않는 후보의 실행 가능성은 이후 탐색과 전체 자원 검증으로 확인한다. 총여유는 작업별 가능한 재배치이며 개별 최후 날짜의 동시 적용을 보장하지 않는다. 전역 순서 재최적화·임의 선점은 추가하지 않는다.

## 구현

이 증분의 엔진은 `jobs-adopted-leveling-1.7`이다. 후속 현재 엔진1.8은 [추가 비용 판단](propagation-cost.md)을 적용한다. 공수 적분·수동 중단·작업/자원 달력 차이·가용량 예외가 있는 effort 실행 묶음에 추가 수요 전파를 적용한다. 후보는 기존 실행 모델로 생성하고, 후보 생성 전의 단조 상한은1.6에서 증명한 안전한 모델에만 적용한다. 실제 비단조 수요를 이진 탐색하지 않는다.

`MandatoryDemand.h`는 자원별 시작/종료 사건을 같은 시각에 함께 합산해 중첩 구간을 정규화한다. 정규화한 후보들을 점별 최소로 교차하므로 내부 공백과 후보에서 사라진 수요는0이다. 서로 다른 작업의 하한은 합산한다. 한 작업의 후보를 검사할 때는 그 작업의 하한을 먼저 빼서 자기 수요를 두 번 세지 않는다. 모든 하한이0이면 후보 생성 시의 단항 부하 검사와 같으므로 추가 전역 부하 순회를 생략한다. 제거 후 하한과 끝점 지지를 재계산해 전파 작업량 상한 안에서 고정점까지 반복한다. 현재 배치가 사라지면 계산 실패로 처리한다.

분기에서는 살아 있는 후보의 끝점 최소/최대와 수요 부재 여부로 논리/자원 순서의 지지를 구한다. 제외된 후보의 이웃 관계를 큐에 다시 넣어 연쇄 전파한다. 선택된 날짜·고정 동료는 정확한 시간축에 예약하고, 미선택 동료의 필수 수요만 추가한 임시 시간축으로 합산 용량을 검사한다. 필수 수요 변경과 끝점 전파가 안정될 때까지 반복한다. 제외 기록은 기존 가역 마스크의 복원 지점에 기록한다. 임시 부하를 공유 배경에 남기지 않는다.

작은 탐색 단위의 추가 비용을 줄이기 위해, 미선택 작업을 함께 움직이는 단위의 후보 총합이32개를 넘거나 기존 기준처럼 한 작업의 후보가32개를 넘을 때 분기 마스크를 사용한다. 추가 비단조 전파는 위 effort 묶음에서 수행한다. 자유여유는 다른 날짜를 고정한 기존 직접 검사 경로를 유지한다. 추가 전파는 연산당50,000판정 또는 전체 판정1,900,000회에서 중단하고 기존 정확한 탐색으로 전환한다. 이 전파 상한만으로 미산정 처리하지 않는다. 전역 제거는 검사 목록을 완성한 작업에만 한 번에 반영하고, 분기의 완료된 안전한 제외는 가역 기록에 유지한다. 모든 남은 후보와 기존 단위 결합/합산/native 인증을 그대로 검사하므로 근삿값을 반환하지 않는다. 새 단계를 포함한 판정은 같은2,000,000회 예산과 협력적 취소를 따른다. 끝점 캐시250,000항목·전체 작업/후보/구간/증인 예산을 늘리지 않는다.

## 진단·보존·검증

`LEVELING_NONMONOTONE_PROPAGATION_POLICY`는 전체 필수 부하 후보 제거 수, 분기 끝점 지지 제외 사건 수, 분기 부하 제외 사건 수, 고정점 순회 수, 기존 탐색 전환 수, 추가 전파 판정 수를 순서대로 기록한다. 전역 제거는 실제 후보 배열의 제거 수다. 분기 계수는 복원 후 다시 제외된 후보도 다시 세므로 고유 후보 수가 아니다. 순회 수는 성공·실패 분기와 상한에서 중단한 순회를 모두 포함한다.1.6의 생성 후보·인증 계수도 함께 유지하며, 새 제거 수는 생성 전 좌표 축소 수와 구분한다.

기존1.0~1.6 승인 기준선은 당시 엔진으로 재현한다. 새 기준선은1.7이며 native 입력 schema9~14를 추가하지 않는다. 필수 구간·가역 제외·끝점 캐시·진단은 비영속 파생 정보다. 총/자유여유의 수학적 정책은 `resource-repartition-float-v3`를 유지하고, 기존 native 전체 부하 인증 후에만 불변 증인을 공개한다.
