# XML 계산식 Baseline Cost

2026-11-15 후속: [외부 XML 기준선 채택·내보내기](xml-baseline-exchange.md)를 지원한다. 채택 번호의 Baseline Cost는 외부 명시 금액을 사용하며 번호0은 이름 없는 참조에도 대응한다. 기본 미채택·native 승인 이력과 분리하며 원본 시간분포/추가 원가의 보존·명시 통화 전환도 연결한다.

2026-11-15 후속: [Baseline0~10 Cost](xml-numbered-baselines.md)도 각 native 승인본의 동결 원가로 지원한다. 기존 이름 없는 참조는 v1을 유지한다. 외부 XML 기준선 자체의 자동 채택은 포함하지 않는다.

2026-11-14 · XBC-01~06. `[Baseline Cost]`/`[BaselineCost]`는 최초 native 기준선(v1)의 동결 원가를 반환한다. 현재 계획 원가·실제 원장·화면의 비교 기준선 선택이나 후속 기준선 버전으로 대체하지 않는다.

| 참조 범위 | 값 |
|---|---|
| 작업 | 동결 배정 원가 + 작업 고정비 + 자재/경비 |
| 프로젝트 | 이후 삭제된 작업을 포함한 동결 전체 작업 원가 |
| 자원 | 동결 자원 배정 원가 합계. 작업 직접비는 포함하지 않는다. |
| 배정 | 해당 동결 작업/자원 조합의 배정 원가 |

배정 식에서 `[Task.Baseline Cost]`·`[Resource.Baseline Cost]`로 소유 작업/자원을 조회한다. `[Project.Baseline Cost]`는 모든 범위에서 전체 동결 프로젝트를 조회한다. 금액 숫자는 현재 통화의 주요 단위(USD의 달러, JPY의 엔)이며 `CStr`·숫자 연산·Cost/Number/Text 필드에 조합할 수 있다. 최종 필드의 기존 범위·반올림을 별도로 적용한다.

## 동결 계산과 미확정

최초 기준선의 저장된 일정과 동결 달력·중단·곡선·FixedWork 부분 단위를 사용한다. 기존 `plannedCostDays`와 같은 배정/날짜별 정수 최소통화 단위 반올림·해당 날짜의 동결 단가·고정비 발생 방식·자재/경비 계산을 재사용한다. 현재 달력·단가·기간·실적·후속 기준선으로 다시 평가하지 않는다. 현재 계획이 미계산/stale여도 올바른 기준선 문맥에서 조회한다. 도메인 단독 조회는 명시 평가 문맥을 요구하며 worker/표/보고서는 이를 제공한다.

동결 당시 존재한 미사용 자원·무공수 배정의 배정 원가는0이다. 작업 직접비는 명시0이 있어야 알려진0이다. 현재에만 추가된 작업·자원·배정과 기준선 없음은 사유가 있는 미설정이다. 원가 엔진이 미확정으로 반환한 단가/고정비 누락 또는 구성 원가 한도 문제도 미설정이며 저장된99/777·현재 원가·임의0으로 채우지 않는다. 명백한 합계 초과·통화 불일치·잘못된 기준선 버전/일정·잘못된 입력은 오류다.

원가 계산의 오류는 별도 경로로 보존하여 기존 Baseline Start/Finish/Duration/Work 값을 원가 누락 때문에 숨기지 않는다. 취소는 worker로 전파한다. 원가 계산 과정은 원본 입력·원장·동결 사본을 변경하지 않는다.

WBS/필터 그룹은 **현재 그룹에 포함된 ID**를 동결 객체와 연결해 합산한다. 자원 그룹은 배정 원가만 합산한다. 빈 그룹·동결 값이 없는 포함 행은 미설정이며 묵시 제외하지 않는다. 프로젝트 전체 동결 합계와 현재 그룹 합계의 구성 범위가 다를 수 있다. 배정 roll-down으로 작업의 기준선 원가를 전파한 값은 해당 배정의 자체 원가와 구분한다.

## 통화·저장·교환

동결 통화와 현재 통화가 다르면 자동 환산 없이 오류다. 기존 명시 프로젝트 통화 전환은 동결 단가·고정비·자재/경비도 변환하므로 그 변환된 입력에서 다시 계산한다. 항목별/날짜별 반올림 때문에 원래 총액에 환율을 곱한 값과 다를 수 있다. 예제 USD12.94는 각 동결 항목을1/2 환산한 EUR6.49로 재계산된다. 전후 원본은 기존 통화 이력에 보존한다.

새 `builtin:baselinecost` 바인딩은 활성/비활성 모두 조건부 **schema62**이다. 현재·기준선·시나리오·일정 채택·통화/ID 전후 전체 사본을 검사한다. 과거 태그에서 새 바인딩을 거절하며 기존 네 기준선 참조의 최소50은 유지한다. 바인딩 없는 과거 비활성 원문은 기존 보존 규칙을 따른다. 새 native 데이터 필드는 없다. 저장/재열기·복구·읽기 전용·undo/redo를 연결한다.

편집기의 범위별 참조 삽입·비동기 미리보기·출처 표시와 표·요약·전파·XLSX/PDF를 연결한다. XML에는 식과 현재 정적 결과를 내보내고 참조 이름을 재작성한다. **native 기준선 자체는 XML에 싣지 않으므로 XML 재가져오기 후 재계산 결과는 미설정**이다. 정적 결과를 새 기준선으로 만들지 않는다. XER는 정적 사용자 필드 값이다. 전체 이력은 source.ppm을 함께 보관한다.

개념 원문은 Microsoft의 [Baseline Cost fields](https://support.microsoft.com/en-us/project/baseline-cost-fields)다. 이 앱은 최초 native v1·native 정수 원가 모델을 사용한다. 외부 Baseline0~10 슬롯·번호별 참조·수동 기준선 금액 덮어쓰기·초과근무/사용당 단가나 실제 제품 재계산 동등성을 추가한 것은 아니다. 번호별 기준선 대응·요약 기간·다른 함수와 기존 GAP는 잔여다.
