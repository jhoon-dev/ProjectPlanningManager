# FixedWork/FixedUnits 날짜 고정 잔여 목표

2026-11-08 · DFW-01~06 · GAP-04/11. **자원 → 날짜별 잔여 공수…**에서 고정 공수(FixedWork), 고정 단위(FixedUnits)의 날짜별 미래 배정 수요를 입력한다. 기존 [고정 기간 날짜 입력](dated-remaining-work.md)과 [공수/단위 곡선 역산](work-contour-inverse.md)을 연결한다.

## DFW-01 유지값과 완료 계산

공수 기준 FixedWork/FixedUnits는 **명시 잔여 총공수**를 유지한다. 상태일의 진척 보고가 있으면 보고된 `remainingWorkUnitMinutes`, 미보고 작업이면 계획의 `workUnitMinutes`를 사용한다. 보고에 잔여 공수가 없을 때 실제공수·기간·진척률로 추정하지 않는다. 기존 미완성 진단을 유지한다.

작업의 모든 자원에 지정한 날짜별 목표를 먼저 확보한다. 남은 총공수만 미입력 자원/날짜의 기존 기본률·상대 곡선으로 시간순으로 채운다. 마지막 자유 근무분만 정수 공수로 줄이고, 여러 자원은 비례 배분 후 안정 자원 ID 순서로 나머지를 나눈다. 모든 날짜 목표와 자유 공수가 충족된 가장 이른 완료 시각을 사용한다. 계획 작업 기간과 기본률/곡선은 바꾸지 않는다.

예를 들어 잔여8시간, 11월3일 목표2시간, 11월4일 명시0이면 남은6시간은 다음 미입력 근무일의 기존 곡선으로 채운다. 목표가 기존 예상 완료보다 뒤에 있어도 그 날짜를 유지하며 필요한 대기 구간을 포함한다. 다른 자원의 같은 날짜에는 입력이 없으면 그 자원의 곡선을 사용할 수 있다.

기간 기준 FixedUnits는 진척 보고의 잔여 기간 또는 미보고 계획 기간을 유지한다. 날짜 목표와 나머지 날짜의 상속 수요로 미래 공수가 달라질 수 있는 기존 FixedDuration 정책을 따른다. 기간 기준 작업을 공수 기준으로 자동 전환하지 않는다.

## DFW-02 날짜·달력·정수 규칙

목표는 같은 작업의 모든 배정을 함께 검산한다. 합계가 잔여 총공수를 넘거나 남은 공수를 달력/기존 곡선 안에서 채울 수 없으면 적용을 거절한다. 임의 잔액이나 새 진척 보고를 만들지 않는다. 총공수를 전부 목표 날짜에 지정하면 다른 날짜의 상속 수요는0이다.

각 목표는 후보의 잔여 시작 이후 해당 날짜 전체의 작업/자원 달력 교집합 근무분에 나눈다. 작업 중단·각 달력의 휴일과 점심을 반영한다. `목표 W / 가능 근무분 N`의 몫을 기본률로, 나머지를 앞쪽 실제 근무분에1%씩 배분한다. 한도는0~100,000%이며 양수 목표에 가능 근무분이 없으면 거절한다. 자원 최대 가용률은 묵시적으로 잘라내지 않고 과부하/평준화에서 별도로 검사한다.

시간(h)은 소수4자리 입력과 기존1/100 자원분 반올림을 사용한다. 빈칸은 상속 가능, 명시0은 해당 자원/날짜 수요 없음이다. 실제 완료 뒤의0 목표만으로 작업을 연장하지 않으며 해당 입력을 해제하도록 안내한다. 실제 완료 또는 잔여 총공수0인 작업의 목표도 해제해야 한다.

## DFW-03 일정·여유·평준화

잔여 실행 시작은 작업 달력의 논리 시작에 고정하고, 공수 기준의 상대 곡선은 미래 실행0분부터 적용한다. 실제 시작은 관측값을 유지한다. 선행관계와 시작/완료 제약, 서로 다른 자원 달력에서 완료가 비단조일 수 있으므로 후보를 실제로 재계산하고 제약의 교집합을 검사한다. 날짜 목표를 다른 날로 옮기지 않는다.

논리 여유·자원 총/자유여유는 같은 후보의 정확한 공수/날짜 목표를 검사한다. 공수 기준에서는 모든 후보가 동일 잔여 총공수를 보존한다. 자원 여유는 현재 인계 순서·전체 부하와 작업별 재배치 증인으로 인증한다. 목표 날짜가 가용량을 초과하면 평준화가 이를 다른 날로 밀어 해결하지 않는다.

기존 후보250,000개·판정2,000,000회·후보 구간2,000,000개와 완료 조건/직렬 전진 탐색2,000,000회 한도, worker 취소를 유지한다. 한도/인증 실패 시 여유를 미산정으로 표시하고 정상 전진 예측은 보존한다. 날짜 고정 공수의 새 엔진은 `jobs-dated-effort-1.0`, 채택/시나리오 정책은 `serial-dated-effort-v1`이다. 기존 FixedDuration 날짜 입력 경로와 엔진을 유지한다.

## DFW-04 입력·재검토

미리보기 전에 현재 논리 잔여 예측의 날짜와 기존 곡선을 보여준다. **목표 날짜 추가**로 예상 완료 뒤의 날짜도 입력할 수 있다. 기존 날짜·저장 날짜·추가 날짜를 검토하고 **검산 미리보기 → 문서에 적용**한다. 미리보기에는 새 잔여 완료 시각을 표시한다. 입력 수정은 준비 결과를 무효화한다.

같은 작업의 다른 자원 목표도 총공수에 포함한다. 오래된 상태일의 배정은 하나씩 수정할 수 있다. 아직 수정하지 않은 입력은 원래 기준을 보존하고 전체 예측은 재검토 상태를 유지하며 자동 채택하지 않는다. 다른 작업의 오래된 목표도 별도로 수정할 수 있다. 상태일 변경·목표 날짜 이전에 시작할 수 없는 제약·달력상 불가능·관측 완료에는 재검토를 요구한다. 저장된 목표를 숨기거나 자동 이동하지 않는다.

적용/해제는 한 revision과 undo/redo, 기존 평준화 무효화·결정 원장 정책을 따른다. 취소·닫기·stale 문서/revision/session·권한 회수는 미적용이다. 읽기 전용은 이력/목표 조회만 허용한다. 계획 기간/공수·배정률/곡선·기준선·이미 저장한 시나리오·관측 진척/실제공수/원가 원장은 변경하지 않는다.

## DFW-05 저장·출력

기존 `RemainingWorkPlan`을 사용하지만 새 작업 유형과 실행 의미가 있으므로 조건부 **schema35**다. 현재/시나리오 입력, 평준화 선택/결정 이력 또는 통화 전환/ID 이관의 보존 원본에 새 의미가 있으면35를 쓴다. 기존1~34 최소 writer를 유지하고 구 envelope의 새 조합·미지원 미래36을 거절한다. 스냅샷의 중첩 통화/ID 이관 금지와 기존 크기/행 한도는 유지한다.

배정당1,024일·프로젝트100,000일/10,000배정과 기존 정수 공수 범위를 유지한다. 저장/재열기·복구·독립 사본·평준화 시나리오를 재현한다. Usage·부하·유효일별 단가 원가와 잔여 보고서는 같은 실행 구간을 사용한다. EAC 공식·관측 AC는 별도 정책 그대로다. XLSX/PDF 보고서에 날짜 목표·명시0과 계산 의미를 포함한다. XML/XER은 날짜 목표의 미지원 손실을 표시하고 `source.ppm`에 보존한다.
