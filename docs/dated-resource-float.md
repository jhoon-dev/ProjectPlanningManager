# 날짜 고정 잔여 입력의 자원 여유

2026-11-06. DFL-01~04, GAP-04/06/11, PRD-03/05/06/07, J-03/05/06/08/14에 연결한다. [날짜별 잔여 입력](dated-remaining-work.md)이 있는 잔여 평준화의 총여유·자유여유·임계와 재배치 증인을 계산한다. 원본 일정·실적·입력 날짜는 수정하지 않는다.

2026-11-08 [FixedWork/FixedUnits 후속](dated-effort-targets.md)은 공수 기준의 모든 후보에서 날짜 목표와 동일 잔여 총공수를 함께 보존한다. 아래 총공수 가변 문장은 기존 기간 기준에 적용한다. 새 조합의 엔진은 `jobs-dated-effort-1.0`, 저장은 schema35이며 실제 후보의 정확 실행·자원 증인을 같은 경로로 인증한다.

- **DFL-01 후보 의미**: 현재 평준화 배치보다 이른 시작을 허용하지 않는다. 각 후보의 작업/자원 달력·휴일·중단과 실행 구간에서 고정 날짜 목표를 다시 배분한다. 날짜 밖 목표·양수 가용 시간 없음·필요 배정률 상한 초과는 해당 후보를 제외한다. 목표를 다른 날로 이동하거나 버리지 않는다. 미입력 날짜의 기존 곡선 상속은 그대로 적용하므로 후보 총공수 자체가 고정되는 정책은 아니다.
- **DFL-02 정확 탐색**: 기존 재분할 후보·논리 관계·현재 FIFO 인계/교차 작업의 최종 반환 순서와 실제 시간축 용량을 사용한다. 날짜 고정 수요에는 상대 곡선의 ‘전체 구간 양수 수요’ 단조성 최적화를 적용하지 않는다. 허용 후보를 유한 열거하고 실제 배정률로 검사하며, 시간축 최소 수요·끝점 지지 전파는 같은 정확 후보 집합에서 수행한다.
- **DFL-03 결과와 근거**: 총여유는 다른 작업도 허용 범위에서 이동하는 작업별 최대 시작 지연이다. 자유여유는 나머지 작업의 현재 날짜를 고정한 최대 지연이다. 각 총여유에 실제 가능한 날짜 증인을 보관하고 전체 부하로 다시 인증한다. 최후 날짜를 모든 작업에 동시에 적용하는 일정으로 해석하지 않는다. 여유 0의 임계 여부, 인계/논리 원인·표/간트/보고서/증인 창은 기존 흐름을 사용한다. 성공 결과는 `jobs-dated-remaining-1.1` / `resource-dated-float-v1`로 식별한다.
- **DFL-04 안전한 미산정**: 기존 탐색 한도(작업10,000·후보250,000·판정2,000,000·후보 구간2,000,000)와 취소를 유지한다. 가용량 미정·한도 초과·전체 증인 인증 실패는 원인과 함께 미산정으로 남기며 부분 여유나 오래된 증인을 게시하지 않는다. 입력/채택/시나리오의 저장 형식은 바꾸지 않는다. 과거 날짜 입력 없는 엔진 경로도 유지한다.

수용 검사: 독립 4분 달력의 가능한 배치 전수 열거로 목표100/200/300/400 정수 공수 각각의 최대 총/자유여유를 대조한다. 목표 작업 총여유는3/2/1/0분, 자유여유는0분, 후속 자원 작업은 총/자유6분이다. 생산 후보 탐색이나 TaskExecution을 oracle로 재사용하지 않는다. 증인의 목표 충족·전체 용량·프로젝트 끝, 취소와 기존 채택/undo·시나리오 재현을 확인한다. [최종 검증](validation/dated-float-udf-2026-11-06/README.md).
