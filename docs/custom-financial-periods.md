# 사용자 정의 기간·기간 마감

2026-11-08 증분. `custom-financial-period-v1`, CFP-01~06의 지원 계약이다.

## CFP-01 · 기간과 기간액

**원가 → 사용자 정의 기간·기간 마감…**에서 승인 기준선, 이름, 시작일·종료일을 선택한다. 날짜는 양끝을 포함한다. 같은 기준선의 사용자 기간은 겹치지 않으며 빈 구간은 허용한다. 서로 다른 기준선은 별도 기간을 가질 수 있다. 열려 있는 기간의 정의와 금액을 수정하면 새 이력이 추가된다.

각 기준선 작업에 기간 예산 PV와 기간 인정 EV를 독립 지정한다. 통화 최소단위 정수로 저장하며 UI는 프로젝트 통화 소수 자릿수를 따른다. PV는0 이상, EV는 음수 정정도 허용한다. 기간 인정 EV는 종료일 이후 상태일에서 입력하며, 조회 상태일을 기간 내부로 되돌리면 지정 EV 전체를 사용하지 않고 그 시점의 native 관측을 조회한다. 빈칸은 해당 native 누계의 마감−개시 증감으로 계산한다. 명시0은 알려진0이다. native 개시/마감이 미보고인 경우 지정하지 않은 기간액도 미정이며0으로 메우지 않는다. 부분 지정은 작업별로 적용한 뒤 프로젝트·기준선 WBS에서 합산한다. 알려지지 않은 작업이 있으면 합계도 미정이다.

기간 지정액은 **해당 관리기간의 PV/EV·CV/SV/CPI/SPI**에 사용한다. 동결 기준선 BAC, native PV/EV 누계, 물리 진척, AC, Steps, 기존 보고 원장이나 XER 원본을 다시 쓰지 않는다. 보고서의 `native 기간 PV/EV`와 `native 마감 PV/EV/AC/EAC/ETC`는 별도 근거 열이다. EAC/ETC는 선택한 native 누계 추정식으로 계산하며 기간 지정액을 누계로 가장하지 않는다. 기간액을 임의 일별로 배분하거나 전체 native 곡선으로 보간하지 않는다.

## CFP-02 · 기간 보고와 대사

**기간 보고서…** 또는 **원가 → native 기간 EVM… → EVM 기간 단위 → 사용자 …**에서 조회한다. 사용자 기간 선택 시 기준선·날짜는 저장된 정의를 사용한다. 전체 코호트와 기준선 WBS 집계, 작업별 원가/EV 근거 ID, 지정 금액 적용 작업 수를 보여 준다. 계산 API는 기준선 WBS 부분 범위도 지원한다.

개시 경계는 시작일00:00 미만, 마감 경계는 종료일23:59 이하이다. 열린 현재 기간의 관측은 현재 상태시각까지만 사용한다. 미래 EV/AC를 예측하지 않는다. PV는 동결 기준선 계획값이다. 날짜배분 AC는 그 조회 상태일에 알려진 실제 날짜 명세이며 누계 원가에 다시 더하지 않는다. `보고증감−날짜배분`은 배분 누락·보고 지연·정정을 포함하는 대사 차이다. 연도0001/9999 경계도 날짜를 넘겨 만들지 않는다.

## CFP-03 · 당시 지식 마감

종료일23:59 이상인 상태일에서 **기간 마감 → 검토 계산 → 확인 → 반영**한다. 미정 금액도 미정인 채 마감한다. 작업별 native 개시·마감 BAC/PV/EV/AC, 추정 지원 여부, 당시 원가/EV 보고 ID와 날짜배분 AC를 고정한다. 기준선·기간 지정액·추정식, 상태일, 작성자/사유/UTC, 원본 문서, `knowledgeRevision`(마감 직전 revision)과 기록 revision을 함께 저장한다. 현재 계획이나 뒤 보고, 외부 XER 채택/철회 정책이 바뀌어도 마감 수치는 재계산하지 않는다.

마감 이후의 보고서 생성 시각과 현재 파일 revision은 현재 값이다. 계산 근거의 지식 revision·마감 이력 ID·원본 문서가 실제 고정된 지식을 식별한다. 과거 마감의 숫자와 근거는 그 마감 이벤트를 명시 선택해 재출력한다.

## CFP-04 · 잠금·재개방·재마감

활성 마감 기준선의 작업에 대해서 마감일 이전(포함)의 상태일로 누계 원가·진척·Steps 보고를 추가할 수 없다. 날짜별 실제공수/원가 명세는 제출 상태일과 실제 날짜 모두 검사하므로 뒤 상태일에 과거 날짜로 배분하는 우회도 거절한다. 개시 누계 변경도 기간 성과를 바꿀 수 있어 마감 기간 시작일보다 이른 보고까지 잠근다. 새 XER 편집/배분이 native 원장을 생성하면 같은 잠금을 적용한다.

뒤 상태일의 새 관측, 현재 계획 편집과 외부 원본/채택 이력은 계속 기록할 수 있다. 마감 보고는 별도로 보존한다. 실제 정정이 필요하면 같은 기준선의 가장 뒤 마감부터 **마감 재개방**한다. 같은 작업을 다른 기준선에서도 마감했다면 관련 활성 마감 잠금도 풀어야 한다. 재개방은 이전 마감을 삭제하지 않는다. 정정 후 재마감하면 새로운 지식 revision과 새로운 마감 이력이 생긴다. 마감 기간의 이름·날짜·지정액 변경도 먼저 재개방해야 한다.

## CFP-05 · 파일·복구·교환

`financialPeriodEvents`가 있는 파일만 조건부 **schema30**으로 기록한다. 정의·마감·재개방은 모두 불변 전이이며 일반 undo로 제거하지 않는다. 뒤 계획 편집의 undo/redo는 이력을 유지한다. 저장/재열기, 자동 복구, 독립 사본도 최초 문서·기록 revision과 전체 마감을 보존한다. 기간 이력이 생긴 뒤 단순 통화 재해석은 거절한다.

이력이 없는 문서는 기존 schema1~29 writer를 유지한다. 구 envelope의 새 필드, 미래31, 미지 키/형식·정수 정밀도·참조/날짜·전이/겹침·통화·revision·마감 코호트와 기록 당시 잠금 위반을 거절한다. 최대512개 이벤트, 누적 지정/마감 작업 참조100,000개, 기존 native64MiB와 보고서1,000,000셀 한도를 따른다. 원장은 revision으로 한 번 색인해 각 마감/재개방 사이의 잠금 준수를 검증한다.

XLSX/PDF는 기간값·native 누계·마감 이력과 계산 근거를 함께 출력한다. XER/XML에는 이 native 정책을 매핑하지 않으며 교환 진단에 source.ppm 보존을 명시한다. 사용자 기간 때문에 기존 XER 재무 원본의 현재성 투영 지문을 변경하지 않는다. P6/MS Project의 고유 기간 마감 동작이나 실제 제품 재계산·재저장을 검증한 것은 아니다.

## CFP-06 · worker와 검증

편집기는 가상 작업 표, 기본1100×760/800×600, 스크롤 가능한 정의, 고정 확인/반영·취소 footer를 사용한다. 검토 worker는 live 문서를 변경하지 않는다. 실제 반영은 문서/revision/session/저장 상태/권한을 재검사하며 변경된 초안·잘못된 금액은 검증 결과와 확인을 해제한다. 계산 취소·창 닫기는 진행 중 worker를 취소하고 오래된 결과를 반영하지 않는다. 읽기 전용에서도 기존 기간·이력 보고를 조회할 수 있다.

`custom_financial_period_contract/ui`, 기존 native EVM·XER·원장·파일/복구와 전체 CTest를 실행한다. `scripts/verify-custom-financial-periods.py`는 앱 계산 함수를 호출하지 않고 raw 원장의 상태일·기록 revision·ID와 Decimal로 native 개시/마감 및 지정 기간액을 재구성한다. 프로젝트/작업/WBS·과거 마감/재마감, 실제 XLSX/PDF를 판독한다.

최종 전체134/134(163.78초), 집중29/29(36.66초), 파서390개·형식362파일, 독립340개 수치 및 화면 XLSX170개 수치·Windows 1만 작업/800×600·기존 native/XER reader를 통과했다. PDF의 검색 가능한 텍스트 판독과 Windows 네이티브 벡터 윤곽선의 구조/시각 검사를 구분한 [검증 기록](validation/custom-financial-periods-2026-11-08/README.md)을 따른다.
