# XML 계산식 시간대 변환

2026-11-13 · XTZ-01~06. 사용자 필드의 **XML 계산식…**에서 명시 시간대 간 변환과 오프셋 포함 문자열을 지원한다. 이 기능은 **PPM 확장 함수**이며 Microsoft Project 표준 함수가 아니다. PC의 시간대·로캘·현재 시각을 추측하거나 네트워크의 최신 자료를 자동 적용하지 않는다.

## 함수

| 함수 | 결과 |
|---|---|
| `PPMTimeZone(date, from, to [,overlap])` | 원본 민간 시각을 해석한 뒤 대상 시간대의 Date 값으로 변환한다. 결과 자체에는 시간대 표지가 없다. |
| `PPMTimeZoneText(date, from, to [,overlap])` | 같은 변환을 `YYYY-MM-DDTHH:MM:SS[.소수6자리]Z/±HH:MM` 문자열로 반환한다. UTC에서 중복 시각으로 변환해도 해당 실제 시점의 오프셋을 보존한다. |
| `PPMTimeZoneOffset(date, zone [,overlap])` | 해당 현지 시각의 **UTC 오프셋 초**를 부호 있는 정수 Number로 반환한다. 역사적인 초 단위 오프셋도 정확히 반환한다. |
| `PPMParseUtc(text)` | 명시 `Z` 또는 `±HH:MM`이 있는 완전한 ISO 일시 문자열을 UTC 민간 시각의 Date 값으로 반환한다. |

함수 이름은 기존과 같이 ASCII 대소문자를 구분하지 않는다. 시간대 이름과 정책 문자열은 정확히 지정한다. date는 기존 Date/Start/Finish 값 또는 오프셋 없는 ISO 날짜/일시 문자열이다. 날짜만 있으면 자정이다. 이미 오프셋이 붙은 문자열은 PPMParseUtc로 UTC를 구한 뒤, 다시 변환할 때 출발을 UTC로 지정한다. Date 결과에는 시간대 표지가 없어 잘못 지정한 출발 시간대를 자동 판별하지 않는다.

```text
PPMTimeZone([Start], "2026f:Asia/Seoul", "UTC")
PPMTimeZoneText([Start], "2026f:Asia/Seoul", "2026f:America/New_York")
PPMTimeZoneOffset([Start], "2026f:Asia/Seoul")
PPMParseUtc("2026-11-13T09:30:00.123456+09:00")
```

예를 들어 서울09:30:00.123456은 UTC00:30:00.123456이다. 11월 뉴욕에서는 전날19:30:00.123456이 되며 Text 결과는 `-05:00`을 포함한다. 일반 Date 결과에는 오프셋이 없으므로 서로 다른 시간대의 Date를 비교할 때는 양쪽을 UTC로 변환한다.

## 시간대 자료와 범위

- 고정 시간대는 `UTC`, `Z`, `±HH:MM`, `UTC±HH:MM`이다. 범위는±14:00 이내이며14시간에서 분은0이어야 한다. UTC와 대상 날짜가 모두 native1~9999년 안에서 표현 가능해야 한다.
- IANA 이름은 **`2026f:Asia/Seoul`처럼 자료 버전을 포함**한다. 고정한 IANA2026f의597개 이름/별칭을 지원한다. 불명확한 초기 설정용 `Factory`는 제외한다. 이름의 대소문자·버전을 추측하거나 Windows 시간대 이름·약어로 대체하지 않는다.
- IANA의 지원 범위는 변환의 실제 UTC가 **1970-01-01T00:00:00 이상, 2101-01-01T00:00:00 미만**이다. 범위 밖에서는 오류다. 현지 날짜가 이 범위 안에 보여도 UTC가 범위를 벗어나면 거절한다.
- IANA 데이터는 실행 파일에 내장된다. 설치 PC의 시간대 자료가 바뀌어도 이 버전의 식은 같은 자료를 사용한다. 나중에 새 자료를 지원할 때도 이전 버전 이름을 다른 규칙으로 조용히 재해석하지 않는다. 알려지지 않은 버전은 오류다.

자료 출처는 [IANA2026f](https://www.iana.org/time-zones/releases)와 Python의 [tzdata2026.6 배포](https://pypi.org/project/tzdata/2026.6/)이다. 원본/패키지 SHA-256, 적용 범위와 생성 파일 해시는 [자료 manifest](../resources/timezones/manifest.json)에 기록한다. 306개 전환 패턴·30,397개 경계로597개 이름을 연결하며, [생성기](../scripts/generate-xml-timezones.py)와 독립 검증용 TZif 사본을 함께 보관한다. 실행 시 Python이나 외부 시간대 파일은 필요하지 않다. Windows 실행 패키지의 `licenses/timezones`에 자료/출처 및 라이선스를 포함한다.

## 중복·누락 시각과 정밀도

`overlap`의 기본값은 `"reject"`이다. 현지 시각이 두 실제 시점에 대응하면 오류이며 `"earlier"` 또는 `"later"`를 명시 선택해야 한다. 선택은 UTC의 이른/늦은 실제 시점 기준이며 DST 여부·전환 폭을 추측하지 않는다. 30분 전환·음수 DST·날짜 전체가 건너뛰는 전환도 같은 규칙을 사용한다.

존재하지 않는 현지 시각은 모든 정책에서 거절하며 앞으로 밀거나 다른 시간대로 바꾸지 않는다. 예를 들어 뉴욕2026-03-08의02:30은 거절한다. 2026-11-01의01:30은 earlier이면05:30UTC, later이면06:30UTC이다.

```text
PPMTimeZone(#2026-11-01T01:30:00#, "2026f:America/New_York", "UTC", "later")
PPMTimeZoneText(#2026-11-01T05:30:00#, "UTC", "2026f:America/New_York")
PPMTimeZoneText(#2026-11-01T06:30:00#, "UTC", "2026f:America/New_York")
```

뒤의 두 Text 결과는 같은01:30이지만 각각 `-04:00`과 `-05:00`이므로 PPMParseUtc로 서로 다른 원래 시점을 정확히 복원한다. 반대로 Date 결과만 보관하면 이 구분은 사라진다. UTC에서 대상 시간대로 변환하는 경우에는 UTC 시점이 이미 하나이므로 대상 중복 정책을 다시 추측하지 않는다.

초와 최대6자리 소수 초를 정수 마이크로초로 보존한다. PPMParseUtc는 대문자 `T`·초·명시 오프셋을 요구하며 윤초·7자리 소수·지역 날짜 표기·알 수 없는 오프셋 `-00:00`은 거절한다. 이는 [RFC3339](https://www.rfc-editor.org/rfc/rfc3339)의 전체 허용 범위를 구현했다는 의미가 아니라 native 날짜 범위와±14:00을 적용한 명시 지원 부분이다. 과거 IANA 오프셋이 초 단위이면 PPMTimeZoneOffset/Date 변환은 정확히 처리하지만 ±HH:MM 문자열로는 손실 없이 쓸 수 없어 Text 함수가 거절한다. 자동 분 반올림을 하지 않는다.

Null은 기존 계산식 규칙대로 전파하며 오류/미설정을 저장된 스냅샷·0으로 대체하지 않는다. 기존 전체 인수 평가·식 크기/단계/깊이·취소와 형식별 결과 검증도 유지한다. 시간대 함수 뒤에 DateValue·DateDiff·근무 달력 함수를 조합할 수 있으나 근무 달력은 기존 민간 시각 달력이고 DST를 반영한 실제 경과 시간 계산으로 자동 바뀌지 않는다.

## 편집·저장·교환

XML 계산식 창에서 함수·출발/대상 시간대·중복 시각 정책을 골라 **시간대 변환 예시 삽입**을 누른다. 시간대는 직접 입력할 수도 있다. PPMParseUtc를 선택하면 출발/대상/중복 선택은 사용하지 않고 명시 오프셋 문자열 예시를 삽입한다. 결과는 기존 비동기 미리보기에서 확인하고 Save/취소·읽기 전용·문서 변경 검사를 사용한다.

활성 시간대 함수가 현재·기준선·시나리오·일정 채택·통화/ID 이관의 전체 사본에 있으면 조건부 **schema53**이다. 새 영속 필드는 추가하지 않는다. 기존 추가 함수의 최소52 등 이전 writer를 유지한다. 과거에 비활성 보존한 확장 식은 기존 schema44부터 읽고 자동 활성화하지 않는다. 활성 시간대 함수가 담긴 schema52 이하 문서는 거절한다. 공유 버전 상한을 저장/전체 사본/복구·파서·미지원 미래 버전 검사에 적용한다.

입력 필드 이름이 바뀌어도 안정 ID 바인딩을 유지하고 네 범위·요약/전파·혼합 native 식·저장/복구·undo·감사 XLSX/PDF를 사용한다. 시간대 결과를 계획 기간·일정·진척/실제 원장에 자동 적용하지 않는다. 프로젝트 전체의 기준 시간대나 원본 보고의 시간대를 추측하지 않는다.

XML은 식 정의와 현재 값을 출력하지만 확장 함수를 외부 제품에서 재계산하지 못할 수 있다. 일반 날짜 요소는 기존의 시간대 없는 값이다. 오프셋을 교환하려면 Text 결과와 원본 식/입력 Text·source.ppm을 함께 보관한다. XER는 현재 결과의 정적 투영이다. 이 기능은 일반 XML 일정 날짜나 날짜 리터럴 `#…#`에 오프셋을 자동 허용하는 변경이 아니다. 오프셋 문자열은 PPMParseUtc의 문자열 인수로 전달한다. 실제 MS Project/P6 열기·재계산·재저장 동등성은 미검증이다.
