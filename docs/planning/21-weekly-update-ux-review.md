표시/선택 작업 수·작업 ID·전체 계산 범위와 전체 완료일을 구분하고 표시 작업 완료일로 시간축을 이동한다.

자원 하위 메뉴와 전체5개 자원 비교를 확인했다. 조립 표시 완료11-19와 전체 완료11-24를 구분했다.
회귀11개와 Windows 네이티브 검사5건을 통과했고 원본 저장 바이트·schema·엔진을 보존했다.

회의용 기본 범위는 전체 프로젝트·화면 필터 제외다. 표시/선택 범위와 기존 상세 열·저장 설정으로 돌아갈 수 있다.

## UX-W05 수정 후속 — 2026-11-17

주 창의 결과 비교에서 기준선·현재 계획·자원 조정 전 실적 예측·현재 적용 일정의 완료일과 편차를 나란히 표시한다.
편차는 기준선 달력의 근무일·시간으로 표시하며, 보고 범위·미보고 가정·배정 작업 검증 범위를 함께 안내한다.
자원 비교에는 현재 적용 일정과 검토 후보를 분리하고 요약 행에서 조정 전·후·현재 부하 근거로 이동한다.
작업별 실적·관계·배정과 채택 사유·결정 이력으로 연결하며 엔진·revision·전체 진단은 펼쳐 볼 수 있다.
Windows 실제 화면에서 기준선11-17, 논리 예측11-20, 후보/채택11-24와 편차+3d/+5d,
과부하16h→0h, 채택 후 현재 적용 결과·이력·저장을 확인했다. 기존 작업·보고·기준선과 이전 결정 기록을 보존한다.
기준선 없음·미정·휴일 편차·다른 A/B 입력·채택 해제·오래된 결과는 자동 검사로 확인했다.
[사용법](../outcome-summary.md) · [검증과 실제 화면](../validation/outcome-summary-2026-11-17/README.md).
이후 UX-W06에서 회의용 출력 기본값을 보완했다. 실제 사용자 과업 성공 판정은 별도로 남아 있다.

## UX-W04 수정 후속 — 2026-11-17

작업 표 위에 파일 저장 상태와 일정 계산 상태를 나란히 표시하고 각각의 명령과 다음 행동을 붙였다.
주간 갱신에는 입력 마치고 재예측을 제공한다. 보고 정정 뒤 단순 닫기는 미저장·재계산 필요를 유지하며,
명시적으로 재예측하면 계산 완료·미저장을 함께 표시한다. 파일 저장은 계산을 대신하지 않는다.
Windows 실제 화면에서 두 상태의 전환과 버튼 연결을 확인하고, 자동 검사로 기준선 저장·재열기·읽기 전용,
불완전·충돌·취소를 구분했다. 기존 계산·출력·채택의 유효성 검증과 파일 형식은 유지한다.
[사용법](../save-reforecast-flow.md) · [검증과 실제 화면](../validation/save-reforecast-flow-2026-11-17/README.md).
이후 UX-W05에서 기준선·예측·자원 조정 결과 요약을 보완했다.

## UX-W03 수정 후속 — 2026-11-17

툴바·추적 메뉴의 주간 갱신 창에 상태일, 이번 주 확인 대상, 기존 보고와 미보고, 실제/잔여 기간과 보고자를 모았다.
선택한 상태일 기준으로 현재 보고·이번 주 앞선 보고·이전 주 보고·미보고를 구분한다.
미보고를 미착수/0%로 추정하지 않으며, 기본 대상에는 향후 계획도 포함될 수 있음을 안내한다.
전체 프로젝트를 작업 ID로 연결하고 필터·검색·입력/정정·다음 미보고 대상 선택을 제공한다.
저장 후 다음 대상의 기존 실적 입력창을 연속으로 연다. 취소하면 해당 초안과 연속 입력만 중단하고 앞선 제출은 유지한다.
Windows 실제 화면에서 상태일 변경·2건 연속 제출·다음 초안 취소·필터·저장·재열기를 확인했다.
[사용법](../weekly-update.md) · [검증과 실제 화면](../validation/weekly-update-flow-2026-11-17/README.md).
이후 UX-W04에서 파일·일정 상태와 다음 행동, 주간 입력 마치고 재예측 연결을 보완했다.

## UX-W02 수정 후속 — 2026-11-17

계획·실제 소요·잔여 기간에 숫자=일과 d/h/m 입력, 정확한 일 단위 표시를 적용했다.
작업 달력의 하루 근무량을 안내하고, 기본8h와7h 달력의 입력·저장·재진입을 확인했다.
공수·분 단위 저장·기존 파일·기준선/보고 원장을 보존한다. 소수 분은 거절하고 오류를 화면에 표시한다.

## UX-W01 수정 후속 — 2026-11-17

상태일 창에 최소 초기 크기 560×280과 확대 글꼴에 따른 크기 계산을 적용해 날짜·시각·해제 옵션·설명을 처음부터 표시한다.
실제 앱에서 날짜 입력·적용, 변경 초안 취소, 해제, 적용/취소/해제 후 재진입을 확인했다.
취소 전후 저장 바이트가 같고 해제 후 기준선1개·실적3건이 보존된다.
기본/125%/150% 글꼴의 Windows 초기 배치 검사와 관련 회귀를 통과했다.
[수정·검증 기록](../validation/status-date-dialog-2026-11-17/README.md).
아래 최초 관찰은 수정 전 증거로 보존한다. 주간 갱신 전체 무도움 성공은 아직 재판정하지 않는다.

## 판단

첫 개선은 기능 확장보다 **상태일 입력창의 표시 복구**다. 주간 갱신의 첫 필수 입력이 잘려
정상적인 흐름을 완료할 수 없었다. 다음은 기간 단위 통일, 주간 입력 대상과 다음 행동 안내,
계획/예측/자원 조정 결과 요약, 회의용 출력 기본값 순서다.
임계 색상, 기준선 간트 겹침, 실적 정정, 자원 과부하 비교·채택과 PDF 출력은 이미 존재한다.
기존 기능의 부재로 기록하지 않고 사용자가 연결해 수행하기 어려운 부분을 개선한다.

중간에 준비 파일의 schema 지정 오류와 같은 문서 ID 사본 열기 거절도 발생했다.
전자는 점검 자료 작성 오류로 바로잡았고, 후자는 독립 ID를 가진 합성 사본으로 분리했다.
이 두 사건을 앱의 일반 사용 결함으로 우선순위에 포함하지 않는다.
전체 WEEK-01~07 무도움 성공은 **미통과**다. 상태일 입력 복구 후 동일 과업을 다시 수행해야 한다.

## 개선 우선순위와 수용조건

P0는 첫 파일럿의 필수 과업을 막는 문제, P1은 입력·판단·전달에 직접 영향을 주는 문제,
P2는 그 뒤의 탐색·표시 보완이다. UX-W01~07은 위 후속 기록대로 구현·Windows 검증을 완료했다.
아래 표는 최초 요구와 수용조건을 보존한다. 실제 대상 사용자의 무도움 과업 성공은 별도 판정한다.

| 순서 / ID | 우선순위·요구 연결 | 바꿀 경험과 확인 조건 |
|---|---|---|
| 1 / UX-W01 | P0 · WEEK-03 / PRD-05 | 상태일 창을 내용 기반 초기 크기로 열고 화면보다 큰 경우에만 본문을 스크롤한다. 처음 열 때 날짜·시각·설명·해제 옵션·확인/취소를 읽고 조작할 수 있어야 한다. 11-13 09:00 입력·취소·해제·재진입을 native 화면에서 확인한다. 작은 화면과 배율별 검증을 추가한다. |
