# 미개발 항목 점검과 후속 순서

**현재 잔여 목록은 [2026-11-06 재점검표](18-remaining-priorities-review.md)를 따른다.** 아래 순서는 증분별 당시 판단을 보존한 개발 이력이다. 1~8의 지원 부분과 서버 인증/실시간 동기화/HTTP/주기 실행은 구현되었다. 계획 공수 변환에 이어 자원 그룹/필터→고정 기간 날짜별 잔여 공수→숫자 계산식, 후속 날짜 고정 자원 여유→외부 UDF 매핑의 지원 부분도 구현했다. [최신 검증 기록](../validation/dated-float-udf-2026-11-06/README.md). 실제 제품 왕복·기업/배정 UDF·FixedWork/FixedUnits 역산은 후속이다.

점검일: 2026-11-05. [GAP 우선순위](16-product-gap-priorities.md), [로드맵](06-roadmap.md), 실제 domain/application/persistence/UI와 회귀 검사를 대조했다. 기존 작업 폴더의 미커밋 구현도 현재 구현으로 포함했다. 과거 문서의 당시 미구현 표기를 그대로 재개발 대상으로 삼지 않는다.

## 현재 확인한 구현

native 계획·잔여 여유/임계, 작업 필드/코드/그룹/저장 보기, 시간축 Usage와 기간 실적 정정, 평준화 채택과 자원 순서 여유/근거, 일정표 인쇄, 네트워크 조회, 다중 XER 프로젝트 선택, native 진척 정책 비교/채택과 평준화 조합을 구현했다. 기능별 검증의 적용 범위는 각 계약과 `docs/validation` 기록을 따른다.

## 이번 증분의 완료조건

결정 이력은 설정 undo에 포함하지 않는다. 원장 변경만 남아도 dirty로 저장하고, 실패/취소/stale는 설정과 원장 모두 적용하지 않는다. schema 15·기존 파일·사본/복구·계획/잔여·원장 한도·잘못된 JSON·읽기 전용 화면과 기존 전체 회귀를 검증한 결과를 [증거](../validation/leveling-decisions-2026-11-05/README.md)에 기록한다. 이 점검표는 전체 장기 기능의 완료 선언이 아니다.

2026-11-05 후속 요청: 2번 객체 필드는 독립 사전·네 형식·다중 자원 입력/조회·undo/복구·schema16·기준선/시나리오·보고서로 확장했다. [검증](../validation/object-fields-2026-11-05/README.md). 계산식/외부 매핑·자원 그룹/필터는 여전히 후속이다.

2026-11-05 후속 요청: 3번의 기간별 계획 배정 편집·자원 곡선은 고정 기간 native 범위로 확장했다. 다음 본 순서는 4번 인쇄·네트워크 확장이다. 3번의 미지원 역산/직접 공수 입력은 장기 후속으로 분리한다.

3번의 [최종 검증](../validation/assignment-periods-2026-11-05/README.md): 전체 CTest99/99, 파서148 seeds, 독립 native/XLSX/PDF 판독9종, 형식177파일을 통과했다. 고정 기간 배정률 구간의 지원 범위를 넘겨 완료 처리하지 않는다.

4번의 native 확장을 구현했다. 다음 본 순서는 5번 다중 XER 일괄 작업공간/내보내기·교환 확장이다. 고급 선 묶기/배치 최적화·조직/다중 프로젝트 네트워크는 후속이다.

4번 [검증 기록](../validation/print-network-2026-11-05/README.md): 전체101/101 및 최종 영향 범위8/8, 파서160 seeds, 형식190파일, 독립 판독10종을 통과했다. 실제 프린터/다른 OS·고급 선/배치 최적화는 후속 범위를 유지한다.

5번의 일괄 작업공간·내보내기 및 작업 코드 교환 증분을 구현했다. 다음 본 순서는 6번 Steps·LOE·WBS Summary·Actual Dates이며, 5번의 실적·원가·MPP는 별도 후속으로 유지한다. [검증 기록](../validation/xer-batch-2026-11-05/README.md).

7번 [최종 검증](../validation/resource-workspace-2026-11-05/README.md): 전체108/108, 파서194 seeds, 형식233파일, 독립 출력 판독10종을 통과했다. native 자재·비용·역할/고급 우선순위/읽기 전용 통합 일정·공유 평준화의 지원 범위이며, 입고·초과근무·비용 최적화와 여러 파일 일괄 날짜 채택은 계속 후속으로 남긴다.

2026-11-05 후속 요청: 8번의 로컬 운영·위험·자동화 증분을 구현했다. 전체 장기 GAP-13/14 완료 선언이 아니며 [계약](../organization-risk-automation.md)의 지원 범위와 잔여 범위를 유지한다. 기존 1~7번의 외부 제품 왕복·고급 모델·운영 검증 후속도 계속 남아 있다.

## 2026-11-05 서버 후속: 인증 → 실시간 동기화 → HTTP → 주기 실행

사용자 후속 개발 요청으로 GAP-13/14의 서버 인증·동기화·HTTP API·주기 실행을 선택 서버로 구현했다. AUTH-SRV: scrypt/불투명 세션/만료·철회/현재 서버 권한; SYNC-SRV: 순번 feed/WebSocket·long-poll 재연결/깨끗한 화면 갱신·초안 보존/버전 충돌; API-SRV: native 검증·미리보기/현재 권한 재검사·원자 DB commit·멱등 영수증; AUTO-SRV: 영속 간격/소유자 권한·lease/중단 재개·중복 차단/취소·충돌 정지/실행 원장을 수용 기준으로 사용한다. [계약·사용법](../../server/README.md)과 [검증](../validation/server-collaboration-2026-11-05/README.md)을 따른다. 기존 단일 사용자 파일 흐름은 서버를 요구하지 않는다. 서버의 현재 원격 편집 범위는 native batch의 작업 이름/기간이며, 임의 필드 병합·SSO/MFA·cron·HA·실제 외부 배포는 별도 범위다.

서버 후속 [검증 결과](../validation/server-collaboration-2026-11-05/README.md): 전체112/112(서버 HTTP 통합 검사 포함), 파서210 seeds, 형식252파일과 Windows 기본 UI·브라우저 예약 실제 실행/취소·TLS/권한 철회/원자성·중단 복구를 통과했다. 선택 서버와 기존 native batch의 원격 협업 범위이며 실제 운영 배포/보안 감사·SSO/MFA·일반 필드 병합·cron/HA를 완료로 확대하지 않는다.

서버 인증 실패 집계 최종 보정 뒤 영향 범위2/2와 HTTP 통합23개를 추가 통과했다. 정상 로그인은 peer의 실패 제한 예산을 소모하지 않는다.
