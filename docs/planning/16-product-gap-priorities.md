## 1. 판단 기준과 현재 상태

PPM은 핵심 일정·추적·원가 흐름과 검증 기반을 구현한 초기 전문 PM 데스크톱 제품이다. 상용 도구 대체 가능성은 실제 업무와 대상 제품에서의 재계산·교환 시험으로 확인해야 한다.

- 기능명이나 지원 개수만으로 계산 동등성을 판정하지 않는다. MSP 30~40%, P6 15~20%와 같은 근거 없는 완성도 수치는 사용하지 않는다.
- 기능 구현, PPM 자체 수치 검증, 외부 제품 재계산, 실제 업무 수용을 각각 기록한다. 독립 reader와의 대조도 외부 제품 실행을 대신하지 않는다.
- 비교 대상은 제품·버전·빌드·언어·일정 옵션·배포 구성을 고정한다. MS Project Standard/Professional/서버 제품과 P6 Professional/EPPM/Primavera Cloud를 합산하지 않는다.
- 기존 39개 OPEN 확인과제는 조사·검증 과제다. 39개 버그나 39개 미구현 기능으로 해석하지 않는다. 이 문서로 해결 처리하지 않는다.
- 불변 기준선·정정 원장·진단·퍼징은 강점이지만, 상용 제품보다 높은 신뢰성이나 파일 변조 방지·승인자 신원 인증의 증거로 확대하지 않는다.

아래 현황은 개발 착수 전 비교 검토의 스냅샷이다. 이후 구현 상태는 위 검증 기록과 항목별 계약을 따른다.

## 3. P0: 일정 계산과 판정 보완

### GAP-01 — 실적 반영 예측의 여유·임계경로

**문제:** 최초 계획에서 임계를 볼 수 있어도 상태일 이후 남은 작업의 임계를 알 수 없으면 주간·월간 일정 통제에 공백이 생긴다. 이 증분 전 예측은 여유·임계를 산정하지 않았다. 현재 native 구현 범위와 후속 한계는 [잔여 계산 계약](../forecast-float.md)을 따른다.

**추가할 동작**

- 실제 시작·완료를 보존하고, 미완료 작업의 잔여 실행 구간에 대해 전진/후진 계산을 수행한다. 완료 실적을 미래의 조정 가능 작업처럼 취급하지 않는다.
- 잔여 총여유·자유여유·임계 여부와 driving 관계를 표·간트·비교·보고서에 같은 의미로 제공한다. 계획 CPM과 예측 CPM의 기준·정책을 표시한다.
- 4종 관계와 양/음의 지연, 서로 다른 달력·자원 달력·수동 중단·공수 작업·순서 위반 실적·날짜 제약을 함께 다룬다.
- 후진 계산의 종점, 완료 목표일 유무, 제약 충돌·음수 여유 처리, 완료 작업 표시, 임계 판정 기준을 계약에 명시한다. 산정 불가·오래된 결과·취소를 0이나 정상 임계로 대체하지 않는다.

**완료조건**

1. 작은 독립 수기 사례에서 상태일 이후 날짜·총/자유여유·임계 작업이 일치하고, 각 관계·달력·제약 조합의 경계 사례를 검증한다.
2. 상태일 이동·잔여 기간/공수 정정 후 미래 임계가 재계산되며 기존 승인 기준선·실제 날짜·정정 이력이 유지된다.
3. 화면·보고·저장/재열기·복구가 동일 정책의 결과를 재현한다. 예전 기준선/시나리오는 기록된 구 정책으로 재현한다.
4. 1천/1만 작업에서 계산과 취소·화면 갱신을 측정하고 기존 [성능 기록](../performance-integration.md)과 같은 조건으로 비교한다. 임의 응답시간을 약속하지 않는다.

**수용 사례 GAP-T01 — native 자동 회귀·UI 검증:** 월~금 09–12/13–18, 휴일 없음. A→B→C는 FS0, D는 독립, 모두 8h, 자원 제약·날짜 제약 없음. 프로젝트 시작은 2026-11-02 09:00, 상태일은 11-02 18:00이고 A만 같은 날 09:00~18:00 실제 완료했다. 예측 완료일을 후진 종점으로 쓰면 B는 11-03, C는 11-04, D는 11-03에 실행되고 총여유는 B/C 0h, D 8h다. B/C가 미래 임계이며 완료 A의 미래 여유는 적용 대상 아님으로 표시한다. 이 사례만으로 다른 정책·달력의 검증을 대신하지 않는다.

### GAP-02 — 계산 의미 차이와 검증 매트릭스

**문제:** 관계·제약·달력의 이름이 같아도 지연 기준 달력, 마감일, 여유, 순서 위반 처리의 의미가 다르면 날짜와 임계가 달라진다.

**수정·추가할 동작**

- native 정책과 제품별 비교 정책을 구분하고, 입력·정책 버전·예외·차이를 기록한다. 호환을 위해 기존 native 계산을 조용히 바꾸지 않는다.
- 우선 마감일의 총여유 영향, 제약 충돌, 관계 지연의 기준 달력, 자원 달력 교집합, ALAP, 상태일·실적 처리, 공수 유형별 편집 결과를 비교한다.
- 각 사례를 입력 자료→독립 기대값→PPM 결과→외부 제품 결과→차이 원인으로 추적한다. 기능의 존재와 제품 동등성 판정을 분리한다.
- 현재 PPM의 마감일은 별도 마감 여유와 경고를 제공하고 CPM 총여유를 변경하지 않는다. MSP는 마감일이 총여유에 영향을 줄 수 있다. 의도된 native 차이인지, 선택적 호환 정책이 필요한지 결정기록에 남긴다.

**완료조건:** 사례별로 일치·의도된 차이·미지원·미실행을 구분하고 출처·제품 빌드·옵션·입력/출력 해시·PPM revision을 남긴다. 정책 변경은 구 파일·기준선·시나리오 회귀를 통과한다. 관련 OPEN 확인과제는 개별 닫기 증거가 있을 때만 갱신한다.

## 4. P1: 일상 업무와 전환 흐름 완성

### GAP-03 — 사용자 정의 필드·Activity Code·그룹·보기 저장

**추가:** 작업/프로젝트/자원별 필드 정의와 값, 텍스트·수치·날짜·목록 형식, 코드 사전과 계층, 코드 배정, 다중 그룹·정렬·필터·열 배치 저장. 첫 증분은 작업 필드·작업 코드·그룹 보기이며 다른 객체 범위는 후속으로 분리한다. 계산식 필드는 의존성·순환·단위 규칙을 별도 확정한다.

**완료조건:** 코드 이름 변경에도 안정 ID와 배정이 유지되고 삭제 영향·미설정 값이 드러난다. 그룹/필터는 계산 대상이나 원본 선행 번호를 바꾸지 않는다. WBS와 그룹을 중첩해도 작업·공수·원가가 중복 집계되지 않는다. 저장/재열기·undo/redo·복구·읽기 전용·보고서의 일관성을 검증한다. 교환 매핑은 GAP-09에서 별도 판정한다.

### GAP-04 — 시간축 Usage 조회와 실적 입력

**현재 구현(2026-11-03):** [시간축 Usage 계약](../timephased-usage.md)의 작업/자원→배정, 일/주/월 계획·동결 기준선·잔여 공수/원가와 XLSX/PDF를 제공한다. 인시/장비시를 구분하고 고정비를 별도 행에 한 번만 합산한다. 잔여 원가는 배정 자원 원가이며 고정비/EAC/ETC를 포함하지 않는다. 실제원가는 기간 미배분 작업 누계로 표시한다. 기간별 관측 실제 입력·정정과 명시 누계의 배분/미배분 대사는 후속 [기간 실적 계약](../period-actuals.md)으로 구현했다. 계획의 기간별 배정 편집·자원 곡선·자동 실적 추정은 제공하지 않는다.

**로컬 검증:** [전체 CTest 69개·독립 출력·화면·1천/1만 제한 범위 측정](../validation/timephased-usage-2026-11-03/README.md)을 통과했다. macOS/Linux·실제 MSP/P6·CI/배포 증거로 확대하지 않는다.

**기간 입력 후속 검증:** [전체 CTest 71개·원장/누계 대사·정정·복구·독립 출력·입력 화면](../validation/period-actuals-2026-11-03/README.md)을 통과했다. 누계는 사용자가 명시하며 부분 보고를 전체 실적의 완전성으로 간주하지 않는다.

**문제:** 기존 자원·날짜별 부하 분석을 작업/배정 상세의 기간별 관리로 확장해야 한다.

**추가:** 작업→배정, 자원→배정 계층과 일/주/월 시간축에서 계획·기준선·실제·잔여 공수와 원가를 조회한다. 초기에는 조회를 제공하고 이후 실제 공수·잔여량·실제원가 입력을 연계한다. 계획 배정 편집은 별도 정책으로 정의한다.

**설계 선행조건:** 현재 누적 원가·작업 실적만으로 과거 자원별 실제 공수나 일별 실제원가를 추정 생성하지 않는다. 배정별·기간별 실적 모델과 정정 원장을 정의하고, 일별 근거가 없는 누적 자료는 기간 미배분으로 구분한다. 노동 공수와 장비 공수는 다른 단위로 유지한다.

**완료조건:** 기간 경계·휴일·달력 교집합·분할·상태일·반올림을 포함해 배정→작업/자원→프로젝트 합계가 검증된다. 과부하는 기존 동시간대 계산을 유지하며 일평균으로 대체하지 않는다. 입력은 하나의 명시적 정정/편집으로 반영되고 기준선·기존 보고 이력을 덮어쓰지 않는다. 필터·그룹·보고서의 범위와 합계가 일치한다.

### GAP-05 — 실제 제품 재계산·재저장 왕복 검증

**추가:** PPM→Project XML/XER→대상 제품 열기·재계산·재저장→PPM 재수입과 역방향을 검증한다. 1차는 현재 지원하는 단일 프로젝트 기간 기반 계획이며, 지원 필드와 미지원 손실을 분리한다.

**완료조건:** 작업/WBS/관계/달력/배정의 보존과 재계산 날짜·여유·임계 차이를 별개로 판정한다. 제품별 빌드·옵션·언어·일/시간 환산·입출력 파일·진단·비교 결과를 보존한다. 최소 대표 사례는 4종 관계·지연·혼합 달력·마일스톤·제약·자원 배정이다. 지원하지 않는 기능은 거절 또는 손실 보고가 기대대로 동작해야 한다. 실행 환경이 없으면 미실행으로 남기며 parser 왕복 성공으로 대체하지 않는다.

**현재 기준:** [공개 XER 검증](../validation/editing-polish-2026-10-30/README.md)은 9개 중 5개 지원 부분 통과, 4개 명시 거부이며 독립 MPXJ 해석과 대조했다. Oracle P6 재계산/재저장 동등성 시험의 통과율이 아니다.

### GAP-06 — 평준화 결과 채택과 취소

**완료조건:** 계산 당시 문서 ID/revision·정책이 현재와 일치할 때만 원자적으로 채택한다. 충돌·불완전·오래된·취소 결과는 적용하지 않는다. 편집 undo/redo로 채택 전후를 복원하고 감사 이력은 보존한다. 저장/재열기·복구·입력 변경 이후 동일 안의 재현과 무효화를 검증한다. 평준화 후 여유는 기준과 자원 대기 반영 여부를 명시하고 원래 논리 CPM 값을 그대로 새 결과에 붙이지 않는다. 총/자유여유·임계의 의미는 GAP-01/02와 함께 검증한다.

## 6. 권장 진행 순서와 완료 판정

1. **일정 신뢰 기반:** GAP-02의 정책/기대값을 먼저 구체화하고 GAP-01을 구현·검증한다. GAP-05의 외부 제품 환경 확보와 사례 준비를 함께 시작한다.
2. **현장 분류·기간별 관리:** GAP-03을 첫 증분으로, GAP-04를 조회→실적 입력 순서로 진행한다. 기간별 실적 모델이 확정되기 전 일별 입력을 출시하지 않는다.
3. **전환·채택·출력 완성:** GAP-05의 현재 지원 부분 왕복, GAP-06의 채택 흐름, GAP-07의 인쇄를 각각 완료한다. 외부 환경 대기 때문에 독립 작업 전체를 멈추지 않는다.
4. **사용 환경에 맞춘 확장:** P6 이관/운영이 우선이면 GAP-09/10, 자원 통제가 우선이면 GAP-11/12, 일정 전달·논리 검토가 우선이면 GAP-08을 앞당긴다. GAP-13/14는 별도 운영/분석 계약을 갖춘다.

각 구현 증분은 다음 자료를 남긴다.

- 요구 ID·PRD/J 연결, 현재 상태와 바뀌는 동작, 계산·데이터·UI·교환 영향 및 정책 결정.
- 독립 기대값과 예외 사례, 실제 실행 결과와 미실행 범위, 소스/정책/파일 버전.
- 해당 변경에 필요한 저장/재열기·기준선/원장·실행 취소/복구·Windows/macOS 회귀 증거.
- 계산/대용량 UI 변경의 성능·취소·오래된 응답 처리 결과, 제품 호환 주장에 필요한 대상 제품 증거.

이 문서의 체크리스트를 채우거나 기능을 구현했다는 사실만으로 전체 MSP/P6 동등성·실무 대체 완료를 선언하지 않는다. 실제 수용 시험은 생성→계획/기준선→상태일 실적→예측 임계 검토→자원 조정안 채택→기간별 원가/성과 확인→출력/교환→저장/재열기를 연결하고, 적용한 범위와 남은 손실을 기록한다.

2026-11-04 GAP-01/02/06 엔진1.4 증분은 후보 제약 전파·고정 작업 분리·반복형 탐색으로 연결64개 제한을 이동 가능128개 제한으로 완화한다. 전체 작업/후보/실행 구간/탐색 한도와 기존1.0~1.3 승인 기준선 재현을 유지한다. 자원 순서 재최적화·자동 선점 분할·불변 채택 결정 원장은 후속 범위다. [상세 계약](../leveling-float.md).

후속 요청의 엔진1.6은 같은 GAP-01/02/06 범위에서 [후보 축소·조건부 전파 PROP-01~04](../candidate-propagation.md)를 구현한다. 안전한 모델의 생성 전 상한, 이웃 후보 제외/복원, 제한된 캐시와 native 인증 공유로 중복 계산을 줄인다. 기존1.5까지의 기준선과 파일 형식을 보존하고 동일 입력의 반복 표본·예산 중단과 완료를 구분한다. [검증 근거](../validation/candidate-propagation-2026-11-04/README.md).
