## 2026-11-02 기능 보완의 권장 순서 (PROPOSED)

사용자 요청으로 현재 기능 공백과 검증 과제를 [GAP-01~14](16-product-gap-priorities.md)로 정리하고 [PRD](01-product-prd.md)에 연결했다. 최초 문서화 이후 후속 개발 요청에 따른 구현 상태는 아래 증거로 갱신한다. 이 절은 아래 과거의 `다음 작업 순서`보다 최신인 기능 개발 순서 제안이며, 별도의 배포·운영 확정 요구는 유지한다.

1. GAP-02 계산 정책·독립 기대값과 GAP-01 실적 반영 예측의 여유·임계를 먼저 보완한다. GAP-05의 외부 제품 환경·비교 자료 확보는 함께 준비한다.
2. GAP-03 사용자 정의 필드·코드·그룹과 GAP-04 Usage 조회를 진행하고, 기간별 실적 모델을 확정한 뒤 입력을 연결한다.
3. GAP-05 현재 지원 부분의 실제 제품 왕복, GAP-06 평준화 결과 채택/취소, GAP-07 일정표·간트 인쇄를 각각 검증한다.
4. 첫 적용 산업과 이관 조건에 따라 GAP-08~12를 진행한다. MPP/다중 프로젝트 이관 또는 P6식 진척이 첫 사용 조건이면 GAP-09/10을 앞당긴다.
5. GAP-13 조직·협업·권한, GAP-14 위험·자동화는 별도 계약을 갖춰 확장한다. 단일 사용자 제품에 서버를 선행 강제하지 않는다.

단계 A~F의 장기 범위와 기존 구현 증거는 유지한다. 추가 기능은 해당 GAP의 상세 수용조건과 정책·파일 호환·회귀 증거가 있어야 완료로 표시한다.

후속 개발 요청으로 GAP-01의 native 잔여 후진 계산과 표·간트·비교·보고 출력 연결을 구현했다. GAP-02는 마감·제약·고정 실적의 native 의미를 먼저 확정했다. [계약](../forecast-float.md)과 [로컬 검증·성능 기록](../validation/forecast-float-2026-11-02/README.md)을 따르며 제품별 비교 매트릭스는 남아 있다.

다음 단계 요청으로 GAP-03의 작업 사용자 필드·계층형 Activity Code·그룹/필터/정렬·열 배치·저장된 보기를 구현했다. [분류 계약](../task-classification.md)과 [전체 CTest 67개·독립 출력·1천/1만 화면 측정](../validation/task-classification-2026-11-02/README.md)을 보존한다. 프로젝트/자원 필드는 2026-11-05 [객체 필드 증분](../object-custom-fields.md)으로 확장했다. 계산식과 외부 UDF 매핑은 후속이다. 다음은 GAP-04의 조회 증분이며 작업/배정·자원/배정의 일/주/월 계획·기준선·잔여 공수/원가부터 구현하고, 근거 없는 과거 일별 실적을 생성하지 않는 기간 미배분 계약을 먼저 정한다.

## 최신 목표와 데스크톱 반영
Windows/macOS 데스크톱 방향은 확정이며 ADR-008에 따라 C++ + Qt 기본 방향을 선택했다. 세부 Qt 모듈/버전/라이선스는 미정이다. 단계 A에서 로컬 파일/복구/이관 계약과 OS 평가 계획, B에서 오프라인 수직 흐름과 파일 충돌, C 이후 선택 협업 확장을 다룬다. F에서는 OS별 설치·업데이트·복구·접근성 검증을 수행한다. 현재 실행·배포 승인은 아니다.
모든 단계에 Parity와 Superiority 결과를 별도로 남긴다. PRD의 SUP-01~05와 DESK-01~09를 단계별 수용조건에 연결한다. 전체 기능 후보는 유지한다.



ADR-008 기본 방향에 따라 세부 Qt 모듈/버전/라이선스 확정과 구현 검증을 위한 ARCH-G0~G6(13-desktop-options.md)을 평가한다. A에서 프로토콜·파일/계산 경계를 설계하고, 향후 구현 승인 후에만 G1~G5 실측·복구·접근성·설치 검증을 수행한다. 기획 v0.1은 현재 자료 통합까지이며 추가 기능 연구로 범위를 계속 늘리지 않는다.

갱신: 기본 언어/UI 방향은 사용자 위임에 따른 C++ + Qt로 선택됐다. A에서 ADR-008의 UI/코어·파일/복구 계약을 검토하고, 향후 구현 승인 후 필수 게이트 증거를 확보한다. 후보 비교는 선택 전제로 반복하는 절차가 아니라 세부안 검증과 실패 시 재검토 경로다.

최우선 PRD-08: A에서 자체 파일 전달·복구·잠금·이관 계약, B에서 계정/서버 없는 새로 만들기→열기→저장→다른 이름→OS간 전달 흐름을 검증한다. 외부제품 교환과 협업은 별도 단계이며 후보를 제거하지 않는다.

REQ-ORA-098 분리: B의 J-03 결정론적 달력 기반과 D-E의 J-11 확률 날씨/비근무 모델을 따로 검증한다. 분포·상관·seed·수렴·quantile이 미검증이면 확률 기능을 완료 처리하지 않는다.

## 2026-11-04 이동 가능128개 초과
