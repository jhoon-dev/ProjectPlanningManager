# 주간 갱신 PM 사용자 시험 진행안

2026-11-18 · 상태: 시험 자료 준비. 참여자 모집·일정·실제 시험 결과는 없음.
[확정 사용자·과업](20-first-user-weekly-update.md) · [UX 개선](21-weekly-update-ux-review.md).

## 목적과 준비

설비·자동화 구축 프로젝트의 PM 겸 공정 담당자가 도움 없이 WEEK-03~07을 끝내고,
완료일 변화와 자원 조정 근거를 설명하며 저장 후 재현하는지 관찰한다.
첫 탐색 표본3명과30개 작업 합성 사례를 제안한다. 표본 수는 확정된 조사 설계나 성공률 추정 근거가 아니다.
참여자별 업무 경력·기존 일정 도구·주간 갱신 빈도만 필요한 범위에서 기록한다.
제품 개발에 참여한 전문가의 점검은 참여자 시험 결과에 합산하지 않는다.

자료는 [사례 설명·원본](../validation/weekly-pm-pilot-2026-11-18/README.md),
[참여자 과업지](../validation/weekly-pm-pilot-2026-11-18/participant-tasks.md),
[빈 관찰 기록](../validation/weekly-pm-pilot-2026-11-18/observation-template.md)이다.
진행자는 이 문서와 사례 설명의 기대값을 읽고, 참여자에게는 과업지만 제공한다.
참여자마다 원본을 별도 폴더에 복사한다. 앱 실행 파일 SHA-256·소스 커밋·OS·배율·화면 크기·언어와
원본 SHA-256을 기록한다. 자동 복구·기존 개인 설정이 결과를 바꾸는지 시작 전에 확인한다.
앱은 로컬 native 프로젝트를 사용하며 계정·외부 제품·서버를 선행조건으로 삼지 않는다.

## 진행 순서

1. 목적은 사용자를 평가하는 것이 아니라 제품에서 막히는 부분을 찾는 것이라고 설명한다.
   화면 녹화나 개인 업무 파일 수집은 기본 절차에 포함하지 않는다. 필요하면 범위·보관 방식을 먼저 합의한다.
2. 같은 과업지를 순서대로 제공하고 사용자가 생각과 판단을 말하게 한다. 메뉴 위치·단축키·정답 날짜는 알려주지 않는다.
3. 과업별 시작·종료 시각, 시도, 도움 요청, 오류, 되돌아가기, 완료일/범위 설명을 기록한다.
   시간은 관찰값이며 합격 제한시간으로 사용하지 않는다. 앱 계산 대기와 환경 장애를 따로 적는다.
4. 도움을 요청하면 먼저 “어떤 결과를 기대하셨나요?”처럼 중립적으로 묻는다. 위치나 절차를 알려주면
   해당 과업을 도움받음으로 기록한다. 지원 내용을 기록한 뒤 다음 과업은 계속 수행할 수 있다.
5. 마지막 저장 파일과 PDF를 복사해 보존하고 원본과 비교한다. 참여자의 실제 설명을 기록한 후 기대값과 대조한다.
6. 마지막에 가장 헷갈린 용어·화면, 기존 주간 업무에서 빠진 단계, 다시 쓰기 어려운 이유를 묻는다.

진행자가 앱 조작을 대신하거나 화면 제어·경로 오류를 복구한 경우 해당 구간의 시간을 분리한다.
환경 장애와 제품 결함을 구분하고, 중단한 단계를 미실행으로 남긴다. 결과를 추측해 채우지 않는다.

## 과업별 판정과 기대값 — 진행자용

사례는6개 셀의 설계→부품→조립/현장 설치→시운전, 각 셀의 조립·설치가 같은 기술자를100% 공유한다.
월~금8h·휴일 없음이다. 현재 원본 상태일은11-13 09:00이며 최초 기준선 완료는11-17 18:00이다.
셀별 설계 완료와 부품 실제2d/잔여2d의 이전 보고12건이 있다. 현재 채택은 없다.

|---|---|

다른 유효한 자원 조정 방식은 별도로 기록한다. 위 숫자는 제시된 입력·정책의 답이며 다른 정책을 틀렸다고 단정하지 않는다.
최초 계획 작성 WEEK-01과 기준선 최초 생성 WEEK-02는 이번 시험의 시작 조건으로 제공한다.

## 관찰값 정의와 후속 판단

각 과업은 **무도움 완료 / 도움받고 완료 / 실패·중단 / 미실행** 중 하나로 기록한다.
완료는 화면상의 결과와 저장·출력물을 확인한 경우다. 날짜가 맞아도 미보고·후보/채택·표시/전체 범위 설명이
틀리면 해당 이해 항목은 실패로 기록한다. 단순 메뉴 탐색 실수와 저장 데이터 오류는 분리한다.
무도움 전체 성공은 WEEK-03~07 모두 무도움 완료이며 핵심 설명과 저장 후 재현이 맞을 때만 인정한다.

- 도움 요청: 사용자가 위치·뜻·다음 행동·오류 복구를 물은 횟수와 내용. 중립 확인 질문은 도움 제공으로 세지 않는다.
- 입력 오류: 잘못 제출된 값과 제출 전 검증으로 막힌 값을 구분. 취소·탐색만 한 행동은 오류가 아니다.
- 시간: 과업 제시부터 결과 확인까지, 실제 초 단위. 환경 장애·진행자 개입 시간을 별도 기록한다.
- 이해: 기준선/현재 계획/예측/채택, 미보고/미착수, 계산/저장, 표시/전체 범위 각각 참여자 표현을 그대로 적는다.

P0는 과업 중단·원본/이력 손실·잘못된 결과를 정상으로 보이는 문제, P1은 반복 도움·오판·출력/재개 실패,
P2는 회복 가능한 탐색 불편으로 분류한다. 한 명의 실패도 원인 조사 대상으로 삼고 비율만으로 미루지 않는다.
3명 자료는 탐색 근거로 제시한다. 모집 전 성공률·중앙 시간·시장 적합성·MSP/P6 대체 가능성을 주장하지 않는다.
시험 후 증거와 관찰로 우선순위를 갱신하고, 이후 실제50~300개 업무 파일로 확대할지를 결정한다.
